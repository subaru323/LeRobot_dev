## 何をする物か

似た部品 2 個がコンベアで流れてくる。上流の検査アプリが 1 個ずつ判定（NG・OK）と追跡番号を出す。NG の部品だけを腕で取り出して箱に入れる。取り出しの後に、完了にするか、理由を付けて保留にするかを決める。

2 つのやり方を、同じ入力で比べる。

| やり方 | 中身 |
|---|---|
| 基準 | 検査の判定を受け、コンベアの進んだ量から位置を予測して取る。腕の完了の信号で「排除済み」と記録する。絵は見ない |
| 候補 | 基準に、追跡を絵で確かめる所（数・位置・上から見える不良の印）と、取った後の撮り直し（取った後に撮った絵か・取った所が空か・箱が 1 個増えたか）を足す。確かめられなければ理由を付けて保留 |

## 結果（2026-11-19、乱数種 0。乱数種 1〜3 でも同じ。確かめた）

16 ケース（`cell.py` の `CASES`）。候補は 正常完了 8・保留 8・誤完了 0。基準は 正常完了 9・誤完了 7。

- 候補が基準より良かった（基準は誤完了、候補は正常完了か保留）：入れ替え 2 つ、空振り 2 つ、空振りで部品を押す、大きな滑り（45mm）、判定の再送で時刻が付け直された物。基準は、どれも腕の完了の信号だけで「済み」にした。入れ替えと再送では、良品を箱に入れた。
- 候補のほうが悪かった（基準は正常完了、候補は保留）：撮り直しの絵が届かない・古い・最初から絵が無い、の 3 つ（取り出しは実はできていた）。**不良の印が上から見えないとき（裏返しだけ、`flip_only`）も保留**。候補は印で不良を確かめるので、印が上から見えない不良は全部保留になる。
- 判定が同じ番号で違う中身で届いたら（NG → OK）、候補は保留。基準は NG の方だけで動く。
- 誤完了は保留にして減らしたが、その分、人の手が要る保留が増える。この 16 ケースは制御と一緒に作ったケースなので、**どれくらいの割合で起きるかの見積もりには使えない**（計画書：最初の少数ケースは失敗を見つける探索）。
