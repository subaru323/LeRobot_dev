## いまの結論

- テレオペ（STEP 8）の後は、**P1 カメラと試し記録 → P2 本番の記録 → P3 学習 → P4 評価** の順に進める。各段に「終わりの条件」を置き、満たしたら次へ進む。
- **このパソコンでは学習しない。** NVIDIA の GPU が無く、入っている PyTorch は CPU 版（`2.11.0+cpu`、`cuda False`。2026-10-28 に確かめた）。学習の場所は利用者が決める（下の決めてほしいこと 1）。
- フォロワーは、本家のコマンド（`lerobot-teleoperate`、`lerobot-record`、`lerobot-rollout`）の**直前に `tools\prime_goal.py` を流してから**使う。流してから本家の接続を通すと、目標位置と速度の上限が残り、アームが動かないことを 2026-10-28 に確かめた（フォロワー単体、休止姿勢、6関節とも移動 0 ステップ）。
- リーダーと、2台そろってのテレオペは、まだ実機で通していない（STEP 6〜8 待ち）。この計画の P1 以降は、すべて STEP 8 の後に始める。

## 11. 試し記録（2 回、アップロードしない）

本番の数には入れません。動くかどうかと、速さの確認が目的です。

### 11-1. 始める前に

- [ ] 2 台ともクランプで固定、フォロワーの周り 1 m に物と人がいない
- [ ] タスクの道具（立方体と箱など）を置いた
- [ ] リーダーを、フォロワーと同じ姿勢にした（`python tools\compare_pose.py` で `<<<` が無い）

### 11-2. 記録

カメラが 2 台のとき（1 台なら `wrist` の部分を消します）：

```powershell
lerobot-record --robot.type=so101_follower --robot.port=COM3 --robot.id=follower1 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}}" --teleop.type=so101_leader --teleop.port=COM4 --teleop.id=leader1 --display_data=true --dataset.repo_id=<HFユーザー名>/cube_pick_test --dataset.single_task="Put the red cube in the box" --dataset.num_episodes=2 --dataset.episode_time_s=20 --dataset.reset_time_s=20 --dataset.push_to_hub=false
```

- `index_or_path` の 0 と 1 は、9 の表の番号に置き換えます。
- 記録中のキー操作（本家の案内）：

| キー | 動き |
|---|---|
| `→`（または `n`） | この回を早めに終えて、次へ |
| `←`（または `r`） | この回を取り消して、やり直す |
| `Esc`（または `q`） | 記録を終えて、保存する |

## 13. 学習（ACT）

学習の場所は、計画書の「決めてほしいこと」1 で決めます。**このパソコンは CPU だけなので、本番の学習には使いません。**

### 13-1. 試しの学習（100 ステップ）

本番の前に、データが読めて学習が回るかだけを確かめます。

```powershell
lerobot-train --dataset.repo_id=<HFユーザー名>/cube_pick --policy.type=act --output_dir=outputs/train/act_cube_pick_try --job_name=act_cube_pick_try --policy.device=cuda --steps=100 --policy.push_to_hub=false
```

- `--policy.device` は、GPU のある場所なら `cuda`、このパソコンで試すだけなら `cpu` にします。
- `--steps` の既定は 100,000 です（`src\lerobot\configs\train.py`）。ここでは 100 で止めます。

### 13-2. 本番の学習


- 学習の結果は `outputs/train/act_cube_pick/checkpoints` にできます。終わると `<HFユーザー名>/act_cube_pick` にアップロードされます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 記録・評価を始めた瞬間にフォロワーが跳ねる | `prime_goal.py` を流し忘れたか、流した後に 5V を抜いた（設定はモーターの電源で消える）。止めて、組み立て手順書の「困ったとき」の過負荷の対処をしてから、流し直す |
| フォロワーの動きが遅れる | `prime_goal.py` の速度の上限が低い。`python tools\prime_goal.py --speed 4000`（0 で上限なし） |
| カメラが開けない | 番号を 9 の表で確かめる。ほかのソフト（ビデオ会議など）がカメラを使っていたら閉じる |
| 記録が遅い（Cadence が下がる） | 11-3 を参照 |
| 同じ名前のデータがあると言われる | 手元のデータのフォルダを消してから記録する（本家の案内）。消す前にフォルダ名を確かめる |
