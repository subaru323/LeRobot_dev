## いまの結論

- テレオペ（STEP 8）の後は、**P1 カメラと試し記録 → P2 本番の記録 → P3 学習 → P4 評価** の順に進める。各段に「終わりの条件」を置き、満たしたら次へ進む。
- **このパソコンでは学習しない。** NVIDIA の GPU が無く、入っている PyTorch は CPU 版（`2.11.0+cpu`、`cuda False`。2026-10-28 に確かめた）。学習はチームの人の NVIDIA の GPU のパソコンで回し、使えなければ Hugging Face Jobs で回す（下の「決めたこと」1）。
- フォロワーは、本家のコマンド（`lerobot-teleoperate`、`lerobot-record`、`lerobot-rollout`）の**1 回ごとに、直前に `tools\prime_goal.py` を流してから**使う（[ルール P-001](../rules/RULES.md)）。流してから Python で `SOFollower.connect()` を呼ぶと、目標位置と速度の上限が残り、アームが動かないことを 2026-10-28 に確かめた（フォロワー単体、休止姿勢、カメラ無し、1 回、6関節とも移動 0 ステップ）。本家の各コマンドを通した場合は未確認。**防げるのは「つないだ瞬間に跳ぶ」ことだけ**で、その後の最初の動きを抑えるのは速度の上限だけ。
- 評価（`lerobot-rollout`）は、終わるときに「つないだときの姿勢へ 3 秒で自分で戻り、力が抜ける」（本家のソースで確かめた）。評価は休止姿勢から始め、最初の 1 回は動きの上限を付けて安全確認だけをする（手順書 14）。
- P4 の評価は 10 回。**10 回で言えるのは大まかなことだけ**（下の欄5）。「方策が良い／悪い」の判定には使わず、次に何を直すかを決める材料にする。
- リーダーと、2台そろってのテレオペは、まだ実機で通していない（STEP 6〜8 待ち）。この計画の P1 以降は、すべて STEP 8 の後に始める。

この計画は、条件を比べる実験ではない（ACT だけを、1 つの記録の量で試す）。比べる相手が無いので、この欄は当てはまらない。P5 で「記録を足す前と後」などを比べることになったら、そのときに書く。

## 欄4. 測り方の点検（P4 の評価。本番の前に決める）

- **成功の決まり**（評価の前に決め、途中で変えない）：`--duration` の時間内に、立方体が箱の中にあり、箱の外に出ていない。腕が箱を倒した、立方体を箱の外に落とした、は失敗。腕が戻る 3 秒の間に立方体が出ても失敗。
- **置き場所**：記録に使った 5 か所から、各 2 回。合わせて 10 回。順番は先に表に書いておく（手順書 14-5）。
- **数え直せるようにする**：評価の様子を動画で残し（手順書 14-4 の sentry、または別のカメラ）、数えた人とは別の人が、動画を見て数え直す。食い違った回は、その回の扱いを書く。
- **わざと悪い条件で下がるか**：P4 の本番の前に、立方体を記録に無い場所（印の外）に 1 回置いて回す。それでも成功するなら、成功の決まりが緩すぎないかを見直す（この 1 回は本番の数に入れない）。
- 採点役に、どの方策の結果かを隠すことはしない（方策が 1 つしかないため）。

## 欄5. 規模と、見分けられる差

10 回の評価で出せる成功率の幅（95% の区間。`tools/success_interval.py` の出力。[記録](../records/success_interval_20261028.txt)）：

| 10 回中の成功 | 成功率の区間 |
|---|---|
| 0 | 0.00〜0.28 |
| 2 | 0.06〜0.51 |
| 5 | 0.24〜0.76 |
| 8 | 0.49〜0.94 |
| 10 | 0.72〜1.00 |

- 10 回では幅が広い。たとえば 5 回と 8 回の区間は重なっているので、その差は見分けられない。
- そのため P4 は **「探索」** と名乗る。成功の回数は、次に何を直すか（記録を足す、置き場所を減らす、学習を延ばす）を決める材料に使い、「方策が使える／使えない」は決めない。
- P5 で、記録を足す前と後を比べるなら、回数を増やす（20 回なら、10 回成功の区間は 0.30〜0.70。同じ記録）。それでも小さい差は見分けられない。

### 壊しうる操作と、元に戻す方法

| 操作 | 起きうること | 防ぎ方 / 戻し方 |
|---|---|---|
| 本家のコマンドでフォロワーに力が入る | 腕が最高速度で跳ね、過負荷で止まる（2026-10-28 に一度起きた。[記録](../knowledge/フォロワーの跳びと過負荷.md)） | コマンドの 1 回ごとに、直前に `prime_goal.py`（ポートも読み替える）。起きたら 5V を抜き、5 秒後に挿し直す |
| 力が入った後の最初の動き | 記録ではリーダーの姿勢へ、評価では方策の出力へ、速度の上限いっぱいで動く | 記録は、始める前に `compare_pose.py` で姿勢をそろえ、始まるまでリーダーを動かさない。評価は `--robot.max_relative_target` と低い速度の上限で始める |
| テレオペ・記録を止めたときに力が抜ける | 腕が自重で倒れる | リーダーで低い姿勢に下ろしてから止める。または手で支える |
| 評価が終わる・止める | 腕が、つないだときの姿勢へ 3 秒で自分で戻り、その後に力が抜ける | 休止姿勢から始める。戻る間は手を出さない。非常のときは腕を支えてから 5V を抜く |
| 手首カメラの取り付け（F6 を一度外す） | キャリブレーションがずれる | 付け直した後、`safe_wiggle.py` でグリッパーを確かめる。おかしければキャリブレーションをやり直す |

| HF Jobs の学習 | 使った秒数だけ課金される。`Ctrl + C` では止まらない | 回す前に上限の時間を決め、`--job.timeout` に入れる（無いと既定の 48 時間）。止めるときは `hf jobs cancel <job-id>` |
