### 1. 「4-2 共通のルール」のホーンの付け方が本家と食い違い、手順書の中でも食い違う
- **どこ**：4-2「ホーンは、**モーターを部品に入れる前に**、上下2枚とも付けておきます」
- **何が問題か**：
  - 本家でホーンを先に付けるのは関節1〜4だけです。
  - 関節5（手首）は「モーターを入れる → ホーン1枚」の順です。
  - フォロワーのグリッパーは「Insert the gripper motor … → Install both motor horns」と、モーターを入れてからホーンを付けます。
  - リーダーの持ち手も、モーターを入れてからホーンを付けます。
  - 4-3 の表の「関節5」「グリッパー」の行は本家の順ですが、上に書いた共通ルールとは逆です。
  - 初心者がルールのほうに従うと、ホーンが邪魔でモーターが入らない恐れがあります。無理に押し込むと部品を傷めます。
- **どう直すか**：共通ルールを「関節1〜4はモーターを入れる前にホーン上下。関節5とグリッパー（リーダーも）は、モーターを入れてからホーン」に直します。
- **どれだけ確かか**：高い。本家の文面で確かめました。

### 2. 「確定」と書いているのに、インストールは確かめ終わっていない。版の固定も後回しになっている
- **どこ**：見出し「この版について（2026-10-15 確定）」と、1-3。
- **何が問題か**：
  - 計画には「インストールのコマンドは、確かめている最中」とあります。手順書はそれを「確定」と書き、未確認の印も付けていません。
  - 手順書は `main` を clone させ、動かないときだけ `53feaef` に戻させています。照合したのは 2026-10-14 のコミットなので、明日以降に clone する人は照合していない版を最初に使うことになります。
  - 確認：`.[feetech,core_scripts]` は 0.6.2 に実在します（core_scripts の中身は dataset、hardware、viz）。`requires-python>=3.12` なので、3.12 の指定は合っています。
- **どう直すか**：
  - clone の直後に `git checkout 53feaef` を手順として入れ、最初から版を固定します。
  - uv での導入を通し終えるまでは、「確定」の文言か、1-3 の「未確認」の印のどちらかを直します。
  - 本家の公式は `pip install -e ".[feetech]"` です。core_scripts を加えた理由を一言書きます。
- **どれだけ確かか**：高い。

### 3. 電源電圧の取り違えへの備えが無い（実機を壊しうる）
- **どこ**：冒頭「電源はすべて5V」、0-2「5V電源アダプタ 2」。
- **何が問題か**：
  - Pro版のキットや、別売りの12V電源が混ざる場合への注意がありません。
  - リーダーのモーター（C044/C046/C001）は12V用ではありません。12Vを入れれば壊れます。
  - 本家の so101.mdx には電圧の記載がありません。この手順書の「5V」は Seeed 側の情報だけが頼りです。
- **どう直すか**：STEP 0 に次の確認を足します。
  - アダプタの銘板が「5V」であることを確かめる。
  - 12V のアダプタが手元にあれば、どちらの基板にも絶対につながない。
  - フォロワーのモーターの型番シールが C001 であることを確かめる（12V版の型番であれば中止する）。
- **どれだけ確かか**：中くらい。キットの中身しだいです。被害が大きいので上位に置きました。

### 4. STEP 5-4 の姿勢の説明が、一次資料に無い作り足しの可能性がある
- **どこ**：「図のとおり（上腕をまっすぐ立て、前腕を水平に前へ）」
- **何が問題か**：
  - コードが「図」（homing diagram）を表示し、「middle of its range of motion (shown above)」と出すことは確かめました。
  - 括弧の中の姿勢の言葉は、本家の文面にもコードの表示文にもありません。
  - 図と食い違えば、真ん中から外れた姿勢でキャリブレーションされます。そうなると「Magnitude exceeds 2047」などの原因になります。
- **どう直すか**：括弧の中を消すか「（未確認）」を付けます。「画面の図と動画を優先する」と書きます。
- **どれだけ確かか**：中くらい。図の中身までは見ていません。

### 5. 「Magnitude … exceeds 2047」の対処が、原因に当たっていない恐れがある
- **どこ**：「困ったとき」の表。
- **何が問題か**：このエラーは、ホーミングのオフセットが範囲を超えたときに出ます。主な原因は、中間の姿勢の取り方や、ホーンの付け位置です。「電源を入れ直す」だけでは直らない見込みが高いです。
- **どう直すか**：先に「STEP 5-4 の中間の姿勢をきちんと取り直してやり直す」を書き、次に Seeed のツールを案内します。
- **どれだけ確かか**：中くらい。

### 6. STEP 2 の「USBだけでは給電されません」は、ポートの確認には当てはまらない
- **どこ**：STEP 2-1。
- **何が問題か**：
  - COM ポートは基板の USB チップのものなので、USB だけで出ます。5V の電源は要りません。
  - 害は小さいものの、電源の有無を COM が出ない原因だと思い込ませます。
  - USB を挿し直したとき、別の USB 差し込み口に挿すと COM 番号が変わることがあります。この注意もありません。
- **どう直すか**：
  - 「ポートの確認は USB だけでも可。STEP 3 以降は 5V 電源も必要」に直します。
  - 「各基板は、毎回同じ USB 差し込み口に挿す」を足します。
- **どれだけ確かか**：中〜高。

### 7. STEP 8-3「トリガーを引くと、グリッパーが閉じる」は、根拠を確かめていない予測
- **どこ**：8-3 の確認表。
- **何が問題か**：向きはキャリブレーションの範囲で決まります。一次資料で確かめた記述ではありません。逆に動いたとき、初心者は故障と思い込みます。
- **どう直すか**：「トリガーに合わせてグリッパーが開閉する」に弱めます。
- **どれだけ確かか**：中くらい。

### 手順書に足すとよいこと
1. **通電前のチェック欄**：アダプタの銘板の電圧（5V）、DC ジャックがしっかり挿さっているか、どちらがフォロワーの基板かのテープ。STEP 3 と STEP 5 の直前に置きます。
2. **STEP 1 の最後の動作確認**：`lerobot-find-port --help` などを実行し、コマンドが通ってから STEP 2 へ進ませます。導入の失敗を、実機をつなぐ前に切り分けられます。
3. **Windows のユーザー名に日本語や空白があるときの注意**：`~\lerobot` と `.cache` のパスで詰まる恐れがあります（未確認）。そのときは `C:\lerobot` のような ASCII だけのフォルダに clone させます。
