```text

最初は既定の 3×4 の画像制御・干渉判定・物理再生の基準を揃え、画像から選んだ 1 手を MuJoCo で実行し、撮り直した画像を制御へ戻すところに着手してください。
実装案、仮説、検証、計画と手順の更新は Claude が担当します。担当が重なるファイルは既存の担当会話と調整してください。実機や課金が要る場合も、待つ間に独立したローカル作業を進めてください。
次の担当が再現できるよう、変えた点、実行コマンド、結果の場所、失敗の理由、次に着手する一件を残してください。
```

## 1. 基準を取る

1. [STATUS](../STATUS.md) で直近の変更と担当を読む。すでに証拠がある検算は、条件と出力を確認して再利用できる。同じファイルに別の担当がいる場合は、その担当に必要な変更・受け入れ条件・検算を渡し、競合しない作業を進める。
2. ルートから既定の 3×4 と、上の検出結果を 5 mm ずらしたときの手首補正あり／なしを確認する。以下はシミュレーション用。

```powershell
& .\MAIN_PG\lerobot\.venv\Scripts\python.exe tools\puzzle_run.py --sim --set 2 --seed 1
& .\MAIN_PG\lerobot\.venv\Scripts\python.exe tools\puzzle_run.py --sim --set 2 --seed 1 --shift 5,0
& .\MAIN_PG\lerobot\.venv\Scripts\python.exe tools\puzzle_run.py --sim --set 2 --seed 1 --shift 5,0 --no-wrist
```

3. `sim/` から、モデルと干渉判定を検算し、同じ種類の盤を物理で一度再生する。現時点では、手順 2 の撮影で選んだ関節指令と手順 3 の書き出しは別経路。両者をつなぐのが初回の実装課題。

```powershell
node tools/check-urdf.js
node tools/check-fk.js
node tools/check-scene.js
node tools/export-physics.js --set 2
& .\physics\.venv\Scripts\python.exe physics\run_physics.py out/physics/set2_gap15_stand1
```

4. 画像制御の記録は `sim/out/puzzle_run/`、物理の場面と結果は `sim/out/physics/` に出る。再実行で上書きされる出力は別名で保管する。コマンドの終了コードと、JSON 内の成功・停止理由の両方を読む。時間の取れる回に [物理の全件検算](../sim/physics/README.md) を流し、爪を閉じない負の例が落ちることを確認する。

## 2. 一手つないで検証する

1. `tools/puzzle_run.py` と `sim/plan-cli.js` の指令・観測の境界、`sim/tools/export-physics.js` と `sim/physics/run_physics.py` の入出力を確認する。既存の JavaScript 検出器と干渉判定を呼ぶ。物理側では実行前後のピースが自由剛体として動くことを確認する。
2. 現在の関節から接続できるかを確認して一手の計画を送り、実行後の同じ世界から RGB と関節状態を返す。途中で世界を初期化しない。撮影の姿勢と時刻、角度・長さの単位、カメラの較正を結びつける。位置姿勢の真値は別の採点処理に渡す。
3. 既定配置の一手を通したら、ずれ・遮蔽・爪を閉じない例を試す。まず落ちた条件を保存し、次に最小の修正を入れ、同じ条件と基準の両方を回す。画像を見ても進めない場合は、上限付きで撮り直し、または停止して理由を残す。
4. 計画書の条件を満たした段だけ進める。短い試験の次に、関連する全体検算を実行する。

## 3. 記録して続ける

各回の記録には「仮説 → 試した条件 → コマンドと結果 → 判断 → 次の一件」を残す。夜間は [既存の夜の開発記録](records/夜の開発_LOG.md) に追記する。実装の担当と次の一手、採用した判断は [STATUS](../STATUS.md) を更新する。方向を決める提案や結論は、読み取り専用の点検役を使い [R-001 台帳](records/R001_LOG.md) に対応を残す。
