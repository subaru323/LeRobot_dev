## どの日も同じ中止の決まり

- 腕が跳ぶ・うなる・熱い・柱やカメラに近づく・ピースを押しつぶしそう：**Ctrl+C**。道具はその姿勢で腕を保つ。「SUPPORT THE ARM」と出たら、**腕を手で支えてから** Enter。危ないときは支えながら 5V を抜く。
- 道具が自分で止まったら、**同じコマンドをそのまま流し直さない**。Claude が記録を読み、ピースを置き場に戻し、腕を写す姿勢に持ってから流す（2026-11-23 から、ピースがもう盤の上にあると、道具は絵を見た後に動かずに止まる。S4 で止めたのは計画の断り「盤に重なる」で、実機ではその後ろに「put the pieces back」と出る）。
- 流し始めに「the motors still hold the arm」：前の回がきれいに終わっていない。腕を支えてから Enter。持っているか読めないまま止まったときも「SUPPORT THE ARM」と出る。
- 関節のサーボは自分を守って急に力を失うことがある（その関節が垂れる）。道具は動いている間 0.5 秒ごとに状態を読んで「motor error status ... while moving」で止まるが、それまでは垂れる。動いている間は腕の下に手を添える。
- 力を入れる前後の「There is no status packet」：基板の返事が 1 回欠けた。限界と力を入れる書き込みは 1 回の欠けで止まる作り（S4-04）。線と 5V を確かめてから流し直す。
- 「motor error status」：5V を抜いて差し直す。「could not release torque ... unplug the 5V power」：腕を支えながら 5V を抜く。
- 本家のコマンド（`lerobot-calibrate` 以外で力を入れるもの）の前は毎回 `tools\prime_goal.py`（[P-001](../rules/RULES.md)）。`puzzle_run.py`・`k1_run.py` は自分で目標を今の位置に合わせてから力を入れる。
- 机の高さの回（D4・D5）は、同じファイル・同じ版の空中の回が ok で終わった後だけ（道具が断る）。`tools\` か `sim/` が変わったら空中から。

## 失敗したとき持ち帰るもの（どの日も）

| もの | どこ | なぜ |
|---|---|---|
| 道具の記録とフォルダ | `puzzle_run.py`：`sim\out\puzzle_run\run_<日時>_p<番号>.json` と同じ名前のフォルダ。`k1_run.py`：`sim\calib\k1_run_<日時>.json`。カメラ：`outputs\k5\` の下の撮ったフォルダ | `puzzle_run.py` の記録は、制御が見た関節の読みと絵・送った指令・止まった所（`stop_at`）を持ち、ポートなしで流し直せる（`--replay`）。流し直しの記録は `replay_<日時>_p<番号>.json` で、本物の回ではない |
| Terminal のタブの文字 | 止まった理由の行と、その前の 20 行ほど。Claude が写す | 記録に入らない警告（「could not release torque」など）が残る |
| 止まった姿勢の写真 1 枚 | スマホ。腕・ピース・盤・柱が写る向き | 腕がどこに当たったか、ピースがどう倒れたかは記録だけでは分からない |
| 利用者のひとこと | 何を見て Ctrl+C したか、音・におい・熱 | 道具が測らないもの |

消さない・上書きしない。同じフォルダに撮り直すと番号が続きから振られ、古い絵が混ざる（D3 の 2）。
