# 決まり ⇄ 検査 ⇄ 時機の一覧

`docs/core/方針.md` 7。決まりを作ったら、同じ回にここへ1行足す。機械で見られない決まりは、なぜ見られないかを書く（空欄にしない）。**回していない検査は、無いのと同じ。** プロジェクトの決まりを足すときは、下の core の行の後ろに足す。

| 決まり | 検査（コマンド） | 回す時機 | 機械で見られないとき、その理由 |
|---|---|---|---|
| core 方針4: 言える範囲で書く（禁止語）・数字は出力から写す | `python docs/core/tools/doc_lint.py <文書>` | 結果や結論の文書を書いたとき、R-001 の点検の前 | 禁止語の表に無い言い替えと、表の中の数字は見られない（目で見る） |
| core 方針4: いまの結論を冒頭に・撤回は本文で打ち消し線 | なし | — | 文の意味の判断が要る。R-001 の点検で見る |
| core 方針3・R-001: 結論を出す前に点検する | `python docs/core/tools/r001_check.py ...` | 結論や方向の提案を利用者に出す前、大きな計画を回す前 | 「出す前に回したか」は機械で見ていない。台帳（`docs/records/R001_LOG.md`）に記録が無い結論は、点検していないものとして扱う |
| core 方針6: 入口の文書を逐一直す・日付だけを書き換えない | なし（道具を作るまで） | 新しい会話の最初 | core に道具が無い。プロジェクトで作るなら、入口の文書の最終更新と、ファイルの最終更新を比べる |
| core 方針10: 書き換えで化けていないか | `python docs/core/tools/doc_lint.py <書いたファイル>`（制御文字） | 書き換えのスクリプトを当てた後 | md 以外のファイルにもかけられるが、拾うのは制御文字だけ |
| core 方針11: 同じ既存ファイルを2つの会話が書かない | なし | 複数の会話で動かす日の始まり | 誰がどのファイルを書くかは、計画書の担当の欄で決める |
| core 方針12: 状態の記述の例外で上位の文書を直したら、道具の名前と出力へのリンクを記録し、利用者に知らせる | なし（道具を作るまで） | 上位の文書を直したとき | 記録の形がプロジェクトごとに違う。記録の文書に「道具の名前・出力へのリンク・知らせた日」の欄を作り、空欄を目で見る |
