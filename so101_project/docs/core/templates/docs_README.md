# docs の置き場所

| 置き場所 | 中身 | 決まり |
|---|---|---|
| `docs/core/` | ルールの種（core v{{VERSION}}）。方針、最初のルール、手引き、道具 | **読むだけ。書き換えない。** 直したいところは `docs/core_proposals/` へ |
| `docs/core_proposals/` | core への修正案（1件1ファイル） | `docs/core/修正案の出し方.md` の形で書く。マスターに届けるためのもの |
| `docs/rules/` | このプロジェクトで足したルール | `docs/core/方針.md` に反しない。ルールごとに根拠の強さ、最後に見直した日を書く |
| `docs/guides/` | このプロジェクトの進め方、手順 | |
| `docs/plan/` | 方向の計画、作業の計画書 | |
| `docs/knowledge/` | 調べたこと、振り返り、失敗と解決 | 冒頭に「いまの結論」を置く。撤回は本文の場所で打ち消し線 |
| `docs/records/` | R-001 の台帳（`R001_LOG.md`）、点検の入出力（`checks/`） | 点検のたびに1件1行 |
| `STATUS.md`（プロジェクトの直下） | 入口の文書 | 変わったらその場で直す。日付だけを書き換えない |
| `CLAUDE.md`（プロジェクトの直下） | 自動で読まれる入口。core から作った | プロジェクトに合わせて直してよい |

**持ち主**: 同じ事実を2か所に書かない。上の表の「中身」が、その事実の正本。順位の先頭は、利用者の最新の発言と記録された利用者の決定（日付の新しい方）。どう作業するかは、その次に `docs/core/方針.md` → `docs/rules/` → そのほかの文書。何を作るか（仕様・要件・課題）の順位は、プロジェクトが決めてここに書く。軸は中身で分け、仕様の文書に書いた作業の仕方も core に従う（`docs/core/方針.md` 12）。core が古いと思ったら、直さずに `docs/core_proposals/` へ。

**決まり ⇄ 検査 ⇄ 時機**: `docs/rules/検査の一覧.md`（`docs/core/方針.md` 7）。
