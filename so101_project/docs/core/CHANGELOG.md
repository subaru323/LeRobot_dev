# core の変更履歴（マスターだけ。埋め込みには含めない）

- 0.1.0（2026-10-14）: 最初の版。自己批判の有用性検証の結果から、方針・根拠・R-001・手引き・雛形・道具（doc_lint、r001_check、seed）をまとめた。R-001 の点検（台帳 C8）を受けて、根拠の言い過ぎを直し、点検役を --safe-mode で起動し、seed --update が core の書き換えを見つけて止まるようにした。
- 0.1.0（2026-10-14、版は据え置き）: seed.py が既にあるファイルを上書きしないようにした（利用者の指示）。設定ファイルが既にあれば書き換えず、足りない決まりを表示する。--update は古い版を docs/core_previous/v<版>/ に残す。
- 0.1.0（2026-10-14、版は据え置き）: seed.py に --core-only を足した（中盤以降のプロジェクト向け。ちくわ排除機構への導入のため）。
- 0.2.0（2026-10-14）: ちくわ排除機構との突き合わせ（台A）を受けて。方針5「聞く。ただし待つ間も進める」、方針6「入口の文書の名前はプロジェクトが決めてよい」「書くのは逐一」「状態の数字は写さず道具に聞く」「事実ごとの持ち主と順位」「入口の鮮度を確かめる」、方針7「決まり ⇄ 検査 ⇄ 時機の一覧」、方針10「ファイルを書き換えるとき」、方針11「複数の会話で動かすとき」を足した。R-001 に「同じ役の仕組みがあれば使ってよい（場面と台帳は守る）」を足した。根拠の強さに「ほかのプロジェクトの実績」を足した。
- 0.2.0（2026-10-14、R-001 の点検（台帳 C10）を受けて同じ版のまま直した）: 方針3・8 に「同じ役の仕組みで代えるときは、守れないものを台帳に書く」。方針6 から「最終更新の1行は書く」を外し「日付だけを書き換えない」に。方針6 に複数の会話のときの書き方と、順位の先頭に「記録された利用者の決定」、「上が core なら修正案」。方針5 を利用者の決定の文言に戻した。根拠の札をそろえ、方針7・11 の根拠を「失敗の記録まで」に、方針10 に比べた数字。方針11 に「共有の部品は正本を1つ」。雛形の CLAUDE.md の R-001 を1行とリンクに。検査の一覧の雛形と、doc_lint の制御文字の検査を足した。
  - **利用者の決定（1〜5）の外で足したもの**: 方針7「回していない検査は、無いのと同じ」、方針11「順番待ちの列」（試行中）、方針11「共有の部品は正本を1つ」、検査の一覧の雛形、doc_lint の制御文字の検査。
- 0.3.0（2026-10-14）: ちくわ排除機構からの修正案2件と、台Aの指摘1件を取り込んだ（R-001 の点検 = 台帳 C11 を受けて歯止めを足した）。
  - 修正案「順位を仕様とふるまいの2本の軸に分けてよい」→ **受け入れ（言葉を変えた）**。新しい方針12 に分けた。先頭はいつも利用者の発言と記録された決定。軸は文書ではなく中身で分け、仕様の文書に書いた作業の仕方も core に従う。仕様の順位は core を外す理由にならない。軸をまたいだら利用者に確かめる。原文の「ふるまいの軸の上位に置く」は、既定の順位（利用者 → core → …）で表した。
  - 修正案「上位の文書を道具の出力に合わせる直し方」→ **一部受け入れ（狭めた）**。直してよいのは、検査の道具が出す合否・件数・進み具合の記述だけで、数字を書き写さずに出力へのリンクに置き換える。道具は検査の一覧に載っているもの。直したら記録し、後で利用者に知らせる。core と記録された利用者の決定には当てない。原文の「それ以外は利用者が決めたときだけ」は残した。
  - 指摘「core の中の置き場所の記述が、埋め込み先で壊れて見える」→ **受け入れ**。README に、置き場所は既定でコード表記、読み替えの仕方、検査から外す範囲（既定の置き場所の記述だけ）を書いた。
  - 方針6 から持ち主と順位を方針12 へ移した。雛形の CLAUDE.md に「順位の 0 と 1 の並びは変えない」「R-001 はプロジェクトのルールで外さない」。検査の一覧に方針12 の行。
