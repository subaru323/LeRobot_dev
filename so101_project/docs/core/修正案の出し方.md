# core への修正案の出し方

プロジェクトの中の `docs/core/` は読むだけ。core に足りないルールや、直したほうがよい所に気づいたら、**プロジェクトの `docs/core_proposals/` に、1件1ファイルで修正案を書く。** 修正案は、利用者がマスター（core を作っているフォルダ）の会話に持っていき、マスターの直しに使う。

## いつ書くか

- core の方針やルールが、このプロジェクトの作業に合わなかったとき（守ると困った、守れなかった）。
- core に無いルールを `docs/rules/` に足し、それがほかのプロジェクトでも使えそうなとき。
- core の文書の誤り、古い記述、分かりにくい所を見つけたとき。

その場の作業は止めない。core と違うやり方が要るときは、`docs/rules/` に「core の〇〇とは違うやり方をする。理由」と書いて進め、修正案も書く。ただし `docs/core/方針.md` に反するやり方は、利用者に確かめてから。

## ファイル名と中身

ファイル名: `YYYY-MM-DD_短い題.md`

```
# （短い題）

- core の版: （docs/core/VERSION の中身）
- どのファイルの、どこか: （例: 方針.md の 6）
- 何を: （足す / 直す / 消す。案の文があれば書く）
- なぜ: （起きたこと。日付、作業、何が困ったか。証拠があればリンク）
- このプロジェクトでどうしたか: （docs/rules/ に足した、仮にこうした、まだ何もしていない）
```

欄は最小限。分からない欄は「分からない」と書く。
