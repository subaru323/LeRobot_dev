# core（ルールの種）

このプロジェクトの始めに埋め込んだ、ルールの種。ここから `CLAUDE.md` や `docs/` のほかのフォルダが生え、プロジェクトはそこで自分のルールを育てる。序盤はよく使い、中盤以降はプロジェクト自身のルールが主になる。**プロジェクトのルールは、`方針.md` の方向に従う。**

想定: Claude Code で進める、中〜大規模のソフトウェアやハードウェアを使うプロジェクト。

**このフォルダは読むだけ。書き換えない**（`.claude/settings.json` で Edit・Write を禁じ、ファイルに読み取り専用の印を付けてある）。直したいところは `docs/core_proposals/` に修正案を書く（`修正案の出し方.md`）。修正案は、利用者が core のマスターに持っていき、次の版に活かす。

**中に出てくる置き場所は既定。** core の文書に出てくる `docs/rules/`、`docs/records/R001_LOG.md`、`STATUS.md` などは、core を種として丸ごと埋め込んだときの既定の置き場所で、リンクにはせずコード表記で書いてある（core の中にリンクは無い）。プロジェクトの置き場所が違うとき（core だけを入れたときなど）は、プロジェクトの docs の地図か、無ければ入口の文書に読み替えの表を書く。置き場所の検査の道具がコード表記まで見るなら、`docs/core/` の中の既定の置き場所の記述だけを対象から外す（core の中どうしのファイル名の記述は検査に残す）。

## 中身

| ファイル | 中身 |
|---|---|
| `方針.md` | ルールの土台。プロジェクトのルールはこれに反しない |
| `根拠.md` | 方針とルールの根拠の要約（何を何回見たか、範囲、反対の材料） |
| `rules/RULES.md` | core のルール（R-001）と、試行中の手順の一覧 |
| `guides/` | 計画書の書き方、短く通す6つの問い、道具の使い方 |
| `修正案の出し方.md` | core を直したいときの修正案の書き方 |
| `templates/` | CLAUDE.md、STATUS.md、docs の置き場所の表、R-001 の台帳、決まり ⇄ 検査 ⇄ 時機の一覧の雛形 |
| `tools/` | 文書の検査（doc_lint.py。禁止語、手書きの数字、制御文字）、結論の点検（r001_check.py） |
| `VERSION`、`MANIFEST.json` | 版の番号と、埋め込んだときのファイルごとのハッシュ |
