# 短く通す6つの問い（試行中）

計画を立てるとき、問題を直すとき、利用者に何かを頼むときに、短く通す問い。**確定したルールではない。** 場面に合う問いを1つ選んで使うほうがよいかもしれない（全部を儀式のように通しても、差は見えなかった）。

| 番号 | 問い | やること |
|---|---|---|
| 1 | **うまくいったら、何がどうなっているか** | 理想の姿を1〜2文で書く。そこから、守る条件を2〜3個決める |
| 2 | **根はどこか** | 目の前のエラーや依頼の奥に、それを生んでいる条件が無いかを見る。直す場所は、エラーが出た所か、根の所か |
| 3 | **どこが弱いか** | 大きい計画のときだけ、実行の前に、新しい会話の AI に計画書だけを渡して弱点を挙げさせる（R-001 の道具を計画書に使ってよい） |
| 4 | **自分で確かめられるか。利用者に頼む必要があるか** | 計画に出てくる道具・コード・データ・機器は、自分で開いて（動かして）確かめる。頼むなら、先に「どれくらいの手間か、今できるか」を聞く。できないなら仮定で進め、仮定と書く |
| 5 | **やったことは適切だったか** | 区切りごとに1〜3行で振り返る。大きい結論を人に出す前は R-001 |
| 6 | **届かなかったら、なぜか** | 打ち切る前に、届かなかった理由と、届く方法を書く |

## 大きさで使い分ける

- **小さい作業**（1つの修正、1つの質問）: 1・2・4 を頭の中で通す。追加の費用はほぼ無し。
- **大きい計画・大きい結論**: 3 と 5 の「新しい会話の AI に見せる」を足す。
