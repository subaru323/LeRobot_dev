# 計画書の書き方（試行中）

実験、大きな作業、方向を決める調べものの前に書く計画書の欄。小さい作業には使わない。**確定したルールではない。** マスターで実験の計画に使い、計画からのずれや結論の撤回を減らす目的で作った。

## 9つの欄

1. **利用者が欲しい答え（利用者の言葉のまま）。** その下に、この計画が答える問いと、**答えない部分**を書く。結論は、答える問いの範囲でしか書かない。
2. **選択肢の地図。** 「やる / やらない」の2択にしない。結果を変えうる軸（誰が、何を、いつ、どの程度、何を持って、何の作業か）を並べ、今回試すもの・試さないものを表にする。結論の見出しには、試したものの名前を入れる。

（欄3〜5と7は、条件を比べる実験のときだけ。ふつうの作業の計画では飛ばしてよい）

3. **基準は本当に「何もしない」か。** 比べる相手が、調べたい行為をすでに含んでいないかを確かめる。
4. **測り方の点検（本番の前に）。** 枠や満点で差が潰れないか。わざと悪い条件で、指標が下がるか（下がらなければ何も測れない）。採点の揺れ（同じものを2回採点して食い違うか）。採点役に、どの条件の結果かを知らせない（ファイル名や置き場所からも分からないようにする）。
5. **規模と、見分けられる差。** この規模で見分けられる差を先に書く。期待する差がそれより小さいなら「探索」と名乗り、採用・不採用を決めない。
6. **費用と止め方（実行前に全部決める）。** 上限（ドルか時間）、削ってよいもの・いけないもの、止める基準。実行中に止め方を変えたくなったら、止めて計画書を直し、利用者に見せる。
7. **結論の言葉の対応表。** どの結果ならどの言葉を使うかを、結果の前に決める。差が見分けられないときに「効かない」「差は無い」と書かない。
8. **結論を出す前の関門。** R-001 の点検を通す。書いた本人も、逆の読み方、試した範囲からのはみ出し、使ってはいけない言葉、次の一手が依頼に近づくか、試していない選択肢の数、を書く。
9. **計画書そのものへの点検。** 実行の前に、新しい会話の AI に計画書を点検させる（R-001 の道具を計画書に使う）。挙がった件ごとに、直す・直さないを計画書に書く。

## 実物を動かす作業（ソフト・ハード）での足し算

- 前提（仕様、寸法、通信、性能、機器の状態）のうち、確かめていないものを一覧にし、実物か一次資料で確かめる順番を書く。
- 壊しうる操作（書き込み、通電、削除、本番環境）の前に、元に戻す方法を書く。
- 試し走り（小さく1回）を本番の前に置き、本番には数えない。
