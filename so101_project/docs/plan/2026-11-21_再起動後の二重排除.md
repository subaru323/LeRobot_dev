# 2026-11-21　再起動後の二重排除を防ぐための信号再生

設備保守と生産技術向け。排除の直後に制御が止まると、再起動した側には「指令を送ったか」「対象が移ったか」が残らないことがある。前回の品種切替の試験で使った指令の識別に、送信前の意図の保存と、再起動後の画像照合を組み合わせる。架空セルの再生を、引き渡し時の復旧試験にも使う。[前回の提案](2026-11-20_品種切替後の完了信号.md)・[開発手順書](../産業用フィジカルAI開発手順書.md)

## 四つの停止点を模擬した結果

送信した指令は直ちに一回実行されると仮定した。比較方式は確認記録が無ければ再送する。候補方式は意図が記録済みで確認が未記録なら、再送を保留して観測を待つ。表の回数は停止前と再開後を合わせた指令送信数。候補の再観測は開始前までを扱った。

| 停止点 | 比較方式 | 候補方式 | 候補方式の判断 |
|---|---:|---:|---|
| 意図の保存前 | 1 | 1 | 新規指令 |
| 意図の保存後、送信前 | 1 | 0 | 再観測待ち |
| 送信後、確認記録前 | 2 | 1 | 再観測待ち |
| 確認記録後 | 1 | 1 | 記録済みの確認結果を返す |

送信後の停止では二度目の送信を防げた。送信前に止まった場合も観測が要るため、復旧時間との交換になる。このモデルでは、通信中の指令、停止中の手動操作、画像の識別精度、制御装置側の実行回数は未検証。

## 再現コード

~~~python
for phase in ("before_intent", "before_send", "after_send", "after_confirm"):
    intent = phase != "before_intent"
    moved = phase in ("after_send", "after_confirm")
    confirmed = phase == "after_confirm"
    retry = not confirmed
    propose = "new" if not intent else "done" if confirmed else "observe"
    print(phase, int(moved) + int(retry), int(moved) + int(propose == "new"), propose)
~~~

## Claude に渡す次の一件

架空セルの既存担当へ四つの停止点と判定表を渡す。実際の再生では、出荷・流路・排除先の観測と時刻を使って、対象個体の現在地と設備の状態を照合する。最初の採点は誤完了、重複指令、保留件数、観測から判断までの時間。停止中にワークが交換された場合、設備が受理して応答が届かない場合、観測後の確定前に再停止した場合、品種切替前の応答が届く場合を追加する。対象がまだ元の位置にある画像だけでは、遅延実行を除外できない。設備側の未実行の証拠が揃うまで保留し、保留の期限と担当への引き渡しをケースに定義する。両方式を同じ障害列で回し、設備側の履歴から二重作動・別個体の誤排除・対象の未排除・保留を採点する。FANUCとデンソーでは、制御装置・PLCに残る情報と、再起動後に参照できる情報を機種差分表で確認する。現場の復旧時間と受入基準は設備担当と決める。
