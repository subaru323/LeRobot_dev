# 提案書 ― SO-101 パズルを、見直して組めるロボットへ

2026-11-19｜[実装計画書](計画書_SO101パズルの発展.md)｜[Claude 実行手順書](../SO101パズル開発手順書.md)

## 目指す動作

上のカメラで机のピースを見つけ、置く順番とつかむ向きを選ぶ。手首のカメラでつかむ直前のずれを直し、持ち上げて運び、盤に置く。置いた後に撮り直し、ずれや落下があれば、残りの手を組み直す。見失った場合や干渉を回避できない場合は、理由を記録して止まる。

最初の完成形は既定の 3×4（L・J・O）。撮影から配置確認までを、滑りや落下が起きうる物理シミュレーションで一貫して確かめる。同じ仕組みで置き場や形を変え、最後に実機の案 A へつなげる。[完成形までの計画](計画書_完成形まで.md)

## 発展の順番

1. **画像と物理をつなぐ。** 既存の検出・計画・物理再生を使い、まず 1 ピースで、画像から組んだ指令を物理で実行し、結果の画像を制御へ戻す。次に既定の 3×4 を最後まで回す。ピースが見えない、滑る、落ちる、干渉する場合を個別に試す。
2. **盤や形を差し替える。** 次の難しさは同じ高さで形・向き・置き順が異なる平面パズル。既存の十字・凹形・ロの字・T字を画像と物理の検証に広げ、未調整ケースも加えて、認識・到達・把持・配置のどこが詰まるか測る。段差や積み重ねは、平面が安定してから、深さやつかみ方の追加が必要かを探索する。
3. **同じ問題を Isaac Sim と実機の検証に持っていく。** Isaac Sim は共通ケースで関節・画角・接触の結果を照合し、光や影を変えた入力を試す。実機は既存の較正・安全手順を進め、そこで得た摩擦や誤差の測定を物理モデルに戻す。

平面パズルの追加だけなら今の表示・計画で進められるが、滑りに対する回復は測れない。Isaac Sim を先に使う案は画像や物理の比較に向く一方、課金環境が必要で、制御と採点の切り分けも残る。まず手元で接続し、手元と Isaac Sim の両方で検証できるケースを作る。

この開発は、合意済みの D2・D3 と W4 の残りを進める順を変えず、手元だけでできる検証を並行して行う。最初の一手は K7 の把持検証に使える形に絞る。

仮説・採点・方式選定・手順の更新は Claude が担当する。利用者が関与するのは、目的を変えるとき、既存の承認範囲を超える費用や外部共有が必要なとき、実物を取り付けて計測・操作するとき。
