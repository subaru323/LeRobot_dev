# SO-101から産業用フィジカルAIへ　総合計画書

2026-11-22 改訂。Claude Codeの原案をAstraでレビューし、工程と採点を見直した。開発と実機確認を引き継ぐ人のための全体計画。個別の操作手順と利用者が決めた条件は、末尾の正本を参照する。

## 1. いまの結論と理想の完成像

**案A（画像で見てパズルを組む）とACT（人の実演から覚える）の両方を進める方針は妥当。最初の成果は、解けると分かっている一手を、実機と同じ制御の流れで最後まで確かめた記録にする。** 隣に寄せた失敗例も同じ入口に入れる。ここが通れば、盤を広げたときに失敗した原因を追える。

| 完成したとき、何が見えるか | 引き渡す証拠 |
|---|---|
| **案A**　利用者が平面の盤とピースを置く。上カメラで配置を読み、手首カメラでつかむ位置を直す。腕は一手ずつ動き、手を離した後に盤と隣のピースを読み直す。扱える盤は最後まで組み、届かない・挟めない・見分けられない盤では、止まった場所と理由を示す。 | 未使用の配置の試行一覧。動作前後の画像、選んだ経路、位置ずれ、隣の動き、完了・停止の理由を一手ごとに再生できる。実機で通った盤と、simだけで試した盤を明記する。 |
| **ACT**　人がリーダーで赤い立方体を箱に入れる動きを教える。学習後はフォロワーが、教示に使わなかった初期配置から同じ仕事をする。 | データ版、学習条件、方策、P4の本番10回の映像・成功数・失敗した段階。成功を主張できる範囲は試した配置まで。 |
| **産業用フィジカルAI**　検査でNGになった個体を追い、正しい個体が排除箱に入った証拠を残す。停電や品種替えの後、個体と指令の対応が不明なら保留し、担当者が証拠から再開を判断できる。別の品種でも同じ試験を再生できる。 | 比較動画、個体別の判断履歴、機種差分表、提案見本。現場合意後は誤排除・流出・保留・サイクル時間・復旧工数と、二品種目で再利用できた工程を提出する。 |

**進め方の提案**　案Aの一手を優先し、ACTのデータ再生と産業セルの既知の誤完了は並行する。共通化するのは画像・時刻・座標の記録と検証手順。パズルと排除作業には個別の合否を持たせる。先に盤の種類を増やす案は、一手の成功と隣への干渉を区別できるようになった時点で優先する。simで作ったパズル実演を教師にする学習は発展課題。案Aや立方体ACTを達成するための前提には置かない。

## 4. 成功と停止をどう採点するか

- 試行前に、**完成必須・拒否必須・可否未確定**に分ける。完成必須の分母には拒否・途中停止・採点不能も残す。拒否必須は拒否の理由まで照合。各分類の分母と結果を併記し、拒否必須なのに実行した件数も独立に出す。全初期配置を残し、最後に成功した連続試行だけを切り出さない。
- 一手ごとに、対象ID、時刻、入力画像、較正版、目標と整定後のずれ、誤差を加えた軌道の最短距離、意図しない接触、隣の移動、再試行数を記録。simでは物理の真値で独立採点する。実機で画像だけでは確かめられない接触は「観測不能」とし、合格の根拠に使わない。
- 既定の8配置は回帰用。S3の初見は、調整に使わない配置と誤差を事前に保存する。原案の20本中16本は開発の比較目標案。達成率を出す母集団は成立を事前確認した盤に固定し、完了と経路生成も別集計とする。意図した把持（爪と対象）、着座（対象と盤）は工程ごとに許容する。爪と隣のピースなどの禁止接触は不合格。禁止接触を判定できない回は接触の欄を判定不能とし、全条件を満たした数に入れない。3 mmの仮の誤差を与えた結果と、軌道上の距離1 mmの診断値は別欄。どちらも実機に適用する値は実測後に決める。
- 初見で失敗した配置は次版の回帰用へ移す。改善の確認には別の初見も用意する。姿勢・照明・寸法を変えて同じ失敗を再現できたかを残す。

**置き直しの導入順**　現行の `--board-read` と `--place-check` は実機を拒否する。次は開発計画で、現在実行できるコマンド列ではない。

1. **R0・腕を動かさず読む。** D3で盤の中央と端に印を使って置いたピースを反復撮影する。調整用と採点用の位置を分け、読取誤差と印に置く誤差を記録する。境界付近で判別できなければ保留。実際に解放して撮り直す姿勢でも同じ位置を撮り、影・遮蔽を含めて独立の基準との差とばらつきを求める。測定誤差が判定境界をまたぐ回は保留とする。現行simで再配置を判断する2 mmと、位置採点の3 mmとの幅を実物でも区別できるかを調べる。
2. **R1・隣のない一個。** D4とR0に加え、限定した実機入口でR1用の異常を模擬入力し、指令停止・保持・明示再開を確かめた後、同じ配置で空中確認できる進入・退出を先に通す。再把持は一回までとする試験案。空中確認だけでは盤上の再把持を確認できないので、その成否を別に記録する。
3. **R2・隣を一個置く。** S1で爪が開閉でき、S3で余裕を調べた寸法を選ぶ。すき間25 mmは候補。既定辺14 mmとの組合せは爪幅を超えうる。隣の位置を前後で比べ、読めなければ止める。
4. **R3・既定盤。** R2を通し、K1・K5・K7の測定で置き直す余裕が確認できた手だけ対象にする。コードの既定盤用の停止値（再把持を断るずれ7.5 mm、累積補正8 mm・3°、既置ピースの移動1.5 mm）をS1で寸法別に検証し、R1から段と配置を限る実機入口を使い、R3の対象だけを追加する。経路・読み・試行上限のどれかを外れたら記録して終了する。

**既存手順との整合**　空中高さは原則+50 mm、届かない場合は検証済み経路に限る例外がある。D4の+40 mmは既定盤の一例。現行の実機入口の下限も+40 mm。例外を使う前に実測した台・工具・対象寸法を反映し、当日の姿勢と全経路で爪先の最低高さと障害物までの余裕を保存する。確認不能な配置は停止として残す。D5では同じ条件で全手の空中経路が通らなければ机の高さへ進まない。フォロワーを使う本家コマンドは毎回P-001、自作側は共通の起動手順を使う。最初に力を入れる前に、使う道具・対象関節・開始姿勢・停止後の扱いをその日の手順と照合する。R1前は対象姿勢で新しい指令が止まること、通常停止時の保持と支持後の解除、通信復旧後も状態を読み直して人が再開するまで指令が出ないことを、記録で判定する。通信断で保持できるか不明なら、その姿勢の試験は保留する。ACTの終了動作は専用手順で扱う。[案Aの安全手順](計画書_完成形まで.md)・[D4](../利用者の日/D4_1個をつかんで置く.md)・[D5](../利用者の日/D5_パズル全部.md)・[P-001](../rules/RULES.md)

| I3　現場での有償検証と二品種目 | 開発が提案案を作成。現場責任者・品質・営業／現品と利用許可、事前の受入合意 | 一工程・一品種に絞り、良否の正解・許容誤差・タクト・保留時の復旧・担当・費用を合意してから実機評価。現行工程との差と監修・現地・保守を含む原価を記録。同じ機種で二品種目を見積もり、再利用できた作業と採算から続行を決める。 |

Isaac Simは、MuJoCoと実測の食い違いについて、別のエンジンで何を判別したいかが決まった段で同じ一手を照合する。Brevの起動・再開・削除は都度利用者に確認し、成果保全後の停止確認は既存手順に従う。今すぐのS0・S1・T0・I0はローカルで進められる。
