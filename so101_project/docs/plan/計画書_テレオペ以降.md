## いまの結論

- テレオペ（STEP 8）の後は、**P1 カメラと試し記録 → P2 本番の記録 → P3 学習 → P4 評価** の順に進める。各段に「終わりの条件」を置き、満たしたら次へ進む。
- **このパソコンでは学習しない。** NVIDIA の GPU が無く、入っている PyTorch は CPU 版（`2.11.0+cpu`、`cuda False`。2026-10-28 に確かめた）。学習はチームの人の NVIDIA の GPU のパソコンで回し、使えなければ Hugging Face Jobs で回す（下の「決めたこと」1）。
- フォロワーは、本家のコマンド（`lerobot-teleoperate`、`lerobot-record`、`lerobot-rollout`）の**1 回ごとに、直前に `tools\prime_goal.py` を流してから**使う（[ルール P-001](../rules/RULES.md)）。流してから Python で `SOFollower.connect()` を呼ぶと、目標位置と速度の上限が残り、アームが動かないことを 2026-10-28 に確かめた（フォロワー単体、休止姿勢、カメラ無し、1 回、6関節とも移動 0 ステップ）。本家の各コマンドを通した場合は未確認。**防げるのは「つないだ瞬間に跳ぶ」ことだけ**で、その後の最初の動きを抑えるのは速度の上限だけ。
- 評価（`lerobot-rollout`）は、時間が終わったときも `Ctrl + C` で止めたときも、「つないだときの姿勢へ 3 秒で自分で戻り、力が抜ける」。立方体をつかんだままでも戻る（本家のソースで確かめた。**実機では未確認**、前提 1c）。そのため `Ctrl + C` は腕を止める手段にならない。評価は休止姿勢から始め、本番の前に、立方体無しの安全確認を 2 段（低い速度、本番と同じ設定）で回す（手順書 14-2）。
- 本家のコマンドは、つなぐときにモーターの加速度を最大（254）に書き直す（`feetech.py` の `configure_motors()`）。そのため、本家のコマンドを使う間は、ルール P-001 の「加速度に上限を付ける」は守れない。抑えられるのは速度の上限（`prime_goal.py`）と、評価での 1 回の指令の幅（`--robot.max_relative_target`）だけ。
- P4 の評価は 10 回。**10 回で言えるのは大まかなことだけ**（下の欄5）。「方策が良い／悪い」の判定には使わず、次に何を直すかを決める材料にする。
- リーダーと、2台そろってのテレオペは、まだ実機で通していない（STEP 6〜8 待ち）。この計画の P1 以降は、すべて STEP 8 の後に始める。

## 欄3. 基準は本当に「何もしない」か

この計画は、条件を比べる実験ではない（ACT だけを、1 つの記録の量で試す）。比べる相手が無いので、この欄は当てはまらない。手引きは欄3〜5・7 を「比べる実験のときだけ」としているが、欄4・5・7 は、評価の数え方と結論の言葉を結果の前に決めるために使う。P5 で「記録を足す前と後」などを比べることになったら、そのときに欄3 を書く。

## 欄4. 測り方の点検（P4 の評価。本番の前に決める）

- **成功の決まり**（評価の前に決め、途中で変えない）：判定は、`--duration` が終わり、腕が戻って力が抜けた**後の状態**で 1 回だけ行う。そのとき立方体が箱の中にあれば成功。腕が箱を倒した、立方体を箱の外に落とした、戻る動きで立方体を持ち出した、は失敗。
- **段階**（成功・失敗に加えて数える。0/10 や 10/10 で差が潰れるのを防ぎ、欄6 でどこへ戻るかを決める材料にする）：つかめた／持ち上げた／箱の上まで運んだ／箱に入った（判定の時点で入っている）。1 回ごとに、届いた一番先の段階を書く。
- **置き場所**：記録に使った 5 か所から、各 2 回。合わせて 10 回。順番は先に表に書いておく（手順書 14-5）。
- **数え直す**：1 回ごとに、別のカメラ（スマホなど）で、始めてから力が抜けるまでを 1 本の動画に撮る。数えた人とは別の人が、動画を見て成功・失敗と段階を数え直す。本家の記録（sentry）は、1 回分の区切りが試行ではなく動画ファイルの大きさで決まり、自動でアップロードもするので、数え直しには使わない。
- **わざと悪い条件で 0 になるか**：本番の前に、**成功しえない条件**で 2 回回す（1 回は立方体を腕の届かない所に置く、1 回は箱を置かない）。どちらも「失敗」と数えられ、段階が「箱に入った」にならないことを確かめる。そうならなければ、成功の決まりか数え方を直す（この 2 回は本番の数に入れない）。
- 採点役に、どの方策の結果かを隠すことはしない（方策が 1 つしかないため）。

## 欄5. 規模と、見分けられる差

10 回の評価で出せる成功率の幅（95% の区間。`tools/success_interval.py` の出力。[記録](../records/success_interval_20261028.txt)）：

| 10 回中の成功 | 成功率の区間 |
|---|---|
| 0 | 0.00〜0.28 |
| 2 | 0.06〜0.51 |
| 3 | 0.11〜0.60 |
| 5 | 0.24〜0.76 |
| 7 | 0.40〜0.89 |
| 8 | 0.49〜0.94 |
| 10 | 0.72〜1.00 |

3 と 7 の行は、[2 つ目の記録](../records/success_interval_20261028_C4.txt) から写した。

- 10 回では幅が広い。そのため P4 は **「探索」** と名乗る。成功の回数は、次に何を直すか（記録を足す、置き場所を減らす、学習を延ばす）を決める材料に使い、「方策が使える／使えない」は決めない。
- **見分けられる差**（P5 で 10 回どうしを比べるとき。Fisher の正確検定、両側、p < 0.05。`tools/success_interval.py --compare 10` の出力。[記録](../records/success_interval_20261028_C4.txt)）：前が 0 回なら 5 回以上、前が 2 回なら 8 回以上、前が 3 回なら 9 回以上で、やっと差と言える。前が 6 回以上なら、10 回どうしではどんな結果でも差と言えない。おおよそ **6 回分の差**が要る。
- P5 で、記録を足す前と後を比べるなら、回数を増やす（20 回なら、10 回成功の区間は 0.30〜0.70。[記録](../records/success_interval_20261028.txt)）。比べる前に、その回数で見分けられる差を、同じ道具で出してここに書く。

## 欄6. 費用と止め方（実行の前に全部決める）

- 費用がかかるのは P3 だけ（学習の場所による）。チームの人のパソコンなら、費用は電気代と、その人がパソコンを使えない時間。HF Jobs を使うなら、回す前に上限の金額と時間を利用者が決め、この表に書く。
- 削ってよいもの：記録の回数（50 回を割っても P3 に進めるが、欄5 の幅はさらに広がる）、評価の数え直し（人が足りないとき。その場合は結果に「数え直し無し」と書く）。
- 削ってはいけないもの：P1 の試し記録、P4 の安全確認 2 段とわざと悪い条件の 2 回、毎回の `prime_goal.py`。
- 止める基準：
  - P1 で、Cadence の実際の速さが 27 Hz を割り、直らない → カメラの解像度を下げる（640×480）か、1 台にする。
  - P2 で、失敗の回が多く、置く場所ごとに 8 回を割る → 記録を足す。
  - P3 で、試しの学習が通らない → 本番の学習を回さない。
  - P4 の安全確認（2 段のどちらか）で、下の合格の条件を 1 つでも満たさない → 本番の評価を回さない。原因を直してから、安全確認をやり直す。
  - P4 のわざと悪い条件で「成功」か「箱に入った」が出る → 本番の評価を回さない。成功の決まりか数え方を直す。
- **安全確認の合格の条件**（2 段とも）：始めた瞬間に、どの関節も目で見て跳ねない。過負荷のエラーが出ない。本家の記録に `Relative goal position magnitude had to be clamped to be safe.` の警告が出る（`--robot.max_relative_target` が働いた印。`robots/utils.py`）。終わりの 3 秒の戻る動きと、`Ctrl + C` で止めたときの戻る動きが、机や箱に当たらない。
- **P4 の結果で、次にどこへ戻るか**（結果の前に決める。原因は分けていないので、行き先は失敗の段階で選ぶ）：
  - 0〜2 回：段階の数を見る。「つかめた」に届かない回が多い → カメラの位置と記録の質（P2）。「つかめた」の後で落とす回が多い → 学習の長さ（P3）を延ばす案と、記録を足す案を、利用者に並べて見せる。評価の動きの上限（指令の幅 5°、30 秒）が邪魔をしていそうなら、その仮説も並べる。
  - 3〜7 回：失敗の型の多い順に、上と同じ並べ方で次の一手を出す。
  - 8〜10 回：置き場所を記録に無い所へ広げる試し（探索）を、P5 の案として出す。
  - どの場合も、行き先は利用者が決める（P5）。
