## いまの結論（2026-11-12 夕方の時点）

- シミュレータは、ちくわ（`ちくわ排除機構` のプロジェクト）の 3D 画面と逆運動学を写して作った。写したのは画面（`index.html`。読み込むファイルと題、URL で条件を変えたときに組み直す所、撮影用の URL の欄だけ変えた）、three.js、逆運動学（`kinematics.js`。写した直後に md5 一致を確かめた）、当たり判定の表示（`collision-view.js`。使っていない）、撮影の道具（`tools/mock-shot.sh`）。
- 腕の寸法は SO-101 の公式の URDF（`so101_new_calib.urdf`）の値を `sim/so101.js` の 1 か所に置いた。**腕の形は公式の STL**（TheRobotStudio/SO-ARM100 の `Simulation/SO101`。13 個）。画面の形と当たり判定の点は、同じ STL から同じ回に作る（`python tools/build-models.py`）。
- 開かなかった原因：Claude の画面の右の枠は、プロジェクトの外のファイル（`file://`）を動かない写しとして出す。`http://localhost:8801/`（ちくわの `.claude/launch.json` の `lerobot-sim`）で開くと動く。エクスプローラーから `sim/index.html` をダブルクリックしても動く。
- 確かめたこと（どれも `sim/` で実行）：
  - 生の URDF と `so101.js` の数字 54 個が完全に一致（`node tools/check-urdf.js`。前提 U-1 は済）。
  - 逆運動学の順運動学と、URDF の行列の積（別の作り）が、可動域の中の乱数 2000 姿勢で一致した（道具の点の差 最大 3.45e-13 mm、向きの差 最大 2.09e-6°）。`node tools/check-fk.js`
  - 爪の寸法を STL の形から測った（`node tools/check-scene.js` の 1 行目）。道具の点（`gripper_frame`）から：固定の爪の内側の面 0.0mm、指先 7〜8mm、指の厚さ 8〜13mm（ブロックの高さの範囲で。ブロックが大きいほど厚い所まで入る）。固定の爪として測った点は、ブロックの高さの範囲・横 ±7mm の指の点だけで、モーターの点は拾っていない（点検 C6 の 4）。**仮に置いていた値（固定の爪の面 12.5mm・指の厚さ 6mm・挟める幅 70mm）は合っていなかった。**
  - 動く爪は回って開くので、開くほどブロックに触れる内側の面が上がり、ブロックの上の角にしか触れなくなる。「内側の面の下端がブロックの高さの半分より下まで届く」所までを挟める開きとした（**この線は Claude の決めた目安で、滑らずに持てるかの物理の裏付けは無い**）。ブロックの辺 12〜30mm で、挟める幅は 42〜47mm（上限の角度 20〜25°）。はじめは爪の外側の角（いちばん低い点）で測っていて甘かった（点検 C6 の 3 で直した。直しても既定の辺は 14mm のまま）。
  - そのため、25mm のブロックでは 2 マスを一度に挟めない（2 マス 50mm + 指が入るすき間 17mm = 67mm > 挟める幅 43mm）。2×2 の O はどの向きにも隣のマスがあるので、つかめない。2 マスを挟めるいちばん大きい辺は 14mm（2 マス + すき間 15mm = 43mm ≤ 挟める幅 46mm）。画面の既定は 14mm にした（決めたこと 7）。**この結論は 2 つの決め方に依存する**（点検 C6 の 2）：(a) ピースの中のマスどうしも、指が入るすき間を空けて細い棒でつないでいる（継ぎ目の無いピースなら 25mm でも 2 マス 50mm で、挟める幅に近い）、(b) 上の「高さの半分」の線。
  - 届く範囲（`node tools/reach-ring.js`。真上を向けて、爪の向き 0° と 90° の両方が解ける、肩の回転軸からの距離。0°・45°・90° の 3 方向だけを 5mm 刻みで見た）：道具の点の高さ 15mm で 55〜265mm、50mm で 80〜240mm、60mm で 90〜235mm。盤と置き場はこの輪を全周に広げて置いている（見ていない方向は外挿。ただし動きはコマごとに逆運動学で解くので、解けた結果は外挿に頼っていない）。
  - パズル（`node tools/check-scene.js`。目標の形 4 種 × すき間 0mm・既定。ブロックの辺 14mm）：
    - 既定のすき間（15mm = 指が入るすき間 13.5mm の切り上げ + 1mm）では、4 種とも解けた。置いた位置の差は最大 0.158mm・向きの差 0.000°。判定の点で見た当たりは 0。いちばん近づいた所は 1.2〜1.7mm（動く爪 ⇄ ピース）。**ただし点と点の間は最大 2mm ほど甘く出るので、1.2mm は「当たっていない」と言い切れる幅ではない**（点検 C6 の 4）。実機の位置の誤差（測っていない）とも比べていない。指先の最低の高さ 3.9mm。
    - すき間 0mm：4×5 の 2 種は、敷き詰め方 0〜9 番のどれも解けない（指が下りるマスが埋まる。敷き詰め方は 10 通りで打ち切っている）。3×3 は 0 番では解けない（手首の回転の可動域）が、1・3・6・7・8・9 番では解けた（点検 C6 の 1。はじめ「解けない」と書いたのは 0 番だけを見た誤り）。3×4 は 0 番で、隣どうしが接して置ける順番が見つかって解けた（接する組の重なり 0.3mm まで。1mm までは点の間隔・置く位置の差ぶんとして許す）。
    - 負の検算：3×4 をすき間 4mm で「指が入る」として無理に解かせると、当たり 21 コマ（動く爪 ⇄ 隣の L のピース、最深 −5.8mm）。判定は生きている。
  - 当たり判定は、腕・爪の STL の表面に約 3mm 間隔で打った点（全部で約 2.9 万点）⇄ ピースの立方体・机。持っているピースは立方体の表面の点で、ほかのピース・机と測る。接する組（つかむ・運ぶ・離す間の 爪の付け根と固定の爪・動く爪 ⇄ そのピース、すき間 0 のときのピースどうし）は 1mm までの重なりを許す。持っているピースの位置は固定の爪の面の値から作るので、固定の爪の面を測り違えても、この判定では見つからない（点検 C6 の 6）。**見ていないもの**：腕どうしの当たり（自分との干渉）、ピースをつなぐ細い棒、点と点の間（最大 2mm ほど甘く出る）、物理、STL と実物の爪が合っているか。
  - 撮影：公式の形の腕が L のピースを両側から挟んで持ち上げる所、判定の形だけを出した絵、無理に詰めた場合に動く爪と L のピースが赤くなる所を見た（`sim/_check/stl/`）。
