# 計画書　産業用フィジカルAIを検査工程の事業に育てる

[提案書](提案書_産業用フィジカルAIと事業化.md) ｜ [Claude用の実行手順](../産業用フィジカルAI開発手順書.md)　2026-11-19

## 到達点と最初の案件

利用者の目標は「最大限、Claudeの稼働でタスクが終わる」「そのフィジカルAIをFanucCRX-20iA/Lやデンソーウェーブのロボットでも大活躍」させること。まず、似た部品が二つ流れてくる架空の検査セルを使う。入力は外観検査の判定、画像、搬送・ロボットの信号。成果は対象を取り出した後に正しい個体の排除を確認し、証拠が足りないとき保留できる工程。提案書にある人が定めた光学・教示点と検査アプリの役目を引き継ぐ。

## 投資順と成果物

| 順 | Claude の仕事 | 次へ進む条件と引き渡すもの |
|---|---|---|
| 1　架空セル | 入力例、時系列再生、個体追跡、独立採点を実装。正常と故障を同じ入口から再生する | 手順書の全ケースで期待した判定を再現。比較動画と判断履歴から、どの信号・画像で判断が変わったかを特定できる |
| 2　物理で一手 | SO-101 の既存の画像制御と MuJoCo を接続。つかむ、運ぶ、離す、整定後に撮る。空振り・滑りも実際の物理状態から描画する | 物体を指令に合わせて配置し直さず、一手の最初から採点まで再現。幾何判定、物理、画像の結果が食い違った例を保存する。[既存の接続計画](計画書_SO101パズルの発展.md) |
| 3　産業機に移す | 同じ検査・排除工程についてCRX-20iA/Lとデンソー向けの変換を試作。対象機種、制御装置、工具が決まった範囲でオフライン検証 | 共通のケース、機種別下書き、差分表、未検証項目を提出。モデル・ライセンスが無い機種は机上検査までで一区切り。機種固有の空欄を推測で埋めない |
| 4　営業技術の案件化 | 架空案件の提案見本を作る。許可済みの引き合いが来たら、ワーク一種・セル一台で有償検証の仕様と見積を起こす | 顧客の課題、現品、良否の正解、決裁者、受入基準、対象外と費用を着手前に合意。実機の信号・停止復帰・検査性能は現場の責任者と測定する |
| 5　二件目と継続 | 同じ機種で品種だけを替え、初回と同じ納品物を作る。次に現場の失敗ログを再生し、保守の検算に戻す | 案件別の売上、監修・現地・保守・計算・利用料を含む原価、共通化できた項目を比較。収支・継続依頼が揃えば品種追加・保守契約を提案する |

段階1〜3の仮説・実装・テスト・文書更新はClaudeが担当。初回の受け渡しは比較動画、判断履歴、機種差分表、営業提案見本の4点。実機準備は既存の担当と並行し、機種と品種を同時に変えた結果から移植工数を推定しない。

## 何を測って続けるか

基準方式は「検査結果を受け、腕の完了信号で排除済みと記録」。候補方式はそこに個体追跡と再撮影を加える。同一の初期配置・外乱で回し、誤排除、誤完了、不良の流出、保留、工程時間を個別に数える。次に追跡と再撮影を片方ずつ外して寄与を見る。最初の少数ケースは失敗を発見する探索で、現場の不良率や投資回収の予測には使わない。調整済みと初見のケースを分けて保存する。

最初の予算はローカルの既存環境内、追加費用0円。1回の作業は一つの検証可能な成果で閉じる。次の試作は「現場判断に効くか・手元で反証できるか・二件目に再利用できるか」でClaudeが選ぶ。例として、追跡と再撮影が曖昧な個体を拾えたら、同じ記録を品種切替の監査や問い合わせ再現に使ってみる。監修時間が減らなければ報告に必要な入力と納品範囲を絞り、支払意思が得られなければ社内の営業工数削減を評価する。

実機の採否、有償環境の起動、顧客資料の外部提供は既存の承認範囲に従う。人には実物・光学・品質・現場判断が要る項目を一枚に集める。Claudeは未検証の仮定、逆の説明、次の追試を記録し、方向を決める提案は [独立点検の台帳](../records/R001_LOG.md) に残す。
