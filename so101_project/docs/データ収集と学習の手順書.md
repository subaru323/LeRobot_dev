### フォロワーを使うコマンドの前に、毎回すること

本家のコマンド（`lerobot-teleoperate`、`lerobot-record`、`lerobot-rollout`）は、つないだ瞬間にフォロワーに力を入れ、モーターに残っている目標位置へ最高速度で向かわせます（組み立て手順書 STEP 8-1）。**コマンドを1回流すごとに、その直前に**次を流します。

```powershell
python tools\prime_goal.py COM3
```

- 最後に `OK: goal = present.` と出ることを確かめます。表示の `present` の数字が、フォロワーの関節の数字か（リーダーにつないでいないか）も確かめます。
- 流した後は、フォロワーを動かさず、5V も抜かずに、すぐ本家のコマンドを始めます（設定はモーターの電源で消える）。
- **これで防げるのは「つないだ瞬間に跳ぶ」ことだけです。** その後の最初の動き（記録ならリーダーの姿勢へ、評価なら方策の出力へ）を抑えるのは、速度の上限（既定 1 秒に約 176°）だけです。記録では、始める前にリーダーとフォロワーの姿勢をそろえます。評価では、14 の安全策を使います。

### 11-2. 記録

カメラが 2 台のとき（1 台なら `wrist` の部分を消します）：

```powershell
lerobot-record --robot.type=so101_follower --robot.port=COM3 --robot.id=follower1 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}}" --teleop.type=so101_leader --teleop.port=COM4 --teleop.id=leader1 --display_data=true --dataset.repo_id=<HFユーザー名>/cube_pick_test --dataset.no_stamp=true --dataset.single_task="Put the red cube in the box" --dataset.num_episodes=2 --dataset.episode_time_s=20 --dataset.reset_time_s=20 --dataset.push_to_hub=false
```

- `index_or_path` の 0 と 1 は、9 の表の番号に置き換えます。
- `--dataset.no_stamp=true`：これが無いと、本家はデータの名前の後ろに日時（`_20261030_153012` のような形）を足します（`configs\dataset.py` で確かめた）。名前を後の学習のコマンドと合わせるために付けます。
- 記録中のキー操作（本家の案内）：

| キー | 動き |
|---|---|
| `→`（または `n`） | この回を早めに終えて、次へ |
| `←`（または `r`） | この回を取り消して、やり直す |
| `Esc`（または `q`） | 記録を終えて、保存する |

- 記録を止めると、フォロワーの力が抜けます。止める前に、リーダーでフォロワーを低い姿勢に下ろすか、手で支えます。

## 14. 実機で評価

### 14-1. 評価の動き方（先に読む）

本家の `lerobot-rollout` は、決めた時間（`--duration`）が終わったときも、`Ctrl + C` で止めたときも、**つないだときの姿勢へ 3 秒かけて自分で戻り、その後に力が抜けます**（`rollout\configs.py` の `return_to_initial_position` が既定で有効、`rollout\strategies\core.py` で 3 秒。ソースで確かめた。実機では未確認）。そのため：

- 評価を始める姿勢は、**休止姿勢**（たたんだ低い姿勢）にします。力が抜けても倒れにくく、戻る先として安全です。
- 戻る間、腕は作業場所を通ります。立方体をつかんだままでも戻ります。人は手を出さず、周りに物を置きません。
- **`Ctrl + C` では腕は止まりません**（止めても 3 秒の戻る動きが起きる）。
- リーダーは使わないので、テレオペのように「リーダーで下ろしてから止める」はできません。
- 本家のコマンドは、つなぐときにモーターの加速度を最大に書き直します。抑えられるのは、`prime_goal.py` の速度の上限と、`--robot.max_relative_target`（1 回の指令の幅）だけです。
- **方策が動いている間と戻る間は、腕に手を出しません**。腕から 1 m 離れ、5V の線に手が届く所にいます。
- **非常のとき**：腕を手で支えてから 5V を抜きます（抜くと、その場で力が抜けて倒れる）。

### 14-2. 安全確認（2 段）と、わざと悪い条件（本番の数に入れない）

本番の評価の前に、立方体を置かず、`--duration=10` で、次の 2 段を 1 回ずつ回します。どちらも下の合格の条件で見て、1 つでも満たさなければ、本番に進みません。

| 段 | `prime_goal.py` | `--robot.max_relative_target` | 合格 |
|---|---|---|---|
| 1 | `python tools\prime_goal.py COM3 --speed 1000`（1 秒に約 88°） | 5 | [ ] |
| 2 | `python tools\prime_goal.py COM3`（本番と同じ。既定 2000、1 秒に約 176°） | 5 | [ ] |

`--robot.max_relative_target=5` は、1 回の指令で今の位置から 5° までに削ります（30 Hz で 1 秒に約 150°。`config_so_follower.py` にある。実機では未確認）。

**合格の条件**（2 段とも）：

- 始めた瞬間に、どの関節も目で見て跳ねない
- 過負荷のエラー（`Overload error`）が出ない
- 画面の記録に `Relative goal position magnitude had to be clamped to be safe.` が出る（上限が働いた印。出なければ、上限が効いているか分からない）
- 終わりの 3 秒の戻る動きが、机や箱に当たらない
- 2 段目では、途中で `Ctrl + C` を押し、戻る動きが机や箱に当たらないことも見る

安全確認に通ったら、**わざと悪い条件**で 2 回回します（本番と同じ設定、`--duration=30`）。1 回は立方体を腕の届かない所に置く、1 回は箱を置かない。どちらも「失敗」と数えられ、段階が「箱に入った」にならないことを確かめます（計画書の欄4）。

### 14-3. 始める前に（毎回）

- [ ] フォロワーの周り 1 m に物と人がいない。自分は腕から 1 m 離れ、5V の線に手が届く位置にいる
- [ ] フォロワーを休止姿勢にした

### 14-4. 実行

```powershell
lerobot-rollout --strategy.type=base --policy.path=<HFユーザー名>/act_cube_pick --robot.type=so101_follower --robot.port=COM3 --robot.id=follower1 --robot.max_relative_target=5 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}}" --task="Put the red cube in the box" --duration=30
```

- `--duration=30`：記録の 1 回 20 秒に、余裕 10 秒（計画書の欄2）。
- カメラの名前（`front`、`wrist`）と番号、解像度は、**記録のときと同じ**にします。
- `--robot.id=follower1` も記録のときと同じにします（キャリブレーションが同じでないと、学習した動きとずれる）。
- **判定**は、30 秒が終わり、腕が戻って力が抜けた**後**に 1 回だけします。そのとき立方体が箱の中にあれば成功（計画書の欄4）。
- 本家の記録（`--strategy.type=sentry`）は、1 回分の区切りが試行ではなく動画ファイルの大きさで決まり、自動でアップロードもするので、数え直しには使いません。使うときは、名前を `rollout_` で始め（例：`<HFユーザー名>/rollout_eval_cube_pick`。始めないと本家が止まる、`rollout\context.py`）、**`--dataset.private=true` を足します**（動画には部屋や人が写る）。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 記録・評価を始めた瞬間にフォロワーが跳ねる | `prime_goal.py` を流し忘れたか、流した後に 5V を抜いた（設定はモーターの電源で消える）か、ポートを読み替え忘れた。止めて、組み立て手順書の「困ったとき」の過負荷の対処をしてから、流し直す |
| 評価が終わった後、腕がひとりでに動く | 本家の仕様（つないだときの姿勢へ 3 秒で戻る）。14-1 を参照 |
| HF Jobs の学習を `Ctrl + C` で止めたのに課金が続く | `Ctrl + C` は表示から離れるだけ。`hf jobs cancel <job-id>` で止める |
| フォロワーの動きが遅れる | `prime_goal.py` の速度の上限が低い。`python tools\prime_goal.py COM3 --speed 4000`（0 で上限なし） |
| 学習のコマンドでデータが見つからない | 記録のときに `--dataset.no_stamp=true` を付け忘れると、名前の後ろに日時が付く。記録の最後に出た名前を使う |
| カメラが開けない | 番号を 9 の表で確かめる。ほかのソフト（ビデオ会議など）がカメラを使っていたら閉じる |
| 記録が遅い（Cadence が下がる） | 11-3 を参照 |
