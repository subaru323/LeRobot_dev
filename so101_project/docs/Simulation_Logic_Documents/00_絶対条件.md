## 条件 1 当たり判定は、ほかのすべてより先に付ける

**描いた物すべてに当たり判定を付け、「判定が付いていない物 0」「比べていない組 0」を道具で確かめてから、配置・動き・報告に進む。**

ちくわの 4 つの段（意味が 4 回ちがう）：

| 段 | 何を問うか | 破れたときに起きること |
|---|---|---|
| 1 宣言 | その物は判定に入っていると書いてあるか | 物があることを忘れる |
| 2 網羅 | 入っている物どうしを全部比べたか | 見ていない組が、いつまでも 0 件で合格する |
| 3 包む | 判定の形は物を包んでいるか | はみ出た所で当たっても出ない |
| 4 一致 | 判定の形は物と同じ形か（条件 12） | 大きすぎると解ける動きを捨て、小さすぎると当たりを見落とす |

**1〜3 を全部通しても 4 は破れる。**

作業の順は一方向ではない（ちくわ）：

```
0. 置き方を決める（台・カメラ・盤・置き場）
1. 全部の物に当たり判定を付ける
2. 監査で確かめる
3. 動きを作る（写す姿勢・経由点など）── ここで判定の相手が増える ──┐
4. 結果を出す                                                    │
     ↑                                                           │
     └── 3 で姿勢や物が増えたら 1・2 へ。置き方が原因なら 0 へ ◀──┘
```

**2026-11-17 の実例**：「写す姿勢」は、上のカメラからピースを隠さない姿勢として 3 の段で足した（隠れるかは数えた）。しかし腕どうしの当たりは 1 の段に無かったので、その姿勢がめり込んでいることを誰も見ていなかった。

**なぜ絶対条件か（ちくわ）**：判定の穴は「良い数字」として出る。見ていない組は 0 件で合格し続ける。だから穴があるほど作業は速く進み、進んでいるように見える。

## 条件 5 腕の自分との当たりを忘れない

**判定に入れる。** 2026-11-17 の午前に入った（別の会話が書いた。`sim/` のコードはその会話が持ち主）。

### いまの判定（2026-11-17）

- 形：腕の部品のまとまり（base・j1〜j5・jaw・cam）ごとに、STL の三角形を格子で切って、丸め箱にする（ちくわの `bodySetFromMeshExact`。`sim/chikuwa-collision.js` はちくわの `collision.js` の写し）。段は 3 つ（12mm → 4mm → 1.5mm）。近い組（3mm【仮】未満）だけを次の段で見直す。
- 外す組（`ADJ` の 9 組）：関節でつながる 6 組、ねじで固定の j5|cam、1 つの関節で距離が決まる jaw|cam・j4|cam。jaw|cam と j4|cam は、可動域全体を 1° おきに 1 回だけ見る `staticCheck` がある。`check-scene.js` が流す（2026-11-17 の 12:25 の版では入っていた。いつからかは確かめていない。画面の判定の表には出ない）。12:30 の出力は jaw|cam −0.4mm（爪 −10°）、j4|cam −0.8mm（手首の回転 −35°）で、どちらも要確認として数える（箱は両側で最大 3.6mm 太るので、当たるかはこの道具では分けられない。1° の間は見ていない）。j5|cam はどこでも測っていない。
- コマの間：組ごとに「2 つのコマの隙間の平均 − その間に縮みうる量の上限（2 つの間の関節だけの腕の長さ × 角度の変化）」で下限を出す。下限が負なら、真ん中で割って測り直す（深さ 6 まで）。割り切れずに残った負の下限は `worstBound` に出る。
- しきい値：めり込み（< 0）で NG。割り切れずに残った間の下限 `worstBound` が負でも NG（12:25 の版では入っていた。その前は要確認）。3mm【仮】未満（`self-collision.js` の `WARN`）なら要確認。
- 負の検算：`check-scene.js` の「腕どうしの負の検算」。前の写す姿勢と経由点に戻すと、めり込みが出る（12:30 の出力も base|j5 −2.8mm、1.4 秒）。
- 12:30 の `check-scene.js`：NG 0。負の検算を除く解けた 9 行で、腕どうしのいちばん近い所は 3.0〜4.1mm（ほとんど j4|jaw。台なしの 4×5 I O L J S は j1|j5 3.0mm）。11:16 に NG だった台なしの 4×5 I O L J S（j2|cam −2.3mm。別の会話によると、S を運ぶ間に手首の回転が 29° から 101° まで回る）は、腕どうしが 3mm 未満の手だけ、運ぶ高さを 20mm 上げる試し方（`scene-data.js` の `CARRY_LIFT`。[取る側, 真ん中, 置く側] の上げ方を 4 通り試す。S は真ん中と置く側、L は全部を上げた。点検 C18 の点検役が node で確かめた）で、3.0mm になった。3.0mm は、3mm 以上になった最初の試し方で止めるので、しきい値のすぐ上に来る（余裕を測った値ではない）。負の検算の行は別で、手首のカメラの負の検算が 2.2mm（j2|cam）、前の写す姿勢の 2 行が −2.8mm（コマの間の負の検算は j1|j4、腕どうしの負の検算は base|j5）。
- 前の写す姿勢 `[-90,0,90,90,0]`（爪 0）を判定と同じ 3 段で測ると、j1|j4 が −2.8mm（こちらで流した。`scene-data.js` の注も −2.8mm）。別の会話が報告した −4.7mm は、4mm の箱だけで測った値。j2|cam の 0.5mm がメッシュで 2.1mm というのも別の会話の報告で、こちらでは流していない。

## 条件 12 判定の形が実物と同じことを、数字で示す

ちくわの量をそのまま使う：

| 量 | 意味 | 許す量 |
|---|---|---|
| 小さすぎ（はみ出し） | 実物が判定の形の外へ出ている量 | **0**。当たっているのに出ない（実機が壊れる） |
| 大きすぎ（膨らみ） | 判定の形が実物より外へ出ている量 | 部品の役割で変える。ぶつかってはいけない物は上限を決める【未定】。**触れるのが仕事の物（爪の内側・ピース）は、触れる面を実物の形で持つ** |

SO-101 の判定の形は 2 種類ある。どちらも数字で示していない：

| 物 | いまの形 | 小さすぎの見込み | 測ったか |
|---|---|---|---|
| 腕・爪・手首のカメラ | STL の表面の点（約 3mm おき） | 点と点の間 最大 約 2mm（`collide.js` の注）。腕どうしの判定は、この点ではなく丸め箱（`self-collision.js`。1.5mm の格子で、実物より最大 1.8mm 太い） | 測っていない |
| 上のカメラの台 | STL の三角形そのもの（`meshField`） | 0（三角形そのもの）。外は 15mm まで測る。中は、深さの上限なしで負が出る（K-03） | 測っていない |
| ピース | 立方体の箱 | つなぎの棒を見ていない（小さすぎ） | 測っていない |

**形を変える前に、測る道具を先に作る**（ちくわ 03 §2 の手順 0）。

## 条件 14 動きは、カメラの絵だけから決める（こちらで足した）

**計画（どのピースを、どこで、どの向きでつかむか）に渡してよいのは、カメラの絵、腕の関節の読み、校正のファイルだけ。本当の置き場（シミュレータが絵を作るのに使う値）は、結果の採点にだけ使う。**

- 理由：本物の腕は、本当の置き場を知らない。シミュレーションで本当の置き場を使うと、カメラ・見つける道具・校正の誤差が、どこにも出てこない。だから「シミュレーションで解けた」が、実機で解けることを何も言わない（利用者 2026-11-17「シミュレーションにはカメラの位置からの画角が必要だし、その画角だけを使ってロボットのプログラムを出力してアームを動かすシミュレーションが必要じゃない？」）。
- 機械で守る：本当の置き場を持つファイルと、計画を出すプログラムを分け、計画のプログラムがそのファイルを読まないことを道具で確かめる（[09 §3](09_画像だけで動かすシミュレーション.md#3-守ること)）。
