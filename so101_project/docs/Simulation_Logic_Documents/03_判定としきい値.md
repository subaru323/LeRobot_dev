# 03 判定としきい値

作った日：2026-11-17。ちくわの `03_判定としきい値.md` を移した（利用者「当たり判定の作り方とか、ちくわ排除機構の docs に全部書いてるから丸ごとパクってきて」2026-11-17）。**当たり判定の作り方（§2〜§6）はちくわのまま。** 移していない項目は、下の「移していないもの」に理由を書いた。 数字（しきい値・刻み）はちくわの腕（CRX-20iA/L、腕の長さ 1m 級）のもので、SO-101（腕の長さ 0.3m 級・ピースは辺 14mm）にはそのまま使えないので、SO-101 の値と、決まっていない所を並べて書く。

**何を測り、いくつで ok / 要確認 / ng とするか。**

## いまの結論（2026-11-17）

- 作り方の標準は §2 の「判定の形の作り方 10 段」。SO-101 では 0 段（一致を測る道具）がまだ無い。
- **腕どうしの当たりは、2026-11-17 に判定に入った**（別の会話の `sim/self-collision.js`）。12:30 の `check-scene.js` で NG 0。外した jaw|cam・j4|cam は `staticCheck` で −0.4mm・−0.8mm と出て、`check-scene.js` の中で要確認として数えている。画面の判定の表には出ない（[00 の条件 5](00_絶対条件.md#条件-5-腕の自分との当たりを忘れない)）。
- しきい値の多くは【仮】か決まっていない。元になる腕の繰り返しの誤差を、まだ測っていない（[計画書_完成形まで](../plan/計画書_完成形まで.md) の K1）。

## 1. 判定の項目

| 判定 | 測る量 | ok | 要確認 | ng | 出どころ |
|---|---|---|---|---|---|
| **当たり（腕・持っているピース ⇄ ピース・机・台）** | いちばん近い所の距離 [mm] | ≥ 2.5【仮】 | 0〜2.5 | めり込み（負） | 2.5 は `sim/` の判定の甘さ（点の間 約 2mm + 割り方 約 0.6mm）。ちくわは 15（下） |
| **腕どうしの当たり** | 外さない組のいちばん近い所 [mm]（丸め箱どうし） | ≥ 3【仮】 | 0〜3 | めり込み（負）、または割り切れない間の下限が負 | `self-collision.js` の `WARN`（サーボの追い遅れの見込み）。`scene-data.js` の判定の表と `check-scene.js` に出る。前からの下見の道具 `self-collide.js` は、点どうしで 0.5mm より深いと数える（`DEEP`） |
| 隣どうしの組（除外の前提の点検） | めり込み [mm] | ≤ 2【仮】 | — | > 2 | 下見の道具 `self-collide.js` の `DEEP_ADJ`。判定（`self-collision.js`）の中には無い |
| **届く** | 逆運動学が解け、URDF の可動域の中 | 全点 | — | 1 点でも外 | `motion.js` |
| **見える（上のカメラ）** | レンズ → ピース・盤のマスの上の面の 5 点の線に、腕・台の点が近づく距離 | ≥ 2.5mm【仮】 | — | < 2.5mm（隠れる） | `overhead-occlusion.js` |
| **見える（手首のカメラ）** | 手首 → ピースの線が爪の三角形にさえぎられるか | 0 本 | — | 1 本以上 | `camera-budget.js`。台・ケーブル・ほかのピースは見ていない |
| **つかめる** | 爪とピースのずれが、許せるずれの中か | 中 | — | 外 | 許せるずれは `camera-budget.js`（つかむ段 1.56〜1.72mm・離す段 1.03〜1.91mm。[想定動作_SO101パズル](../plan/想定動作_SO101パズル.md)） |
| **速さ** | 関節の速さ ÷ 実機のサーボの上限 | ≤ 75%（ちくわ） | 75〜100% | > 100% | 実機の上限と比べていない（決まっていない） |
| **動かない物どうし** | 台・盤・置き場のピースの重なり | 重なりなし | — | 重なり | `check-layout.js` の置き場の検算 |

### 移していないもの（ちくわの 03 §1・§5、00 の構造）

消さずに、理由と一緒に残す。要るようになったら移す。

| ちくわの項目 | ちくわの値 | 移していない理由 |
|---|---|---|
| 連続性（1 コマの最大の関節の動き） | ≤ 15° / 45° | ちくわでも、どの画面も使っていなかった（60/120 で見ていた）。SO-101 ではコマの間を動いた量（§3）で割っている |
| 一回の関節の動き | ≤ 60° / 120° | 経路の短さ（ちくわ 00 の条件 2）を移していないため。1 コマの動きの上限は、実機へ送るとき（[08 §5](08_カメラ_配置と配線とプログラム.md#5-プログラムの組み方)）に別に付ける |
| 総関節移動 | 【仮】下限 × 2 / × 4 | 同上 |
| ループ（始めと終わりの関節の差） | < 1° | パズルは 1 回で終わり、回り続けない |
| **姿勢の分かれ目（肘の上下・手首の反転）の反転 0 件** | 0 件 | **入れるべき見込み**だが、SO-101 の 5 軸で何が分かれ目かを、まだ書いていない（[K-11](現在の課題.md#k-11)） |
| 2 回で解く（1 回目の答えを初めの値にしてもう一度） | — | 解き方を決まった答えにする手の 1 つ（§5）。いまの逆運動学で要るかを見ていない |
| ちくわ 00 の 3 層の構造（確かめられる → 成り立つ → 良い の順） | — | 00 では条件だけ移した。順は「成り立つを先に、良いは後」（00 の条件 2・10 を移していない理由）で守る |

### 当たりの余裕のしきい値の決め方（ちくわの式。SO-101 の値は決まっていない）

ちくわは次の式で 15mm を出した：

```
要る余裕 = 物の誤差（二乗和の平方根） + コマで刻む誤差 + 形にしていない物の予備
ちくわ  = 2.81 + 5.00 + 5.00 = 12.81mm → 15mm
```

SO-101 では、同じ式に次の項を入れる。**どれもまだ測っていないか【仮】**：

| 項 | SO-101 での値 | 出どころ |
|---|---|---|
| 腕の繰り返しの誤差 | 測っていない | K1（紙の格子で測る） |
| 上のカメラの台の置き方 | ±2mm【仮】 | `so101.js` の `OVERHEAD`（STL の形から組んだ） |
| 判定の形の甘さ（点の間） | 約 2mm（片側） | `collide.js` の注。測ってはいない（[00 の条件 12](00_絶対条件.md#条件-12-判定の形が実物と同じことを数字で示す)） |
| コマで刻む誤差 | 約 0.6mm（4mm で割ったとき） | `scene-data.js` の `SUB_STEP`（S-4 で測った） |
| 形にしていない物 | ケーブル・ピースのつなぎの棒 | 決まっていない（[K-07](現在の課題.md#k-07)） |

> ちくわの注：校正していない腕では、−13mm の当たりと「余裕 +2mm」が区別できない。**校正は前提。**

**例外**：爪とピースは、つかむのが仕事なので近づく（§2 の「意図して近づく区間」）。ここに上のしきい値を当てない。

## 2. 当たり判定の作り方

### 形の選び方（ちくわの表。SO-101 の物を足した）

| 実物 | 使う形 | 理由 | SO-101 で当てはまる物 |
|---|---|---|---|
| 曲がった腕・込み入った形 | **丸め箱の集まり**（STL から）。球の集まりは使わない | 球は大きすぎと小さすぎが同時に出た（ちくわで 96.8mm と 31.0mm） | 腕・手首のカメラの台。腕どうしの判定は丸め箱（`self-collision.js`）。腕と台・ピースの判定は表面の点のまま（下の「いまの形」） |
| 縦に立つ円柱（柱・ピン） | 上下が平らな円柱 | カプセルだと上下に丸い頭が出る | — |
| 角材 | 角柱 | 外接円は太すぎ、内接円は細すぎ | 上のカメラの台の柱（いまは三角形そのもの） |
| 端が平らな部品（カメラ） | 端が平らな円筒・箱 | カプセルは両端に鼻が出る | 上のカメラ本体（32×32 の基板） |
| 角ばった部品 | 向きのある箱 | | ピース（立方体） |
| **触れるのが仕事の物**（指・爪の内側） | **触れる面を実物の形で持つ**。外接円で包まない | ちくわで、指を丸棒で見たら、どの姿勢でも 15.81mm 食い込み、その段が成り立たなくなった | 爪の内側（いまは STL の点と三角形。S-8 で三角形まで測り直す） |

### 判定の形の作り方 — 標準の手順（すべての判定の形に使う）

ちくわで利用者が決めた（2026-09-06）：「今後ワークやカメラや台が決まって当たり判定を作るときは、今回ロボットアームの当たり判定を作ったのと同じやり方でやりたい」。**順を守る。1 つでも飛ばすと、安全でない向きへ静かに壊れる。**

**始める前に、その部品が「ぶつからない物」か「触れる物」かを決める**（許す大きすぎが桁で違う。[00 の条件 12](00_絶対条件.md#条件-12-判定の形が実物と同じことを数字で示す)）。

| # | やること | ちくわの道具 | SO-101 の現状 | 飛ばすと何が起きるか |
|---|---|---|---|---|
| **0** | **一致を測る道具を先に持つ** | `shape-fidelity.js` | **無い**（[K-04](現在の課題.md#k-04)） | 形を触る作業は、放っておくと小さすぎ（穴）を増やす |
| 1 | 実物の形（STL）を用意する。無いなら図面から起こす | — | 腕・手首のカメラ・上の台は公式の STL（`sim/models/src/`）。カメラ本体とケーブルは無い | 「実物と同じ」の実物の側が無いまま、近似だけ作ることになる |
| 2 | 面（三角形）を面積の重みで刻む。頂点だけで作らない | `sampleTriangles` | 表面に約 3mm おきに点を打つ（`tools/build-models.py`） | 大きい平らな面の内側に穴が空く |
| 3 | 刻んだ点を格子でまとめ、格子ごとに丸め箱を作る | `bodySetFromMesh` | 腕どうしの判定だけしている（`self-collision.js` が `bodySetFromMeshExact` で丸め箱にする）。ほかは点のまま | — |
| 4 | 芯は縮めない。丸め半径は点の間隔 × 1.6 | 同上 | していない | 縮めると角の点が包めず、小さすぎが出る（ちくわで 3.2mm） |
| 5 | 刻みは「大きすぎの上限」から逆算する。個数で決めない | `cellSize` | 決まっていない | 個数を固定すると、大きい物だけ粗くなる |
| **6** | **小さすぎ 0・大きすぎ上限以下を、測って確かめる** | `shape-fidelity` | していない | 条件 12 を破る |
| 7 | 要素が増えたら枝刈りを入れる。**総当たりと一致することを機械で示す** | `parts-selftest` | 爪のまわりの測り直しは `check-refine.js` で力ずくと比べた | 枝刈りの誤りは絵に出ない |
| 8 | **形を持つ場所を全部数えて、新しい形を全部に通す**（下の表） | — | 下の表 | 1 か所忘れると、そこだけ古い形で判定する |
| 9 | **絵に出す**。判定と同じ形を出す | `collision-view.js` | 「当たり判定」のボタン（腕の点・ピースの箱） | 絵と判定がずれても気づけない |
| 10 | **下流の数字を取り直す**（当たりの数・余裕・1 コマの最大） | `condition-audit` | 道具ごとに流し直す（`check-scene.js` など） | 前の形で測った値が残り、直ったように見える |

**STL が無い物の扱い（ちくわ）**：形を手で決めた物は、実物との差を誰も知らない。「一致は測っていない」と書いて使う。「単純な形だから正しい」とは言わない。

### 速さのための枝刈り（答えを変えてはいけない）

外接球による下限で枝刈りするなら、取りこぼさない。十分離れているときは下限をそのまま返してよい（本当の値以下なので安全側）。**枝刈りが答えを変えていないことは、総当たりと突き合わせて確かめる**（[00 の条件 13](00_絶対条件.md)）。

### 必ず判定に入れるもの（ちくわ）

- **机**（y = 0）
- **自分の台**（「取り付ける所は必ず触れるから」と外さない。外すのは根元の部品だけ）
- **腕どうし**（自分との当たり）← SO-101 では 2026-11-17 に入った（`self-collision.js`）
- **持っているピース**（腕と一緒に動く物として）
- **動かない物どうし**（台と盤と置き場のピース）
- **ケーブル**（SO-101 で足した。手首のカメラのケーブルは腕に沿って動く。[08 §4](08_カメラ_配置と配線とプログラム.md#4-ケーブルのつなぎ方)）← 入っていない

### 外してよいもの / いけないもの（ちくわ）

| 種類 | 扱い |
|---|---|
| 触れて当たり前（爪 × つかんでいるピース、隣どうしの部品） | はっきり書いて外す |
| 同じ剛体の中で距離が変わらない（爪の付け根 × 手首のカメラ） | コマごとには見ず、1 回だけ見る。**SO-101 では外していて、1 回も測っていない**（`self-collision.js` の `STATIC` に j5\|cam が無い） |
| 形の近似で見られない | 「見ていない」と書いて、理由を画面に出す |

**手で並べない。** 部品が関節でつながっているかから機械で作る。

**外す前提は、別の点検で数字で支える**（ちくわ 2026-09-26）。外すとは「その組を見ない」ことなので、前提が崩れても赤も緑も出ない。外すのを 1 つ決めたら、その理由の形を測る点検を 1 つ持つ。

| 外すもの | 理由（前提） | 前提を測る点検 |
|---|---|---|
| 隣どうしの部品（base⇄j1 … j5⇄jaw） | 関節のまわりで触れている | 下見の道具 `self-collide.js` が、隣も 2mm より深いものを数える。判定（`self-collision.js`）の中には無い |
| j5 ⇄ cam（手首のカメラは爪の付け根と同じ剛体） | ねじで固定。距離が姿勢で変わらない | `self-collision.js` は外すだけで、測っていない。`self-collide.js` は隣どうしとして扱う（2mm より深ければ数える） |
| jaw ⇄ cam、j4 ⇄ cam | 1 つの関節（爪・手首の回転）だけで距離が決まる | `self-collision.js` の `staticCheck` が、その関節の可動域の全体を 1° おきに 1 回だけ見る（ちくわの checkRigid の考え）。`check-scene.js` が流す（2026-11-17 の 12:25 の版では入っていた。いつからかは確かめていない。画面の判定の表には出ない）。12:30 の出力は jaw\|cam −0.4mm（爪 −10°）、j4\|cam −0.8mm（手首の回転 −35°）で、どちらも要確認として数える（箱は両側で最大 3.6mm 太るので、当たるかはこの道具では分けられない。1° の間は見ていない）。ちくわの「0 未満で ng」から外れるのは、この太りのため |
| 爪 × つかんでいるピース | つかむのだから触れる | 掴んだ瞬間のずれ（`check-scene.js`・`check-layout.js`）。深さは見ていない |
| 置いたピース × 盤 | 置くのだから触れる | 無い |

### 意図して近づく区間（ちくわ）

つかむ・離すでは、爪がピースに近づく。経由点に印を付けて外し、**印は補間で足したコマにも引き継ぐ**（引き継がないと、そこだけ当たりと出る）。

### つかむ・離す瞬間の状態は続ける（ちくわ）

- 置いたピースの位置と向きは「爪から離した瞬間」のものをそのまま持つ。決まった向きで置き直すと、ずれが黙って消える。
- 絵と判定を同じ関数から作ると食い違いは消えるが、同じ間違いを両方が持つ。実物との一致は別に測る。

## 3. コマの間（ちくわ）

**当たり判定はコマ（離れた姿勢）でしか見ない。コマとコマの間はすり抜ける。**

- 割る決まり：**関節角ではなく、判定の形の点が実際に動いた量で割る。** ちくわは 10mm（刻む誤差 5mm）。`sim/` は 4mm（S-4。速い所で腕の点が 1 コマ最大 43mm 動いていたので、辺 14mm のピースや台の足をすり抜けうると分かった）。
- **判定の設定はこれで全部、を揃える**（[00 の条件 9](00_絶対条件.md)）。揃えないと、同じ姿勢で結論が違う。

| 揃えるもの | `sim/` の値 |
|---|---|
| コマの間を割る | 判定の点が 4mm 動くごと（`SUB_STEP`）／腕どうしの判定（`self-collision.js` の `motionCheck`）は、組ごとに「隙間の平均 − 縮みうる量の上限」で下限を出し、負なら半分に割る（深さ 6 まで。残った負の下限は NG）／下見の `self-collide.js` は割らず、既定で 2 コマおき ← 揃っていない |
| 形の点の間隔 | 約 3mm（`build-models.py`）／腕どうしの判定は丸め箱（4mm、近い組は 1.5mm の格子）← 形の作り方が違う |
| 台の距離を測る深さ | 15mm（`scene-data.js`）。15mm より深い点も、中なら負で出る（2026-11-17 の [K-03](現在の課題.md#k-03)）／腕どうしの判定は丸め箱どうしの距離で、深さの上限は無い／下見の `self-collide.js` は 10mm と決めているが、K-03 のあとは深い点も負で返る（流し直していない） |
| 爪のまわりの測り直し | 画面はあり。`self-collide.js`・`stand-path.js` はなし（`NO_REFINE`）← 揃っていない |
| 外すもの | 上の表 |

## 4. 見えるか（撮れるか）

**当たりなしでも「写らない」ことがある。** 当たり判定とは別の判定として常に置く。

- 上のカメラ：写す姿勢で、ピースと盤のマスの上の面の 5 点（真ん中と 4 つの角）へ線を引き、腕と台の点が線から 2.5mm 以内なら隠れると数える（`overhead-occlusion.js`）。
- 手首のカメラ：つかむ場所の上で、ピースへの線が爪の三角形にさえぎられる本数（`camera-budget.js`）。
- ちくわの「重心ではなく四隅で見る」：絵に入るかは、角が全部入るかで見る。
- **写す姿勢は、見えるかと当たりの両方を通す。** 2026-11-17 の「写す姿勢」は見えるかだけで選ばれ、腕どうしでめり込んでいた（[00 の条件 1](00_絶対条件.md#条件-1-当たり判定はほかのすべてより先に付ける)）。

## 5. 解き方を決まった答えにする（ちくわ）

数で解く以上、答えは初めの値で変わる。決まった答えにするのは自分で守る。

| 手 | 中身 | `sim/` |
|---|---|---|
| 前の答えから始める | 前の設計の答えを候補に入れる | 確かめていない |
| 角度の巻き方を揃える | 前のコマにいちばん近い同じ角度へ寄せる（可動域は守る） | 確かめていない |
| 乱数の種を決める | でたらめに置く試しはすべて種を決める | `check-layout.js --seed` |
| 入力の印を出す | 同じ入力かを機械で見分けられる | していない |

**経路まで見て答えを選ぶ**：経由点ごとの近さだけで選ぶと、終わりは良いが途中がひどい答えをつかむ。

## 6. 出力に必ず含めるもの（ちくわ）

| 項目 | 理由 |
|---|---|
| **当たっている相手** | 無いと因果を取り違える（ちくわで、当たっていない支柱を動かして「直った」と言った） |
| **仮の値の一覧** | 仮の値から出た ng を、本当の不具合と混ぜないため |
| **この判定の限界** | 書いていないことを Claude は勝手に補う |
| 入力の印・乱数の種 | やり直せるか確かめる |
| 件数と内訳 | 「いちばん悪い 1 点」だけでは、良くなったか分からない |

`sim/` の限界の書き方の例：

```
コマの間  「判定の点が 4mm 動くごとに割る。掃いた体積での保証はない」
形        「STL の表面の点（約 3mm おき）。点の間は見ていない」
腕どうし  「丸め箱（1.5mm の格子）どうし。j5⇄cam は測っていない。jaw⇄cam・j4⇄cam は可動域を 1° おきに見るだけ（1° の間は見ていない）」
見えるか  「上の面の 5 点。面の全体は見ていない。ケーブルは形が無い」
```
