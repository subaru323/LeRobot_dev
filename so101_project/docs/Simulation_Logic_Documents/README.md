## このフォルダは何か

**`sim/` が従う決まりと、まだ解けていない課題を置く。** ここに書いてあることが正。コードとここが食い違ったら、コードを疑う。

| 置き場所 | 中身 |

| `docs/Simulation_Logic_Documents/`（ここ） | 決まった仕様だけ。実装はこれに従う。経緯は書かない |

| [sim/README.md](../../sim/README.md) | 道具の使い方 |

### この仕組みが目指すもの（ちくわと同じ）

このシミュレータは、人が画面で回すのではなく、**Claude が回す前提**で作る。だから、

- 入力はテキスト（JSON・URL の条件）で書ける。1 回の試しは秒〜分で終わる。
- 出力は、数字（構造のあるデータ）と絵の両方。
- **間違いは機械が捕まえる。** 「気をつける」で運用しない。Claude は間違えるので、見ていない所が「0 件」と出ないように、見ていないことは見ていないと出す（[03 §6](03_判定としきい値.md#6-出力に必ず含めるものちくわ)）。

### 3 つの原則（ちくわと同じ）

1. **実装はここに従う。** 食い違ったらコードが間違い。
2. **ここに無いものは決まっていない。** 決まっていないことを勝手に決めて実装しない。仮の値を使うなら `【仮】` と書き、判定の結果にも出す。
3. **経緯はここに書かない。** 「なぜそうしたか」は `docs/plan/` と `docs/knowledge/` へ。ここは結論だけを短く保つ。

## 書き方の約束（ちくわと同じ）

- 1 文書 1 主題。長くしない。参照先を書いて済むならそうする。
- 数字には出どころを付ける（URDF・STL・道具の出力・利用者・【仮】）。数字の持ち主は道具の出力で、文書は写すだけ。
- 変えたら、日付と理由を 1 行残す（各文書の末尾の「変更履歴」）。
- 「決まっていない」を空欄にしない。決まっていないと書く。空欄は「決まっている」と読まれる。
