# 02 座標と単位

作った日：2026-11-17。ちくわの `02_座標と単位.md` の形を移し、中身を `sim/` の決め方（`sim/so101.js` の冒頭の「座標」）に合わせた。**`sim/` の全部の画面と道具で共通。例外を作らない。**

## 1. 単位

| 量 | 単位 | 例外 |
|---|---|---|
| 長さ | **メートル**（画面・判定・逆運動学の中） | 置き場のファイル（`sim/layouts/*.json`）・道具の出力・文書は mm。読み書きの口で直す |
| 角度 | **度** | three.js に渡す所だけラジアン。`Math.PI` を度の所に渡すと 3.14° しか回らない（ちくわで踏んだ） |
| 時間 | 秒 | |
| 絵 | 画素。左上が (0, 0)、右へ u、下へ v | |

## 2. 軸の向き

```
画面（three.js）: Y が上、机の上の面が y = 0（パズルの画面）
              X が腕の前、Z が腕の右（上から見て、X → Z が時計回り）
URDF          : Z が上。画面 = (x_urdf, z_urdf, −y_urdf)
置き場の yaw  : 上から見て X → Z の向きに測る（度）
腕の原点      : base_link の原点。台ありでは机から 9.6mm 上（so101.js の OVERHEAD.robotOriginMm）
```

- 関節の角度は **URDF の角度**（`so101_new_calib.urdf`）。実機の LeRobot の角度（`shoulder_pan.pos` など）との符号・0 の位置の対応は確かめていない（[計画書_完成形まで](../plan/計画書_完成形まで.md) の V-4・U-2）。**画面と道具の角度を、そのまま実機に送らない。**

## 3. 判定と絵は、同じ変換で置く（ちくわと同じ）

当たり判定の置き場所と、画面の部品の置き場所は、同じ式で作る。別々に書くと、ずれたときにどちらが正しいか分からなくなる。

```
frames[i] = 関節 i を回した後の座標系（KIN.fk）
全関節 0 の座標の点 v → frames[i].p + frames[i].R ·(v − frames[i].o)
```

- 寸法は `sim/so101.js` だけ、形は STL だけに持つ。絵も逆運動学も当たり判定もカメラの絵の正解も、そこから作る。
- **ただし同じ値から作ると、同じ間違いを両方が持つ**（ちくわ 03 §2）。実物との一致は別に測る（カメラの置き方は実物で、[計画書_完成形まで](../plan/計画書_完成形まで.md) の K5）。

## 4. 名前の付け方

判定の結果が「何が何に当たったか」とそのまま読めるようにする。

| 名前 | 中身 |
|---|---|
| `base`・`j1`〜`j5`・`jaw` | 腕の部品のまとまり（`so101.js` の `LINK_GROUP`。j1 肩の回転、j2 上腕、j3 前腕、j4 手首の曲げ、j5 手首の回転と固定の爪、jaw 動く爪） |
| `cam` | 手首のカメラと台（j5 と一緒に動く。`CAMERA_GROUP`） |
| `stand_*` | 上のカメラの台（柱・板） |
| `piece_*`・`board` | ピース・盤 |
| `table` | 机 |

- 除外の一覧を名前の一部の一致で書かない。関節でつながっているか（部品の並び）から機械で作る（ちくわ 02 §4）。

## 5. 仮の値の扱い（ちくわと同じ）

寸法や性能が分からないときは、目安で仮に決めてよい。**ただし必ず：**

1. コードの注に `【仮】` と書く。
2. 判定の結果（画面の「判定」の欄・道具の出力）に出す。
3. 文書でも `【仮】` と書く。

仮の値が原因で ng になったときは、数字を勝手に変えて「問題なし」と言わない。**「◯◯ mm 以下なら成り立つ」という要る仕様の形にして返す。**
