# docs の置き場所

core v0.3.0 の雛形から作った。core の文書に出てくる既定の置き場所と、このプロジェクトの置き場所が違うところは、下の「読み替え」に書く。

| 置き場所 | 中身 | 決まり |
|---|---|---|
| `docs/core/` | ルールの種（core v0.3.0）。方針、最初のルール、手引き、道具 | **読むだけ。書き換えない。** 直したいところは `docs/core_proposals/` へ |
| `docs/core_proposals/` | core への修正案（1件1ファイル） | `docs/core/修正案の出し方.md` の形で書く。マスターに届けるためのもの |
| `docs/rules/` | このプロジェクトで足したルール（[RULES.md](rules/RULES.md)）と、[決まり ⇄ 検査 ⇄ 時機の一覧](rules/検査の一覧.md)。文書の書き方と置き方は [ドキュメンテーションのやり方](rules/ドキュメンテーションのやり方.md)・[ファイル整理のやり方](rules/ファイル整理のやり方.md)（2026-11-17、ちくわ排除機構から移した） | `docs/core/方針.md` に反しない。ルールごとに根拠の強さ、最後に見直した日を書く |
| `docs/Simulation_Logic_Documents/` | `sim/` が従う決まり（[README](Simulation_Logic_Documents/README.md)：00 絶対条件・02 座標と単位・03 判定としきい値・08 カメラの配置と配線とプログラム・09 画像だけで動かすシミュレーション）と、[現在の課題](Simulation_Logic_Documents/現在の課題.md)（K-nn）。2026-11-17、ちくわ排除機構の同じ名前のフォルダを移した | 決まった結論だけ。経緯は `docs/plan/` と `docs/knowledge/`。コードと食い違ったらコードを疑う |
| `docs/`（直下の `*手順書.md`） | 作業の手順書（下の表） | core の既定では `docs/guides/`。このプロジェクトでは、記録（`docs/records/checks/`）が名前で指しているので、直下に置いたまま動かさない |

| `docs/records/` | R-001 の台帳（[R001_LOG.md](records/R001_LOG.md)）、点検の入出力（`checks/`）、道具の出力の控え、書き直す前の控え（`backup/`） | 点検のたびに1件1行 |

## 持ち主

同じ事実を2か所に書かない。上の表の「中身」が、その事実の正本。順位の先頭は、利用者の最新の発言と記録された利用者の決定（日付の新しい方）。どう作業するかは、その次に `docs/core/方針.md` → `docs/rules/` → そのほかの文書。

何を作るか（仕様・要件・課題）の順位：記録された利用者の決定（[計画書](plan/計画書_テレオペ以降.md) の「決めたこと」）→ 計画書 → 手順書。軸は中身で分け、仕様の文書に書いた作業の仕方も core に従う（`docs/core/方針.md` 12）。core が古いと思ったら、直さずに `docs/core_proposals/` へ。

| 事実 | 正本 |
|---|---|
| この机の COM 番号、USB のシリアル番号 | [組み立て手順書](組み立て手順書.md) STEP 2 の表（`tools/so101_common.py` の先頭は、それに合わせた写し） |
| 組み立ての進み具合 | [組み立て手順書](組み立て手順書.md) の各 STEP のチェック欄 |
| 決めたこと、段階、止め方 | [計画書_テレオペ以降](plan/計画書_テレオペ以降.md) |
| 準備 A〜E の状況 | [準備手順書](準備手順書.md) の「いまの状況」 |
