# フォロワーの跳びと過負荷（2026-10-28）

## いまの結論

- LeRobot の `SOFollower.connect()` は、フォロワーに力を入れるとき、モーターの目標位置（Goal_Position）を「いまの位置」に合わせない。モーターは、残っている目標位置へ向かう。加速度は最大（254）に設定され、速度の上限も付かない。**確かめた**（ソース：`so_follower.py` の `configure()`、`motors_bus.py` の `torque_disabled()`、`feetech.py` の `configure_motors()`）。
- キャリブレーションをやり直した後は、残っている目標位置が別の角度を指しうる。2026-10-28 に、目標位置を合わせずに動かすと腕が速く動き、肩上げ（ID 2）と肘・手首曲げ（ID 3・4）が過負荷エラー（Overload error）で止まった。**確かめた**（実機）。
- 過負荷のモーターは、力を抜く指示を受け付けない。LeRobot の `disconnect()` は、ID の順に力を抜いていき、途中のモーターで失敗するとそこで止まる。そのため、その先のモーター（ID 3〜6）は力が入ったまま残った。**確かめた**（実機のエラーと、F4〜F6 が手で動かなかったこと）。
- 5V を抜いて挿し直すと、過負荷エラーと力の両方が消えた。**確かめた**（実機。挿し直した後、全部のモーターがエラー無しで返事をした）。
- STS3215 は、力が抜けている状態で Goal_Position を書くと、一部のモーターで自分から力が入った（6 個中 3 個で Torque_Enable が 1 になった。目標 = いまの位置なので動きはしなかった）。その後に力を抜いても、目標位置と速度の上限は残った。**確かめた**（実機、1 回）。なぜ 3 個だけだったかは分からない。
- 目標位置を「いまの位置」に合わせ、速度の上限を書いてから `connect()` を呼ぶと、目標位置と速度の上限は残り、6 関節とも 0 ステップだった。**確かめた**（実機、フォロワー単体、休止姿勢、1 回）。この手順を `tools\prime_goal.py` にした（[ルール P-001](../rules/RULES.md)）。

## 何が起きたか（時刻の順）

1. キャリブレーション（3 回目で成功）の後、フォロワーを ±10° ずつ動かすテストを、`SOFollower.connect()` で始めた。目標位置は合わせていなかった。
2. 手首回転は動いたが、手首曲げの読みが、指示（-97.8°）と大きく違う 40.4° になった。テストを止めた。
3. 止めるときの `disconnect()` で、ID 2 が `Overload error` を返し、力を抜けなかった。
4. 利用者から「動かすの速すぎるだろ」。F4〜F6 が手で動かない、とも。
5. ID を調べると、ID 3・4 が過負荷エラーを返していた。5V を挿し直してもらうと消えた。
6. 目標位置を合わせてから力を入れ、速度（約 13°/秒）・加速度・力に上限を付けたテスト（`tools\safe_wiggle.py`）では、6 関節とも ±10° を往復でき、負荷で止まることも無かった。

## まだ分からないこと

- 手首曲げの 40.4° の読みが、実際に腕が大きく動いたのか、読みの誤りか。仮説：目標位置へ速く向かった途中を読んだ。
- 本家のコマンド（`lerobot-teleoperate`、`lerobot-record`、`lerobot-rollout`）を `prime_goal.py` の後に通したとき、跳ばないか（[計画書](../plan/計画書_テレオペ以降.md) の前提 1〜1c）。
