# r001_check が使えないときの代わり

- core の版: 0.3.0
- どのファイルの、どこか: `rules/RULES.md` の R-001（点検の手段）、`tools/r001_check.py`
- 何を: 足す。`claude -p` が使えない環境で、`r001_check.py` が分かるエラーで止まり、代わりの手段（読むだけのサブエージェント）と、そのとき台帳に書く欄を示すようにする。案の文：「`claude -p` が失敗したら（組織の設定で使えない、ログインしていない、など）、`r001_check.py` は出力に失敗の理由を書いて 0 以外で終わる。そのときは、プロジェクトの仕組み（読むだけのサブエージェント）で代え、台帳に『r001_check が失敗した理由』と『代えたことで守れなかったもの』を書く。」
- なぜ: 2026-10-28、計画書の点検で `r001_check.py` を流したところ、`claude -p` が「Your organization has disabled Claude subscription access for Claude Code」を返した。`r001_check.py` は終了コード 0 で終わり、出力のファイル（review.md）には費用 0 ドルの JSON とその文だけが書かれた。終了コードだけを見ると、点検が通ったように見える。出力を開いて初めて失敗と分かった。
- このプロジェクトでどうしたか: 読むだけのサブエージェント（Claude Code の Explore）で代えた。台帳 C3 に、代えたこと、点検役の文脈に入っていたもの（利用者のメールアドレス、`MAIN_PG/lerobot/CLAUDE.md`）、依頼文を書き手が書いたことを書いた。[検査の一覧](../rules/検査の一覧.md) に「このパソコンでは動かない」と書いた。
