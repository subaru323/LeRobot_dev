# ファイル整理のやり方

作った日：2026-11-17。利用者の指示「ドキュメント管理もちくわ排除機構のを参考にちゃんとやってや」（2026-11-17）から、ちくわ排除機構の `docs/admin/rule/ファイル整理のやり方.md`（読むだけ）を、このプロジェクトに読み替えて移した。

**このフォルダは git の管理の外 = 消したら戻せない。** 整理は「消す」ではなく「置き場所を分けて、読む量を減らす」こと。

## 1. 大原則（4 つ）

| # | 決まり | なぜ（ちくわの出どころ） |
|---|---|---|
| 1 | **消さない。移す。** 移した元にはリンクか 1 行を残す。迷ったら動かさない | 情報が落ちると、課題を立てる根拠が消える（ちくわ 0-D） |
| 2 | **道具が読んでいるファイルは動かさない。** 動かす前に、名前で `sim/`・`tools/`・`docs/records/` を探す（Grep）。当たったら動かさず、一覧で整理する | 動かすと、道具と記録が黙って壊れる（ちくわ F-289）。`docs/` 直下の手順書は記録が名前で指しているので動かさない（[docs/README.md](../README.md)） |
| 3 | **動かした後は検査を回す**：`python tools/check_links.py`（壊れ 0） | 壊れたリンクは誰も気づかない（ちくわ F-75） |
| 4 | **直下を散らかさない。** プロジェクトの直下に置くのは、いまある物（`CLAUDE.md`・`STATUS.md`・`docs/`・`sim/`・`tools/`・`MAIN_PG/`・`outputs/`・`_backup/` など）だけ。新しい物は決まった置き場所へ | ちくわ 0-Q |

## 2. 置き場所の早見表

| こういうもの | 置き場所 |
|---|---|
| シミュレーションの確認の絵・道具の出力の控え | `sim/_check/<日付_件名>/`（文書からパスで指す）。作り直せる出力は `sim/out/` |
| 実機の道具の出力 | `outputs/<道具の名前>/` |
| 書き換え前の控え | `docs/records/backup/`（文書）・`_backup/`（文書以外） |
| 利用者から渡された資料 | `docs/与件/`（書き換えない） |
| 点検の入出力 | `docs/records/checks/` |
| 役目を終えた計画 | `docs/records/` へ移し、元の一覧に「移した（日付・理由）」 |
| シミュレーションの決まり | `docs/Simulation_Logic_Documents/` |

**確認のために値を落とした写しを、本物の隣に放置しない**（本物と取り違えた。ちくわ F-74）。

## 3. 移すときの手順

| # | やること |
|---|---|
| 1 | **移してよいかを決める**：まだ直っていないことを含まないか / また起きうる失敗ではないか / ほかの文書が元として指していないか。1 つでも当たれば移さない |
| 2 | そこにしか無い「直っていないこと」があれば、先に [現在の課題](../Simulation_Logic_Documents/現在の課題.md) か計画書へ吸い上げる |
| 3 | 道具が読んでいないかを名前で探す（§1 の 2） |
| 4 | 移す。移した先の一覧に 1 行、元の場所には「◯◯へ移した（日付・理由）」 |
| 5 | リンクを張り替えて `python tools/check_links.py` |

**大きな整理（分ける・10 ファイル以上を動かす）は、先に `docs/records/backup/整理の控え_<日付>/` へ丸ごと控えを取る。**

## 4. 文書を分けるとき（索引を必ず作る）

ちくわの利用者の指示（2026-09-25）「ドキュメント分割したら、インデックス用の統括ドキュメントも作ってほしい」をこちらでも守る。

1. **原文を移す**（言い換え・要約で畳まない）。分ける前に控えを取る。
2. 分けた先の名前に「`_分冊N`」「`_これまでの経過`」のどれかを入れる。
3. 分けた文書の索引（どの見出しがどの分冊にあるか）を 1 枚作り、[docs/README.md](../README.md) に 1 行。
4. `python tools/check_links.py`。

## 5. やらないこと

- 削除。とくに `sim/_check/` と `docs/records/` を「古いから」と消さない（文書が証拠として指している）。
- `docs/core/` を書き換える（読むだけ。直したいときは `docs/core_proposals/`）。
- `MAIN_PG/lerobot` の本体のソースを書き換える。
