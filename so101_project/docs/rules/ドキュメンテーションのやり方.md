# ドキュメンテーションのやり方

作った日：2026-11-17。利用者の指示「ドキュメント管理もちくわ排除機構のを参考にちゃんとやってや」（2026-11-17）から、ちくわ排除機構の `docs/admin/rule/ドキュメンテーションのやり方.md`（作業フォルダの外。読むだけ）を、このプロジェクトの置き場所に読み替えて移した。

**新しい決まりは作っていない。** ちくわで踏んだ失敗から残った決まりのうち、毎日効くものを、このプロジェクトの置き場所に合わせて書いた。上の順位は `docs/core/方針.md`（とくに 4 言える範囲で書く・6 入口の文書を逐一直す）。ここはそれに反しない。

**いつ書くか：その場で、逐一。** 失敗した・指摘された・測って状態が変わった・方針が変わった、そのたびに書く。会話の終わりにまとめて書かない（いつ切れるか分からない。`CLAUDE.md` の「次の一手や決まったことが変わったら、その場で STATUS.md を直す」と同じ）。

## 1. 何をどこに書くか

表の持ち主は [docs/README.md](../README.md)。ここには、毎日出てくるものだけ写す。

| 書きたいこと | 書く先 |
|---|---|
| 次に何をするか（状態が変わるたびに） | [STATUS.md](../../STATUS.md) の「次の一手」 |
| 測って状態が変わった | その段の計画書の行（例：[計画書_完成形まで](../plan/計画書_完成形まで.md) の S-nn）に、道具の名前と出力の場所 |
| 失敗した / 利用者に指摘された | [失敗と解決策](../knowledge/失敗と解決策.md) の末尾に F-nn |
| シミュレーションでまだ直っていないこと | [現在の課題](../Simulation_Logic_Documents/現在の課題.md) に K-nn |
| シミュレーションの決まり（何を測り、いくつで ng か） | [Simulation_Logic_Documents/](../Simulation_Logic_Documents/README.md) の 00〜09 |
| 次の仕事でも効く作り方・調べたこと | [docs/knowledge/](../knowledge/) に 1 主題 1 ファイル |
| 点検（R-001）で挙がった件 | [R001_LOG.md](../records/R001_LOG.md) に 1 件 1 行 |

## 2. 必ず守ること（8 つ）

| # | 決まり | なぜ（ちくわの出どころ） |
|---|---|---|
| 1 | **経緯を先に書く。** 失敗は F-nn を先に書き、そこから K-nn（直っていないこと）と決まり（次も効くこと）を取り出す | 上から書くと、参照だけ残って中身が無くなった（ちくわ F-75） |
| 2 | **取り出しは 2 方向。** F-nn を書いたら「次の仕事でも効くか」を 1 行考え、効くなら `docs/knowledge/` か決まりの文書へ | 作り方の知識だけ育たなかった（ちくわ F-93） |
| 3 | **同じ事実の持ち主は 1 つ。** ほかはリンクにする。数字の持ち主は道具の出力で、文書は写すだけ | 3 か所に書いてずれた（ちくわ F-222）。`docs/core/方針.md` の「状態の数字は道具の出力」 |
| 4 | **測って書く。** 「作った」ではなく「動くのを確かめた」。決まっていないことは空欄にせず「決まっていない」「【仮】」と書く | 自分で付けた「済み」が、測ると動いていなかった（ちくわ 00 条件 8） |
| 5 | **数字には「何を見た上での数字か」を同じ行に**（種・置き場・何コマおき・どの判定の設定か） | 見ていない範囲の当たりが「0 件」になった（ちくわ 0-K） |
| 6 | **消さない書き方で直す。** 大きな書き換えは先に控え（`docs/records/backup/`）。撤回・訂正は、元の文の場所で打ち消し線（`~~…~~`）を引き、すぐ後ろに正しい文と日付を書く（後ろに足すだけにしない） | ちくわで CLAUDE.md を 0 バイトにした（F-91）。`docs/core/方針.md` 4 |
| 7 | **書いた後にリンクと言葉を確かめる**：`python tools/check_links.py` と `python docs/core/tools/doc_lint.py <書いた文書>` | 参照先が無かった（ちくわ F-75）。[検査の一覧](検査の一覧.md) |
| 8 | **点検で挙がった件は台帳に 1 件 1 行**（種類 = 事実 / 考え・自分で確かめたか・対応 = 受け入れ / 一部 / 見送りと理由・後で誤りと分かったか） | 点検の効き目を後で数えるため（ちくわ 2026-10-14・core の R-001） |

F-nn と K-nn の番号は、それぞれの文書の最大 + 1。

## 3. 新しい文書を作ったとき

1. [docs/README.md](../README.md) の表に 1 行（新しいフォルダなら、フォルダの行）。
2. 新しいフォルダなら README.md を 1 枚（役目・中身・出どころ）。
3. 計画なら `docs/core/guides/計画書の書き方.md` の欄に合わせる。
4. `python tools/check_links.py`。

## 4. 利用者への報告は別

文書は Claude と道具が読むので、記号（K-nn・F-nn・S-nn）を使ってよい。

- **利用者への報告**では、自分で作った記号や言葉を使わず、「何を調べて・何が分かって・だから何をするか」を先に書く（ちくわ 0-Y）。
- **確からしさの札**：結論や数字に「確かめた（道具の出力・実物で見た）」か「見込み（読んだだけ・状況から）」かを同じ行に書く。
- **利用者に決めてほしいことがある報告**は、それを先頭（何の話かの 2〜3 行の直後）に書く。
