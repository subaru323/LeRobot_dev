# 決まり ⇄ 検査 ⇄ 時機の一覧

`docs/core/方針.md` 7。決まりを作ったら、同じ回にここへ1行足す。機械で見られない決まりは、なぜ見られないかを書く（空欄にしない）。**回していない検査は、無いのと同じ。** プロジェクトの決まりは、core の行の後ろに足す。

コマンドは、プロジェクトの直下（`docs` と `tools` があるフォルダ）で実行する。

| 決まり | 検査（コマンド） | 回す時機 | 機械で見られないとき、その理由 |
|---|---|---|---|
| core 方針4: 言える範囲で書く（禁止語）・数字は出力から写す | `python docs/core/tools/doc_lint.py <文書>` | 結果や結論の文書を書いたとき、R-001 の点検の前 | 禁止語の表に無い言い替えと、表の中の数字は見られない（目で見る） |
| core 方針4: いまの結論を冒頭に・撤回は本文で打ち消し線 | なし | — | 文の意味の判断が要る。R-001 の点検で見る |
| core 方針3・R-001: 結論を出す前に点検する | `python docs/core/tools/r001_check.py ...`。**このパソコンでは動かない**（2026-10-28、組織の設定で `claude -p` が使えない）。代わりに読むだけのサブエージェントで点検し、台帳に代えたことを書く | 結論や方向の提案を利用者に出す前、大きな計画を回す前 | 「出す前に回したか」は機械で見ていない。台帳（`docs/records/R001_LOG.md`）に記録が無い結論は、点検していないものとして扱う |
| core 方針6: 入口の文書を逐一直す・日付だけを書き換えない | なし（道具を作るまで） | 新しい会話の最初 | core に道具が無い。STATUS.md の最終更新と、`docs/` のファイルの最終更新を目で比べる |
| core 方針10: 書き換えで化けていないか | `python docs/core/tools/doc_lint.py <書いたファイル>`（制御文字） | 書き換えのスクリプトを当てた後 | md 以外のファイルにもかけられるが、拾うのは制御文字だけ |
