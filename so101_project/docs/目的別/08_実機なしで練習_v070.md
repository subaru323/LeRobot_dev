## 3. CPU で、ちょっとだけ学習する（データは流し読み）

```powershell
& "$v\lerobot-train.exe" --dataset.repo_id=lerobot/pusht --dataset.streaming=true --policy.type=act --steps=20 --batch_size=4 --log_freq=5 --save_freq=20 --policy.device=cpu --policy.push_to_hub=false --output_dir=outputs\v070\train_tiny --job_name=v070_tiny
```

- `--dataset.streaming=true`：データを全部落とさずに、流し読みしながら学習する（本体 0.6.2 にもある。`configs\default.py`）。
- `--save_freq=20`：20 ステップ目に保存する（4 の評価で使う）。

流した結果（2026-11-16、出力先だけ違う同じコマンド）：

- ACT のパラメータは約 5,159 万（ログの `num_learnable_params=51588994`）。データは 206 回分、25,650 フレーム。
- 最初の 1 ステップに 62 秒（流し読みの準備）、その後は 1 ステップ 2.5〜3 秒（バッチ 4）。損失は 5 ステップ目 70.7 → 15 ステップ目 16.8（学習のログ）。
- **20 ステップ目の保存の後、`WinError 1314`（特権を保有していません）で落ちた。** 保存のフォルダ `checkpoints\000020\pretrained_model` は書けていて、4 の評価に使えた。落ちるのは、開発者モードがオフで `checkpoints\last` のシンボリックリンクを作れないため（[Windows で学習の保存が落ちる](../knowledge/Windowsで学習の保存が落ちる.md)）。保存の要らない試しなら `--save_checkpoint=false` で避けられる見込み（足して流してはいない）。

見どころ：

- 上の約 3 秒は、**ACT（約 5,200 万の重み）**の 1 ステップです。同じ速さでも、本家の SmolVLA の例の 2 万ステップは約 17 時間（20,000 × 3 秒）かかります。SmolVLA は重みが約 4.5 億あり（本家の説明による。ここでは数えていない）、1 ステップは ACT より遅いはずなので、17 時間は**少なく見た値**です（測っていない）。しかも上はバッチ 4 で、本番は 8 以上。**本番の学習は GPU で**、が数字で分かります（[データ収集と学習の手順書](../データ収集と学習の手順書.md) 13）。
- 損失が下がっていくのを、ログの `loss:` で見ます。

## 4. シミュレーションで、方策を評価する（PushT）

PushT は、2 次元の画面で T の形の板を押して、目標の形に重ねる課題です。3 で作った方策を CPU で動かし、成功の数と動画を出します（20 ステップしか学習していないので、成功しないのが当たり前。**流れを最後まで通すのが目的**）。

```powershell
& "$v\lerobot-eval.exe" --policy.path=outputs\v070\train_tiny\checkpoints\000020\pretrained_model --env.type=pusht --eval.batch_size=2 --eval.n_episodes=2 --eval.use_async_envs=false --policy.device=cpu --output_dir=outputs\v070\eval_tiny
```

流した結果（2026-11-16、出力先だけ違う同じコマンド）：終わりのコード 0、約 40 秒。出力の `n_success: 0`（2 回中 0 回）、`pc_success_ci95: [0.0, 65.76...]`。`videos\PushT-v0_0\eval_episode_0.mp4`・`eval_episode_1.mp4` ができた（押す様子を見られる）。

Windows で止まった所と回り道（どれも 2026-11-16 に起きた）：

| 止まり方 | 理由 | 回り道 |
|---|---|---|
| `ValueError: cannot find context for 'forkserver'` | v0.7.0 の `sim\local_vector_env.py` が、環境を別のプロセスで動かすときに `forkserver` を使う。Windows には無い | `--eval.use_async_envs=false`（同じファイルのエラー文が勧めている） |
| `HFValidationError ... 'lerobot\diffusion_pusht'` | 本家の案内の例 `--policy.path=lerobot/diffusion_pusht` の `/` が `\` に変わる（[Windows でハブの方策名が通らない](../knowledge/Windowsでハブの方策名が通らない.md)） | `hf download <名前> --local-dir <フォルダ>` で手元に落とし、フォルダを渡す（重みは読めた：「Loading weights from local directory」） |
| `ProcessorMigrationError ... requires migration to processor format` | `lerobot/diffusion_pusht` は古い形式のまま（Hub のファイルに `policy_preprocessor.json` が無い） | 変換の道具 `python -m lerobot.processor.migrate_policy_normalization --pretrained-path <フォルダ>` を流したが、設定の書き出し（`draccus` の `encode_tuple`）で `TypeError` で落ちた。**本家の学習済みの PushT の方策は、このパソコンの v0.7.0 では評価できなかった**。自分で学習した方策（新しい形式）なら通る |

## 5. 本体（0.6.2）と v0.7.0 の違い（このプロジェクトに関係する所）

サブエージェントが両方の `--help` とソースを比べた結果を、要所だけ自分でソースを開いて確かめた（2026-11-16）。

| 項目 | 本体 0.6.2（`53feaef`） | v0.7.0 |
|---|---|---|
| 学習の様子のグラフ | `--wandb.enable=true` | `--wandb.*` は無くなり `--trackio.enable=true` など。**本家の案内の `--wandb.enable=true` を v0.7.0 で使うと止まる** |
| EMA の設定 | `--ema.decay` など | `--ema.type {warmup,constant,power}` |
| 増えたもの | — | `--tf32`、`--robot.type=sim`（シミュレーションを「ロボット」として記録・評価に使う）、`lerobot\sim`、方策の種類 |
| 変わらないもの | `--policy.path`、`--dataset.repo_id`、`--batch_size`、`--steps`、`--output_dir`、`--dataset.single_task`、`--dataset.streaming`、ACT の既定値、`lerobot-dataset-viz`、遠隔推論の設定 | 同じ |
| `lerobot-record` で方策を動かす | できない（`lerobot-rollout` を使う） | 同じ |
| Windows の落とし穴 | 保存のシンボリックリンク・方策の名前の `\`・説明文の文字コード（同じコードがある。流して確かめたのは、名前の件の小さな再現と、説明文の件だけ） | 同じ 3 つ（流して起きた）＋評価の `forkserver` |

### 入れ替えるかの決め方（利用者が決める）

| 入れ替える理由 | 入れ替えない理由 |
|---|---|
| `--robot.type=sim` で、実機の前に記録・評価の流れを試せる（試していない） | 実機の手順（組み立て手順書・データ収集と学習の手順書）を、全部 0.6.2 で確かめてきた。入れ替えると、オプションを確かめ直す |
| 学習の場所（GPU のパソコン）に新しく入れるなら、新しい方が直っている所があるかもしれない | 学習の場所と記録の場所で版がずれると、データや方策が読めない恐れ（確かめていない）。**記録・学習・評価は同じ版にそろえる** |

いまは「実機は 0.6.2 のまま、v0.7.0 は練習だけ」にしています（[README](README.md) の「決めていないこと」）。
