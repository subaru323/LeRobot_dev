## 1. 先に決めること（回す前に書く）

条件と回数は、**結果を見る前に**決めて、下の表に書きます。結果を見てから条件を足したり、悪い回を外したりすると、「たまたま良かった」を見分けられなくなります（[計画書_テレオペ以降](../plan/計画書_テレオペ以降.md) の欄4「測り方の点検」・欄7「結論の言葉の対応表」と同じ考え）。

5 回ずつでは差がかなり大きくないと言えません（`success_interval.py --compare 5` の出力：0/5 と比べて 4/5 以上、1/5 と比べて 5/5 のときだけ差あり。2/5 以上はどう転んでも差を言えない）。

### 1-1. 条件

| 名前（`eval_log.py` に渡す） | 置き方 | 成功の決まり | 入れるか |
|---|---|---|---|
| `seen` | 記録のときの印（5 か所）のどれか | 赤い立方体が箱（ボウル）に入って、腕が止まった | [ ] |
| `unseen` | 印と印の間（記録で一度も置いていない所）。別の色のテープで 4 か所に印を付ける | 同じ | [ ] |
| `blue` | 赤と同じ大きさの**青い**立方体を、`seen` の印に置く | 青い立方体が箱に入った | [ ] |
| `two` | 赤と青を両方、`seen` の印 2 か所に置く | **赤**が箱に入った（青を入れたら失敗。メモに「青」と書く） | [ ] |
| `distractor` | 赤を `seen` の印に、関係ない物（ペンなど）をそばに置く | 赤が箱に入った | [ ] |
| `move_target` | つかんだ後に、箱を 10 cm ずらす | ずらした先の箱に入った | [ ] |

- `move_target` は、**記録のときに箱の位置も変えていた**方策でだけ意味があります。04 の記録は箱をテープで固定する（準備手順書 E-2）ので、04 の方策では失敗するのが当たり前です。06 で箱の位置を変えて記録した方策と比べるときに入れます。
- 置く場所は、`seen` の中でも毎回変えます（`eval_log.py` の `repeat` の番号と、印の番号を対応させる。例：repeat 1 → 印 1）。

### 1-2. 回数で、何が言えるか

先に次を流して、決めた回数で何が見分けられるかを見ます。

```powershell
python tools\success_interval.py 5
python tools\success_interval.py --compare 5
```

- 1 つ目は「5 回中 k 回成功」のときに、成功の割合として**否定できない範囲**（Wilson の区間、信頼度 95 パーセント）です。
- 2 つ目は「5 回ずつの 2 条件」で、片方が k1 回なら、もう片方が何回以上で差があると言えるか（Fisher の正確検定）です。「none」と出る行は、5 回ではどう転んでも差を言えない、という意味です。
- 見たい差が見分けられない回数なら、条件を減らして回数を増やします。

| 決めたこと | 値 |
|---|---|
| 入れる条件 | |
| 条件ごとの回数 | |
| 方策の名前 | |
| 決めた日・決めた人 | |

### 1-3. 結論の言葉（結果の前に決める）

| 結果 | 書く言葉 |
|---|---|
| 2 つの条件（または 2 つの方策）を Fisher の正確検定（両側）で比べて p < 0.05 | 「この回数で、差が見えた」 |
| p ≥ 0.05 | 「この回数では、見分けられなかった」（「同じ」「効かない」とは書かない） |
| `two` で青を入れた回がある | 回数をそのまま書く（「色を見ていない」とは、この試験だけでは言い切らない。形・位置・色のどれで選んだかは分からない） |

- 決めるのは Fisher の検定だけにします（`success_interval.py --compare` と `eval_log.py summary <名前1> <名前2>` が同じ検定）。Wilson の区間は、読むための目安です。区間の重なりで決めると、同じ結果でも答えが変わることがあります（例：0/5 と 4/5 は、区間は重なるが Fisher では p = 0.048）。

## 2. 試す順番を作る

```powershell
python tools\eval_log.py plan act_cube_general --conditions seen unseen blue two --repeats 5 --policy act_cube_pick --seed 1
```

- `docs\records\eval\act_cube_general.csv` ができ、条件が**ばらばらの順番**で並びます（同じ条件が続くと、途中で照明が変わった、片付けに慣れた、などが 1 つの条件にだけ乗るため）。
- 出た順番の一覧を印刷するか、画面に出したままにします。
- 同じ名前でもう一度作ろうとすると止まります（結果を消さないため）。

## 3. 1 回ずつ回す

毎回の手順は、[データ収集と学習の手順書](../データ収集と学習の手順書.md) の 14-3（始める前に）と 14-4（実行）と同じです。違うのは、置き方を `eval_log.py` の順番に合わせることだけです。

1. 別の窓で、記録の道具を立ち上げておきます。
   ```powershell
   python tools\eval_log.py record act_cube_general
   ```
2. 表示された条件のとおりに、立方体を置きます。
3. 14-3 の確認をします（**直前に `prime_goal.py` を流し、`OK` を確かめる。1 回ごと**）。
4. 14-4 の `lerobot-rollout` を流します。`--task` の文は、**記録のときの `--dataset.single_task` と同じ文**にします（04 なら記録の文。違う文にすると、学習で見ていない入力になる）。
5. 腕が戻って力が抜けたら、記録の道具に段階（0〜4）を打ち込みます。成功でなければ、失敗の型（つかみ損ね、落とした、など）を短く書きます。**違う物を箱に入れたとき（`two` で青を入れた、など）は `w`** を打ちます（失敗として数え、失敗の型は「wrong object」になる。4 を打つと成功に数えられてしまう）。
6. 全部終わるか、`Ctrl + C` で止めると、条件ごとのまとめが出ます。止めても、それまでの行は保存されています。続きは同じコマンドで再開できます。

- 段階：0 = つかめなかった、1 = つかんだ、2 = 持ち上げた、3 = 箱の上まで運んだ、4 = 箱に入れた（4 だけが成功）。データ収集と学習の手順書 14-5 の段階と同じです。
- 数え直し用に、別のカメラ（スマホなど）で撮っておきます（14-3 と同じ）。

## 5. 結果からすること

| 見えたこと | 次にすること |
|---|---|
| `unseen` だけ下がる | 記録の置き場所を増やす（5 か所 → 8 か所など）。本家の目安は「置く場所ごとに 10 回」 |
| `blue` でも赤と同じように入る | 立方体を「赤い物」ではなく「形・位置」で見ている可能性。色で選ばせたいなら、記録に青を混ぜて「赤だけ入れる」回を入れる |
| `two` で迷って止まる（動画と同じ） | 1 個ずつの記録しか無いため。2 個置いた記録を足すか、06 の言葉の指示（「赤を入れて」）で区別させる |
| どの条件も段階 1〜2 で止まる | つかみ方の記録が足りない。04 に戻って、つかむ所をゆっくり見せる記録を足す |
