## 動画で起きた困りごとと、このプロジェクトでの扱い

| 動画で起きたこと | このプロジェクトでは |
|---|---|
| macOS で動かず、Windows の上の仮想マシン（Ubuntu）に移った。カメラをつなぐと USB の転送が追いつかず止まり、最後は Ubuntu を別のドライブに入れて切り替えた（デュアルブート） | **Windows で直接動かしている**（組み立て手順書 STEP 1。フォロワーのキャリブレーションと動作テストまで通った）。仮想マシンは使わない。カメラ 2 台が同時に動くかは、03 の `camera_check.py` で先に確かめる |
| 組み立ての途中で全部のケーブルをつないでしまい、後で ID を書くために全部外した | 組み立て手順書 STEP 3 で、**組み立ての前に** 1 個ずつ ID を書く順になっている |
| キットの小さいクランプでは机に留められなかった | 01 で大きいクランプを買う |
| 本家のコマンドでフォロワーが跳ねる心配は、動画では出ていない | このプロジェクトでは実際に跳ねて過負荷で止まった（[フォロワーの跳びと過負荷](../knowledge/フォロワーの跳びと過負荷.md)）。本家のコマンドの前に毎回 `prime_goal.py`（[ルール P-001](../rules/RULES.md)） |
| 学習中に停電して、学習をやり直した | 06 で、途中の学習結果から続ける方法（`--resume=true`）を書く |
| （動画には無い。この手順書を作るときに、このパソコンで起きた） | Windows では、学習の途中保存（シンボリックリンク）と、`--policy.path=<Hub の名前>`（`/` が `\` に変わる）で止まる。前者は開発者モード、後者は先に手元に落とす（[学習の保存](../knowledge/Windowsで学習の保存が落ちる.md)、[方策の名前](../knowledge/Windowsでハブの方策名が通らない.md)）。本体 0.6.2 にも同じコードがある |
| ACT はボウルを途中で動かすと追いつかず、SmolVLA は追いついた（動画の人の観察、試した回数は少ない） | 05・06 で、同じ条件を決まった回数だけ回して比べる。回数が少ないと差を言えないので、`eval_log.py summary` の区間で見る |
