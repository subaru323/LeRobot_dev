# 07 方策を別のパソコン（GPU・Jetson）で動かす

- 作成：2026-11-16
- 目的：学習した方策を、腕をつないだこのパソコン（CPU だけ）ではなく、GPU のあるパソコンで計算させて、フォロワーを動かす。
- 動画の場面（16:23〜16:40）：古い Jetson Nano で、テレオペは動いたが、画面をつながずに方策を動かせなかった。
- 確かめた範囲（2026-11-16）：オプションの名前は、本体（0.6.2、`53feaef`）のソースと本家の案内（`remote_inference.mdx`）で確かめた。**どの案も、一度も流していない。** 本体の環境には、案 B に要る `remote` の部品（`eclipse-zenoh`）がまだ入っていない。

## 0. 3 つの案

| 案 | やり方 | よい所 | 気を付ける所 | おすすめ |
|---|---|---|---|---|
| A 腕を GPU のパソコンにつなぐ | 腕の USB とカメラを、GPU のパソコンに差し替えて、そこで `lerobot-rollout` | 新しい仕組みが要らない。04・06 のコマンドがそのまま使える | GPU のパソコンにも、このプロジェクトの道具（`prime_goal.py`）とキャリブレーションのファイルを入れる。持ち主の机に腕を持っていく | **最初はこれ** |

## 案 A：腕を GPU のパソコンにつなぐ

1. GPU のパソコンに、[準備手順書](../準備手順書.md) A-2 で LeRobot（`53feaef`）を入れてある前提です。足りなければ、モーターとコマンドの部品を足します。
   ```powershell
   uv pip install -e ".[feetech,core_scripts]"
   ```
   SmolVLA を動かすなら `".[feetech,core_scripts,smolvla]"`。
2. このプロジェクトの `tools` フォルダを、GPU のパソコンにコピーします（`prime_goal.py` と `so101_common.py` が要る）。
3. キャリブレーションのファイルをコピーします。
   - このパソコンの `C:\Users\genes\.cache\huggingface\lerobot\calibration\robots\so_follower\follower1.json`
   - → GPU のパソコンの `%USERPROFILE%\.cache\huggingface\lerobot\calibration\robots\so_follower\follower1.json`
   - 場所は本体のソース（`utils\constants.py` の `HF_LEROBOT_CALIBRATION`、`robots\robot.py`）で確かめた。**コピーしないと、`--robot.id=follower1` でつないだときにキャリブレーションをやり直すよう求められます。**
4. 腕の USB とカメラ 2 台を GPU のパソコンに差し、COM 番号とカメラの番号を調べ直します（[組み立て手順書](../組み立て手順書.md) STEP 2、[03](03_撮影台とカメラ.md) の 3〜4）。カメラは撮影台ごと持っていき、**位置を変えない**。
5. `tools\so101_common.py` の先頭の `FOLLOWER_PORT` を、そのパソコンの番号に書き換えます。
6. あとは [データ収集と学習の手順書](../データ収集と学習の手順書.md) 14、または [06](06_SmolVLA_言葉で指示.md) の 5 と同じです（毎回 `prime_goal.py`）。

## 案 B：方策だけ GPU のパソコンで（遠隔推論）

本家の 0.6.2 では、前の版の「非同期推論」（`lerobot.async_inference`）は無くなり、`lerobot-policy-server` と `lerobot-rollout --inference.type=remote` に置き換わりました（`remote_inference.mdx`）。古い記事のコマンド（`--server_address` など）は使えません。

### B-1. 両方のパソコンに入れる

```powershell
uv pip install -e ".[remote]"
```

- `remote` の中身は `eclipse-zenoh` と `msgpack`（本体の `pyproject.toml`）。
- GPU のパソコンには、方策の分（SmolVLA なら `smolvla`）も入れます。
- このパソコン（腕の側）には、モーターとコマンドの部品（`feetech,core_scripts`）が入っています。

### B-2. GPU のパソコン：設定ファイルを直して、サーバーを立てる

1. このプロジェクトの `tools\remote\server_so101_front_wrist.yaml` を、GPU のパソコンにコピーします（本家の例 `examples/remote_inference/server.yaml` に、手首のカメラを足したもの）。
2. 次の 2 か所を書き換えます。
   - `model.repo_or_path`：学習した方策（例：`<HFユーザー名>/act_cube_pick`）
   - `zenoh.listen_endpoints`：GPU のパソコンの LAN の IP アドレス（PowerShell で `ipconfig` の「IPv4 アドレス」）
3. Windows のファイアウォールで、TCP の 7447 番を、**家や学校の LAN（プライベート ネットワーク）だけ**に開けます（Windows が初回に許可を聞いてきたら「プライベート」だけに印）。
4. サーバーを立てます。
   ```powershell
   lerobot-policy-server --config_path=server_so101_front_wrist.yaml
   ```
   `Policy server ready: deployment=so101_cube ...` と出たら準備完了（本家の案内）。設定が方策と合わないと、ここで止まって理由が出ます。

- **この設定ファイルは ACT（[04](04_立方体をボウルへ_ACT.md)）用です。** カメラの名前を `front`・`wrist` のまま学習した方策を前提にしています。
- SmolVLA（[06](06_SmolVLA_言葉で指示.md)）は、学習のときに `--rename_map` でカメラの名前を `camera1`・`camera2` に替えています。サーバーに渡すときの名前は、方策のフォルダの `config.json` の `input_features` に書かれた名前に合わせ、言葉の指示を使うので `language.enabled` も見直します。腕の側で名前を替える方法（rollout に `--rename_map` を付けて通るか）と、サーバーがどの名前を受け付けるかは、**まだ確かめていません**（2026-11-16）。案 B で SmolVLA を動かすのは、案 A で動いた後にします。

- 本家の案内：IP を指定して待ち受けても、相手を認証するわけではない。信用できる LAN の外では、証明書付きの中継（router）を使う。**学校や会社の共有の Wi-Fi では使わない**。

### B-3. このパソコン（腕の側）：方策の代わりにサーバーへつなぐ

```powershell
python tools\prime_goal.py <フォロワーのポート>
lerobot-rollout --inference.type=remote --inference.endpoint=tcp/<GPUのパソコンのIP>:7447 --inference.deployment=so101_cube --inference.mode=chunk --inference.chunk_merge=aligned --inference.semantics=so101-degrees-gripper-percent-v1 --robot.type=so101_follower --robot.port=<フォロワーのポート> --robot.id=follower1 --robot.max_relative_target=5 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}}" --fps=30 --task="Put the red cube in the box" --interactive=true
```

- `--policy.path` は**付けない**（付けると本体が止める。`rollout\configs.py`）。
- `--inference.deployment` と `--inference.semantics` は、設定ファイルの `deployment` と `semantics` と同じ文字にします。
- `--interactive=true` のときは、つながった後に `/start` と打つと動き始め、`/stop` で終わります（本家の案内）。
- 画像の転送が重いときは、`--inference.encoding=jpeg --inference.jpeg_quality=90` を足します（本家の案内）。

### B-4. 止まり方（先に読む）

本家の案内の「待つとき・止まるとき」の要点です。

| ときに | 腕は |
|---|---|
| 最初の動きが届くまで | その場で待つ |
| 届いた動きを使い切った | 最後の目標を保って、少し待つ。新しい画像からの動きが来れば再開 |
| 時間切れ・古い動き・壊れた返事 | 方策の動きをやめて、決めた止め方に従う |
| `/stop` や `Ctrl + C` | 方策の動きをやめ、つないだときの姿勢へ戻る設定なら戻る（[データ収集と学習の手順書](../データ収集と学習の手順書.md) 14-1 と同じ） |
| サーバーや LAN が切れた | **自動では戻らない。** 手元の動きを使い切った後、待って止まる。続けるには rollout を立て直す |

- 待っている間も、力は抜けません（本家の案内「torque を切らない」）。**非常のときは、腕を手で支えてから 5V を抜く**（14-1 と同じ）。
