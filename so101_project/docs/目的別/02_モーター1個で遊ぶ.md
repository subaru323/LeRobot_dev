# 02 モーター（STS3215）を 1 個で動かして、仕組みを知る

- 作成：2026-11-16
- 目的：SO-101 の関節に使っている STS3215 を、腕から離して 1〜2 個で動かし、位置・速度・加速度・負荷・2 個での親子（リーダーとフォロワーの縮小版）を手で確かめる。
- 動画の場面（20:39〜24:11）：モーターの付属品、デイジーチェーン、同じ名前でギア比が違う型、基板と USB、Python で 15 分で動いた、位置と速度のモード、速度と加速度を変える、往復（Arduino の Sweep と同じ）、2 個つないで片方の位置をもう片方が追う、速く回すと遅れる。
- 道具（`tools\`、本体の `.venv` の python で流す）：

| ファイル | すること |
|---|---|
| `servo_play.py` | コマンドで 1 個を動かす：`scan`（誰が返事するか）、`setid`（ID を変える）、`info`、`goto`、`sweep`（往復）、`wheel`（回り続ける） |
| `servo_gui.py` | スライダーの窓：位置・速度・加速度・往復、状態の表示 |
| `servo_mirror.py` | 2 個：手で回した方を、もう片方がまねる |
| `servo_common.py` | 上の 3 つが使う共通部分（単位の説明もここ） |

- 確かめた範囲（2026-11-16）：本物のモーターでは**まだ流していない**。偽のモーター（目標へ決めた速さで近づく、作り物の基板）で、全部のコマンドを流し、次を確かめた：力を入れた瞬間に跳ばない（前に残っていた目標位置 100 を、いまの位置で上書きしてから力を入れる）、終わると力が抜けて位置モードに戻る（モードがもう 0 なら書かない）、モーターが 6 個返事をすると動かさずに止まる、一斉の呼びかけが乱れた（`None`）ときと、位置の上下限が 0〜4095 でないときに止まる、`setid` は返事が 1 個とはっきりしないと止まる、2 個の親子で後ろの方が前の方に追いつく、親が 0/4095 の端をまたぐと子は止まって待つ。

## 0. 安全のための決まり（道具が守ること・人が守ること）

| 決まり | 道具の中で | 理由 |
|---|---|---|
| 力を入れる前に、目標位置を「いまの位置」に合わせる | `servo_common.torque_on_here()` | このプロジェクトのフォロワーは、残っていた目標位置へ全速で跳んで過負荷で止まった（[ルール P-001](../rules/RULES.md)） |
| 動かす前に、速度と加速度に上限を付ける。0 は送らない | `set_caps()` | 位置モードで速度 0 は「上限なし（全速）」の意味（このプロジェクトの `prime_goal.py` の説明による。モーターの資料では確かめていない） |
| 終わったら、力を抜き、**位置モードに戻す**。モードは、0 でないときだけ書く | `safe_close()`、`ensure_position_mode()` | モードの設定（`Operating_Mode`、番地 33）は電源を切っても消えない場所（EEPROM）にあり、本体は力を抜くときにその書き込みの鍵（`Lock`）を外す（`feetech.py` の `disable_torque`）。回り続けるモードのまま腕に組み込むと危ない。EEPROM は書ける回数に限りがあるので、毎回は書かない（STS3215 の回数は未確認） |
| 腕らしいときは動かさない：一斉の呼びかけ（broadcast ping）にきれいな返事が無い、3 個以上が返事をする、位置の上下限が 0〜4095 でない（腕の中でキャリブレーションされた印）のどれか | `refuse_if_arm()` | 腕を相手に回り続けるモードを使うと、関節がぶつかる。本体の `broadcast_ping` は、返事が乱れると「0 個」ではなく `None` を返す（`feetech.py`）ので、それも止める理由にする。上下限が違うときは、`LOOSE` と打てば続けられる |
| 動かす先は 50〜4045（端の 0/4095 をまたがない） | 各ツール | 位置の値が 4095 → 0 に跳ぶ所をまたぐと、逆に一回りしようとする。手で回す親（`servo_mirror.py` の ID 1）は端をまたぎうるので、またいだら子は止まって待つ |
| ホーン（円い板）を何かに押し当てない。止められたまま力を入れ続けない | 人が守る | 止められたモーターは熱くなる。`servo_mirror.py` は負荷が 1 秒続くと止まる |
| 電源は 7.4V の型（C001・C044・C046）なら **5V**。12V をつながない | 人が守る | 秋月の C001 のページの電源電圧は 4〜7.4V |

## 4. 1 個を動かす（コマンド）

```powershell
& $py tools\servo_play.py COM5 info --id 1 --watch
```

手でホーンを回すと、`position` が変わります（力は入っていない）。4096 で一回り、2048 が真ん中です。`Ctrl + C` で止めます。

```powershell
& $py tools\servo_play.py COM5 goto 3000 --id 1
& $py tools\servo_play.py COM5 goto 1000 --id 1 --speed 3000 --accel 100
```

- 1 行目：いまの位置から 3000 へ、1 秒に 800 ステップ（約 70°）で動き、着いたら力が抜けます。かかった秒数が出ます。
- 2 行目：速さと加速度を上げると、どれだけ早く着くかを比べます。
- `--hold` を付けると、Enter を押すまで力を入れたままにします。その間に指でホーンを押して、どれくらいの力で押し返すかを感じます（押し当て続けない）。

### 試すこと（表に書く）

| 速度（steps/s） | 加速度 | 2048 → 3000 にかかった秒 | 見た感じ |
|---|---|---|---|
| 400 | 10 | | |
| 800 | 20 | | |
| 1500 | 50 | | |
| 3000 | 100 | | |

単位：速度は 1 秒あたりのステップ（4096 で一回り）。加速度の 1 は 1 秒あたり 100 ステップずつ速くなる（このプロジェクトの `tools\so101_common.py` の説明と同じ。モーターの資料では確かめていない）。

### 往復（Arduino の Sweep と同じ）

```powershell
& $py tools\servo_play.py COM5 sweep 1500 2500 --id 1 --times 5
```

### 回り続ける（速度モード、`wheel`）

```powershell
& $py tools\servo_play.py COM5 wheel 400 --id 1 --seconds 3
& $py tools\servo_play.py COM5 wheel -400 --id 1 --seconds 3
```

- モードを 1（一定の速さで回る）にして、3 秒回し、止めて、位置モード（0）に戻します。マイナスで逆向きです。
- モードの値（0 = 位置、1 = 速度、2 = PWM、3 = ステップ）は本体の `feetech.py` にあります。
- 終わった後に `scan` で `mode 0` に戻っているかを確かめます。**戻っていないモーターは腕に組み込まない。**

## 5. スライダーの窓（`servo_gui.py`）

```powershell
& $py tools\servo_gui.py COM5 --id 1
```

1. 窓が開きます。最初は力が抜けていて、手で回すと位置のスライダーがついてきます。
2. 「Torque ON (here)」で、いまの位置のまま力が入ります（跳ばない）。
3. 位置のスライダーを動かすと、モーターがついてきます。速度・加速度のスライダーを変えると、次の動きから効きます。
4. 往復：「sweep mark A」「sweep mark B」で 2 か所を決め、「Sweep on/off」。
5. 下の行に、位置・速さ・負荷・電圧・温度が 1 秒に 5 回出ます。
6. 窓を閉じると、力が抜けて位置モードに戻ります。

## 6. 2 個で親子（`servo_mirror.py`）

1. 2 個目の ID を 2 にします。**つなぐのは、ID を変えるモーター 1 個だけ**にします。新品 2 個はどちらも ID 1 のはずで、同じ ID の 2 個は返事が重なって 1 個に見えることがある（または乱れる）ので、道具では確実には見分けられません。道具は、返事が乱れたら止まり、最後に「1 個だけか」を聞くので、`yes` と打つ前に目で確かめます。
   ```powershell
   & $py tools\servo_play.py COM5 setid --new 2
   & $py tools\servo_play.py COM5 scan
   ```
   本体の `setup_motor()` を使い、どの通信速度のモーターでも見つけて、ID と 1 Mbps を書きます（電源を切っても残る）。
2. 2 個をデイジーチェーンでつなぎ、`scan` で ID 1 と 2 が出るかを見ます。
3. 流します。
   ```powershell
   & $py tools\servo_mirror.py COM5 --leader 1 --follower 2
   ```
4. ID 1 のホーンを手で回すと、ID 2 がまねます。表示の `lag`（遅れのステップ）と `loop`（1 秒に何回回ったか）を見ます。

### 試すこと

| 試すこと | オプション | 見ること |
|---|---|---|
| ゆっくり回す / 速く回す | — | 速く回すと `lag` が増える（動画 24:11 と同じ） |
| 1 回に動く幅を広げる | `--max-step 80` | 遅れが減るか。そのかわり、急に動く |
| 速度の上限を下げる | `--speed 800` | 遅れが増えるか |
| 1 秒の回数を下げる | `--hz 10` | カクカクするか |
| ID 2 を指で止める | — | `load` が上がり、`--load-stop`（既定 600）を 1 秒超えると止まる |

これが SO-101 のテレオペの中身です：リーダー（6 個）の位置を読み、フォロワー（6 個）の目標位置に書く、を 1 秒に何十回もくり返します。このプロジェクトの `safe_teleop.py` は、同じことを 6 関節で、1 回の幅の上限と、キャリブレーションの範囲の内側だけで行います。

## 7. 動画にあって、ここでしていないこと

| 動画 | ここでは | 理由 |
|---|---|---|
| P ゲインなどを、メーカーの専用ソフト（Windows）で変えた | しない | 腕に組み込むモーターの値を変えると、本体の動きと合わなくなる。本体はつなぐたびに P=16・I=0・D=32 を書く（`so101_common.py` の `torque_on_in_place()` と同じ値）。試すなら予備のモーターだけで |
| Arduino の UART から動かす | しない | 本体の Python で足りる。Arduino で動かすなら、基板の UART の口とジャンパーの設定を、基板の資料で確かめる |
