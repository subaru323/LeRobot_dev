# 03 撮影台を作り、カメラ 2 台を同時に動かす

- 作成：2026-11-16
- 目的：フォロワーとカメラを**動かない台**に留め、カメラ 2 台（正面・手首）が同時に決めた速さ（30 fps）で撮れることを、記録の前に確かめる。
- 動画の場面：6:37（仮想マシンで、カメラをつなぐと USB の転送が追いつかず止まった）、11:36〜12:13（20 分ほどで撮影台を作った。後半はレゴでカメラの台を作った）。
- 買うもの：[01 買い物リスト](01_買い物リスト.md) の「03 で要るもの」
- 道具：`tools\camera_check.py`（LeRobot のカメラの部品をそのまま使い、全部のカメラを同時に開いて、実際の fps を測る。ロボットには触らない）
- 確かめた範囲：`camera_check.py` は、偽のカメラ（30 fps と 12 fps を返す）で、数え方と OK / LOW の判定と画像の保存が動くことを確かめた（2026-11-16）。本物のカメラでは未確認。

## 1. なぜ台が要るか

学習した方策は、**記録のときのカメラの見え方**を覚えます。評価のときにカメラが 1 cm ずれる、照明が変わる、リーダーや人の手が写る、だけで、知らない入力になります。

| 決まり | 理由 |
|---|---|
| フォロワーとカメラは同じ台に留める | 台ごと動いても、腕とカメラの位置関係は変わらない |
| 記録から評価まで、カメラに触らない | 触ったら、3 の写真と見比べて戻す |
| リーダーと操作する人は、正面のカメラに写らない所に置く | 評価のときはリーダーも人もいない。写っていると、記録と評価で見え方が違う |
| 照明は毎回同じ（窓の光を避け、机のライトを使う） | 昼と夜で見え方が変わると、記録に無い入力になる |
| 机の面は無地 | 立方体を見分けやすい（準備手順書 E-1） |

## 2. 作り方（3 案から選ぶ）

| 案 | 作り方 | よい所 | 気を付ける所 |
|---|---|---|---|
| A 板 + カメラアーム（おすすめ） | 合板（目安 60 × 45 cm）にフォロワーをクランプで留め、板の端にカメラアーム（1/4 インチのネジ付き）を留める | 作るのが早い。板ごと持ち運べる | アームの関節は、締めた後に触らない |
| B アルミフレーム | 2020 のアルミフレームで門の形を作り、上の横棒にカメラを留める | 一番ずれにくい。上から見下ろす角度も作れる | 部品の注文と組み立てに時間がかかる |
| C レゴ（動画の後半） | レゴでカメラの台を組み、机に置く | 手元の物ですぐ作れる | 押すと動く。台の足をテープで机に留める |

### 2-1. 置き方の目安（A の場合）

```
          （奥）
   ┌───────────────────────────┐
   │   [ボウル/箱]               │
   │                             │
   │   ×  ×  ×   ← 立方体の印     │
   │   ×     ×                   │
   │                             │
   │        [フォロワー]          │  ← クランプ 2 個で板に留める
   └───────────────────────────┘
          （手前）  ↑ 正面のカメラ：手前の上から、斜め下に見下ろす
                       リーダーは板の外（カメラに写らない横）に、別のクランプで机に留める
```

- お手本の見え方：SmolVLA の論文のデータ（SO-100、上からのカメラと手首のカメラ、640 × 480）の画像を、[08](08_実機なしで練習_v070.md) の `peek_dataset.py` で書き出して見られる。上からのカメラは、腕の土台・箱・立方体が全部入り、無地の黒い机。手首のカメラは、グリッパーの片側の爪と、つかむ物が大きく写る。
- 正面のカメラは、フォロワーの手前 50〜60 cm、高さ 40〜50 cm から、作業場所の全体（ボウルと 5 か所の印）が入る向きにします（目安。4 の画像で決める）。
- 手首のカメラは、フォロワーの手首に付けます（[準備手順書](../準備手順書.md) C）。

## 3. 手順

1. フォロワーを板（または机）に、クランプ 2 個で留めます。手で押しても台が動かないことを確かめます。
2. 正面のカメラをアーム（またはフレーム、レゴの台）に留めます。
3. カメラ 2 台を、**パソコン本体の別々の USB の口**に差します（同じハブに 2 台つなぐと、帯域が足りなくなりやすい）。
4. カメラの番号を調べます（[データ収集と学習の手順書](../データ収集と学習の手順書.md) 9 と同じ）。
   ```powershell
   lerobot-find-cameras opencv
   ```
5. 2 台を**同時に**、記録と同じ設定で開いて、実際の fps を測ります（下の 4）。
6. 測れたら、台とカメラを写真に撮り、下の表に寸法を書きます（ずれたときに戻すため）。

| 項目 | 値 |
|---|---|
| フォロワーの土台の中心 → 正面のカメラ（水平の距離） | cm |
| 机の面 → 正面のカメラ（高さ） | cm |
| 正面のカメラの番号・手首のカメラの番号 | |
| 写真のファイル名 | |

## 4. 2 台が同時に 30 fps で撮れるか（`camera_check.py`）

```powershell
cd C:\Users\genes\Documents\PROJECTS\lerobot
MAIN_PG\lerobot\.venv\Scripts\python.exe tools\camera_check.py 0 1
```

- `0 1` は 3-4 で調べた番号です。
- 10 秒間、2 台を同時に読み、カメラごとに `… fps -> OK` か `LOW` を出します（頼んだ fps が 30 なら、27 以上で OK）。
- `outputs\camera_check\cam0.png`・`cam1.png` に、3 × 3 の線と真ん中の十字を描いた画像が保存されます。正面のカメラの画像で、次を確かめます。

| 確認 | 確認 |
|---|---|
| ボウル（箱）と 5 か所の印が、全部写っている | [ ] |
| 腕を一番遠い印まで伸ばしても、グリッパーが画面の外に出ない（テレオペで伸ばして撮り直す） | [ ] |
| リーダーと操作する人が写っていない | [ ] |
| 立方体の赤が、白く飛んでいない（照明の映り込み） | [ ] |
| 2 台とも OK | [ ] |

### LOW と出たとき

| 試すこと | やり方 |
|---|---|
| 圧縮した形式（MJPG）で受け取る | `camera_check.py 0 1 --fourcc MJPG`。OK になったら、記録のコマンドのカメラの設定にも `fourcc: MJPG` を足す（例：`front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: MJPG}`。`fourcc` の項目は本体のソース `configuration_opencv.py` にある。記録のコマンドに足して通るかは未確認） |
| USB の口を変える | パソコンの前と後ろなど、別の口に差し直す。ハブを外す |
| 解像度を下げる | `--width 320 --height 240`。記録・学習・評価を全部同じ解像度にそろえる |
| ほかのソフトを閉じる | ビデオ会議のソフトなどがカメラを使っていると開けない |

- 動画の人は、仮想マシンの中では USB の転送が追いつかず、Ubuntu を直接入れて解決しました。このプロジェクトは Windows で直接動かしているので、仮想マシンの問題は起きません。それでも、2 台を同じハブに差すと帯域が足りなくなることはあります。
- カメラの番号は、差し直しや再起動で入れ替わることがあります。記録の日ごとに、4 を流してから始めます。
