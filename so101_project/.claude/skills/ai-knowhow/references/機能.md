### K-0074 MCP の道具は既定で道具検索（tool search）に回され、起動時には道具の名前とサーバーの説明だけが読まれるので、サーバーを増やしても文脈はほとんど減らない。いつも見せたいサーバーだけ alwaysLoad: true にする。道具の出力は既定で 2.5 万トークンが上限。

対象: Claude Code ／ 根拠: 公式 ／ 確認日: 2026-11-17 ／ 見直し期限: 2027-02-17

**要点**
- 公式: 「Only tool names and server instructions load at session start, so adding more MCP servers has minimal impact on your context window.」
- サーバーごとの道具の数の上限は決まっていない。限りは文脈の予算。
- `alwaysLoad: true` で先に読み込む。その分の道具は会話の文脈を使い、起動もそのサーバーの道具を待つ（接続の上限 5 秒まで）。サーバーの作者が道具ごとに先読みを指定でき、設定で `"alwaysLoad": false` にすると止められる。
- 出力が 1 万トークンを超えると警告、既定の上限は 2.5 万トークン（`MAX_MCP_OUTPUT_TOKENS` で上げられる）。サーバーがその道具の上限を上げていなければ、5 万字を超える成功した文字の結果は、その変数に関係なくファイルに保存される。警告の線は変えられない。
**注意**
- 道具検索を使わない場合がある: Opus 4・Sonnet 4 より前のモデル、Azure の Microsoft Foundry、`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を付けたとき、HIPAA の構成のセッションなど。このときは道具を最初から全部読む。
- MCP の道具を全部見せたいからと alwaysLoad を広く付けると、昔の「MCP を入れすぎると文脈が減る」に戻る。

出どころ: https://code.claude.com/docs/en/mcp

### K-0080 Claude デスクトップの予約タスク（ローカル）は、アプリが開いていて PC が起きているときだけ走り、前の回やほかの予約タスクが動いていればその回は飛ばされ、逃した回はアプリを開いた・PC が起きたときに直近の1回だけ取り戻して走る（昼に走ることもある）。

対象: Claude Code デスクトップ 1.1.5368 以降 ／ 根拠: 公式 ／ 確認日: 2026-11-17 ／ 見直し期限: 2027-02-17

**要点**
- 公式: 「Tasks only run while the desktop app is running and your computer is awake.」スリープ中の回は飛ばされる。設定の Keep computer awake でアイドルのスリープを防げる（蓋を閉じると寝る）。
- 飛ばされる理由（履歴の skipped にマウスを載せると出る）: PC が寝ていた、前の回がまだ動いていた、ほかの予約タスクが既に動いていた。
- 逃した回: 過去7日分を見て、いちばん最近の1回だけ取り戻して走らせる。公式は、時刻が大事なら指示文に「〇時を過ぎていたら〜」のような守りを書くよう勧めている。
- 各タスクは、予定の時刻から数分遅れて始まる（同じタスクはいつも同じずれ）。
- アプリを開いたときに始まる取り戻しの回は、モデルが「Default · Set by admin」なら、アカウントの既定のモデルで走ることがある。
- 設定で Worktree を選ぶと、回ごとに別の worktree で走る（フォルダの中の作業の列を回どうしで受け渡すなら選ばない）。
- 権限: タスクごとに権限のモードを決める。作った後に Run now して、出た確認に「always allow」を選んでおくと、次から止まりにくい（詳細ページで取り消せる）。フォルダの中の編集なら、モードを Accept edits にする。毎回確認を求める MCP の道具（requiresUserInteraction）を使う回は毎回止まる。
- 指示文は `~/.claude/scheduled-tasks/<名前>/SKILL.md`。予定・フォルダ・有効かどうかはそこに無い。
- PC を切っていても走らせたいなら、クラウドの予約タスク（ルーティン）。こちらは手元のファイルを見られない（新しい clone）。
**注意**
- 夜に複数のプロジェクトの予約タスクを並べると、互いに飛ばし合う。時刻をずらし、1回を短くする。
- Claude_knowhow の 2026-11-17 の夜、1回目（0:22 ごろ）の跡が無かった。理由は履歴の skipped で確かめられる（このとき別のプロジェクトの 23:30 の予約タスクが動いていた可能性がある。確かめていない）。

出どころ: https://code.claude.com/docs/en/desktop-scheduled-tasks
