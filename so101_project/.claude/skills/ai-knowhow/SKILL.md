# Claude のノウハウ（種のパッケージ 2026-11-26.1347）

Claude_knowhow フォルダのノウハウ集から作った種。71 件。中身は公式ドキュメントか、検証の記録で確かめたもの。

このパッケージのほかの種: `enforcing-project-rules`（プロジェクトの決まりを、文章でなく仕組み（打つ前のフック・始めの点検・決まりと判定の表・担当つきの監査）で守らせる）、`framing-business-strategy`（提案・企画・機能・広げ先を、事業戦略の視点（3〜5年後・業界の構造・真似されない理由）で組み立て、1枚にする・見直す）、`reviewing-security`（コードの変更を SQL インジェクション・XSS などの観点で見直し、攻撃の筋道つきで指摘して直す）、`running-night-work`（人がいない間（夜など）に AI に作業を進めさせる仕組み（作業の列・予約タスク・朝の報告）を組む）、`writing-project-docs`（CLAUDE.md・STATUS.md・AI への依頼書・スキルを、ノウハウに沿って書く・見直す）。その場面ならそちらを使う。

- 各項目の id（K-xxxx）を、利用者への説明や記録に添える。

## 既存のプロジェクトを見直す手順

1. `python "${CLAUDE_SKILL_DIR}/scripts/audit.py" <プロジェクトのフォルダ>` を動かす。昔の定石の型と、長すぎる CLAUDE.md を拾う。
2. 拾ったものは機械の一次検査。1件ずつ中身を見て、本当に当てはまるかを決める（例: 引用や説明の中の IMPORTANT は問題ない）。
3. 直す案を、項目の id と一緒に利用者に出す。直すのは利用者が承認してから（AI 向けの文書はどの会話にも効くため）。
4. 道具が拾えないもの（CLAUDE.md にコードから分かることを書いている、など）は、ドキュメント.md の項目を見ながら読んで判断する。
