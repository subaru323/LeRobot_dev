## 採用済みのルール

- **R-001**: 実験・調査・分析の結論や、方向を決める提案を利用者に出す前に、新しい会話の AI に結論を渡して問題を最大8件挙げさせ、直してから出す。点検役が挙げた数字や事実は、受け入れる前に自分で確かめる。呼び出しは `python docs/core/tools/r001_check.py`。**このパソコンでは動かない**（組織の設定で `Codex -p` が使えない）ので、読むだけのサブエージェントで代え、代えたことを台帳に書く。挙がった件は `docs/records/R001_LOG.md` に記録する。中身は `docs/core/rules/RULES.md`（正本）。
- **P-001**: フォロワーに力を入れる前に、目標位置を「いまの位置」に合わせる。本家のコマンドの前には毎回 `tools\prime_goal.py`。中身は `docs/rules/RULES.md`。

## このプロジェクトの決まりごと

- LeRobot の本体は `MAIN_PG/lerobot`（コミット `53feaef`、`.venv` もそこ）。本体のソースは書き換えない。
- 実機（モーター、基板）を動かすコマンドで、利用者の Enter が要るものは、Terminal パネルのタブで流し、利用者に押してもらう。
  - タブで流すコマンドは、作業フォルダを指定しても、そのフォルダで始まらないことがあった（2026-10-28）。実行ファイルは絶対パスで書く（`C:\Users\genes\Documents\PROJECTS\lerobot\MAIN_PG\lerobot\.venv\Scripts\python.exe`、`...\Scripts\lerobot-calibrate.exe` など）。
  - タブは 6 つまで。自分で開いたタブは、使い終わったら閉じる。利用者が打ち込んだタブは、利用者に閉じてもらう。
- `tools\` のスクリプトは LeRobot を読み込むので、上の `.venv` の python で流す。文書の検査（`tools\check_links.py`、`docs\core\tools\doc_lint.py`）は、どの python でもよい。
- 文書を書き換えたら、`python tools\check_links.py` と `python docs\core\tools\doc_lint.py <ファイル>` を流す（[検査の一覧](docs/rules/検査の一覧.md)）。
