# やめること（昔の定石）

どれも昔は勧められていたが、いまのモデル・版では効かないか、逆効果か、エラーになる。

- ~~守られない指示には IMPORTANT や大文字を付けると守られる。~~（K-0055、Opus 4.5 より前のモデル）
  → 代わりに: K-0042 IMPORTANT や大文字で強調しない。現行のモデルは普通の1行に従い、強調を重ねると決まりをやりすぎて当てはめる。
- ~~「think hard」「think harder」と書くと、思考の量が増える。~~（K-0056、旧 Claude Code（版の境目は原文に無い））
  → 代わりに: K-0047 「think hard」と書いても思考の量は増えない（effort で決まる）。「怠けるな」「終わるまで続けろ」はやりすぎを招く。ただし「よく考え抜いて」のような一般的な指示は、手書きの手順より良い推論を生むことが多い。
- ~~「怠けるな」「終わるまで続けろ」と書くと、最後までやり切る。~~（K-0057、Claude 4.5 以前）
  → 代わりに: K-0047 「think hard」と書いても思考の量は増えない（effort で決まる）。「怠けるな」「終わるまで続けろ」はやりすぎを招く。ただし「よく考え抜いて」のような一般的な指示は、手書きの手順より良い推論を生むことが多い。
- ~~最後のアシスタントの発言を「{」などで埋めておく（prefill）と、JSON を強制できる・前置きを消せる。~~（K-0058、Claude 4.5 以前）
  → 代わりに: K-0005 最後のアシスタントの発言を先に埋めておく（prefill）方法は、Claude 4.6 以降でエラーになる。形式は structured outputs かツールの enum で、前置きの削除はシステムプロンプトの指示で行う。
- ~~思考の機能を使えるモデルでも「一歩ずつ考え、<thinking> に推論を書いてから <answer> に答えよ」と書くと良くなる。~~（K-0059、Fable 5.2/5.1/5・Opus 5.5/5・Sonnet 5.5 で思考を使っているとき）
  → 代わりに: K-0049 <thinking> タグなどで推論を本文に書かせる手作りの思考の連鎖は使わない。Fable・Opus 5/5.5・Sonnet 5.5 では断られる原因になりうる。推論を見たいなら、要約された思考ブロックを読む。
- ~~extended thinking は thinking: {type: enabled, budget_tokens: N} で量を決める。~~（K-0060、Claude 4.5 以前（4.6 で非推奨、4.7 以降はエラー））
  → 代わりに: K-0004 Fable 5.2 と Opus 5.5 は思考（thinking）が常にオンで、思考の量は effort で決める。budget_tokens での手動の設定は 4.7 以降でエラーになる。
- ~~CLAUDE.md にアーキテクチャやファイルの構成を書いておく。~~（K-0061、旧 Claude Code）
  → 代わりに: K-0050 CLAUDE.md には、AI がリポジトリを読んでも分からないことだけを書く（確かめるコマンド、誤解しやすい所、リポジトリの外の決定、2回直したこと）。1ファイル 200 行未満。
- ~~サブエージェントに任せると答えが良くなる。文脈を守るためにサブエージェントを使う。~~（K-0062、旧 Claude Code）
  → 代わりに: K-0027 複数のエージェントに分けるのは、並列にできる作業、文脈を汚したくない作業、専門に分けたい作業のときだけにする。トークンは1体の3〜10倍かかり、文脈を共有する作業には向かない。
- ~~スラッシュコマンドは .claude/commands/ に作る。~~（K-0063、旧 Claude Code（今も動く））
  → 代わりに: K-0013 スキルは説明文だけが常に読まれ、本文は呼ばれたときか関係があると判断されたときだけ読まれる。説明文は 1,536 字で切られる。.claude/commands/ はスキルにまとめられた。
- ~~「#」キーで CLAUDE.md に覚えさせたいことを書き足す。~~（K-0064、旧 Claude Code）
  → 代わりに: K-0012 自動メモリ（auto memory）は既定で有効。MEMORY.md は先頭 200 行か 25KB までが起動時に読まれ、ほかのメモは必要なときだけ読まれる。
- ~~文脈の窓（200K）がいちばんの制約なので、/clear を多用して細かく管理する。~~（K-0065、200K の文脈のモデル）
  → 代わりに: K-0017 多くのモデルで 1M トークンの文脈が既定になり、圧縮も自動になったので、ほとんどの場合、文脈を最大の制約として細かく管理しなくてよい。
- ~~文脈が残り少ないと早く切り上げてしまうので、文脈をリセットして引き継ぎの文書を書かせる。~~（K-0066、Sonnet 4.5）
  → 代わりに: K-0029 仕組み（ハーネス）の部品は「モデルが1人ではできないこと」への手当てで、モデルが良くなると要らなくなる。新しいモデルが出たら、外せる部品と指示を見直す。
