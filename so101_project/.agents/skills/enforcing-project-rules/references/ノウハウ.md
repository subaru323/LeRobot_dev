### K-0069 決まりを守らせるフックは exit 2 で止める（または onFailure: "block"）。exit 1 などほかの終了コードは止めずに進み、exit 2 は JSON で allow を出しても止める。フックの if 欄は確実な守りではない（Bash の入力を分けられないときは if に関係なく動く）。

対象: Claude Code ／ 根拠: 公式 ／ 確認日: 2026-11-17 ／ 見直し期限: 2027-02-17

**要点**
- exit 0 は成功、exit 2 は止める、ほかは「止めない誤り」で処理は進む（有効な JSON を出さない exit 1 も同じ。失敗で止まる種類のフックは除く）。`"onFailure": "block"` は command と http のフックで、v2.1.295 以降。公式: 「If your hook is meant to enforce a policy, use `exit 2`.」
- matcher は英数字・_・-・空白・カンマ・| だけなら名前の一覧として完全一致、ほかの文字があると正規表現（端を固定しない）。FileChanged と StopFailure は英数字・_・| だけが完全一致。matcher を受けない場面に書いた matcher は黙って無視される。
- `if` 欄は権限のルールの書き方で道具の呼び出しを絞る。Bash の入力を小さいコマンドに分けられないときは型に関係なく動くので、公式は Bash の節で「best-effort」と呼び、確かな許可・拒否は権限の仕組みでせよとしている。道具以外の場面で `if` を付けたフックは動かない。
- ユーザー・プロジェクト・local のフックは足し合わされ、同じハンドラーを複数の設定ファイルに書いたときは1回だけ動く。プラグインやスキルの同じハンドラーは別に動く。
**注意**
- 調査の AI は hooks のリファレンスの前半（約 8 万字）だけを原文で読んだ。場面ごとの節と出力の JSON の細部は読めていない。

出どころ: https://code.claude.com/docs/en/hooks

### K-0050 CLAUDE.md には、AI がリポジトリを読んでも分からないことだけを書く（確かめるコマンド、誤解しやすい所、リポジトリの外の決定、2回直したこと）。1ファイル 200 行未満。

対象: Claude Code ／ 根拠: 自分で確認 ／ 確認日: 2026-11-17 ／ 見直し期限: 2027-05-17

**要点**
- 判定: 「コードを読めば分かるか」「実際に見に行くか」の両方が Yes なら書かない。
- 書くもの: (1) テスト・型・lint のコマンドと、1つのテストの動かし方 (2) 真似してはいけない古い書き方、使っていないように見えて使っている場所 (3) デプロイの手順など、リポジトリに無い決定 (4) 2回直したこと。
- 見出しは Commands / Conventions / Gotchas のように分ける。指示は確かめられるほど具体的に（「2スペースで字下げ」）。
- 長いほど守られにくくなり、推奨の長さを超えると起動時に警告が出る。
**注意**
「短く具体的に」は公式の勧め。このフォルダでは比べる実験はしていない（CL-002）が、長くした結果の失敗は、調べたプロジェクトで観察した（下の節）。
**自分の記録（調べたプロジェクト（記録は Claude_knowhow の docs/knowledge、2026-11-17 の考察）、2026-11-17 に調べた）**
- CLAUDE.md が事故のたびに伸びた（464 行→902 行。★615 個、太字の印 約 570 組、1500 字を超える行 6 本）。一度 840 行に縮めても戻った。
- 言葉づかいの決まりは 808 行目にあり、その後も「日本語で」「分からない」の訂正が続いた（2か月で約 45 件。「日本語で」だけの短い返信が 15〜21 件）。
- そのプロジェクト自身の直し案が、再発の原因の第一に「読む量が多すぎて、作業の瞬間に関係する失敗が出てこない」を挙げた。取り下げた決まりが本文に残って読み違えも起きた。
- 1つのプロジェクトの観察で、短くした形と比べた実験ではない。
- 裏付けたのは「常に読む文書を長くすると、作業の瞬間に要る決まりが埋もれる」という向き。「200 行未満」の数は確かめていない。
