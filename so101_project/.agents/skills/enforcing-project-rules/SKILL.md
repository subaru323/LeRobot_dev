# 決まりを仕組みで守らせる（種のパッケージ 2026-11-17.1234）

> この種は試作（実務でまだ確かめていない）。

このパッケージのほかの種: `ai-knowhow`（Codex と Codex の使い方全般（モデル・effort・機能・指示の書き方）と、既存のプロジェクトの昔の定石の見直し）、`reviewing-security`（コードの変更を SQL インジェクション・XSS などの観点で見直し、攻撃の筋道つきで指摘して直す）、`running-night-work`（人がいない間（夜など）に AI に作業を進めさせる仕組み（作業の列・予約タスク・朝の報告）を組む）、`writing-project-docs`（CLAUDE.md・STATUS.md・AI への依頼書・スキルを、ノウハウに沿って書く・見直す）。その場面ならそちらを使う。

実際の開発（Claude_knowhow が調べたプロジェクト）では、CLAUDE.md と記憶の両方に書いた禁止が4回破られ、打つ前のフックを入れたら止まった（K-0021）。定着した仕組みはどれも、具体的な失敗から作り、自動で起動するものに結んであった。

## 決まりを足す前に決めること

決まりごとに、下の上から順に、守らせ方を1つ選ぶ。文章（CLAUDE.md）は最後の手。

| 守らせ方 | 向く決まり | 根拠 |
|---|---|---|
| 権限の deny・設定 | 触ってはいけないファイル、使ってはいけないコマンド | K-0021 |
| 打つ前のフック（PreToolUse） | 打つ形で見分けられる禁止（例: 標準入力から読むコマンド）。止めるときは exit 2 か onFailure: "block" | K-0021、K-0069 |
| 新しいチャットの始めの点検（SessionStart フック） | 引き継げる状態か、入口が読めるか、記憶や入っていないスキルに決まりを置いていないか | K-0085 |
| 決まりと判定の表に登録する点検 | 結果の文書や生成物を見て分かること（数字の食い違い、壊れたリンク） | K-0082 |
| AGENTS.md の1行 | 判断が要り、機械で見られない方針。理由を1文添え、先頭近くに置く | K-0050 |

## 手順

1. **破られた決まりを集める。** 利用者に同じ訂正を2回された、記録に「再発」がある、が合図。
2. **守らせ方を上の表から選ぶ。** フックや deny で止められるなら、文章を足さずにそちらにする。フックを足したら、新しいチャットで効いているか確かめる（K-0021）。
3. **決まり ⇄ 判定 ⇄ 回す時機を1つの表に登録する。** 機械で見られない決まりは、理由を書いて「手で見る」の行にする。登録した点検が実際に回っているかも、表から見張る（K-0082）。
4. **状態は文書に写さない。** 点検の結果・件数・進行は、出すコマンドを文書に書く（K-0081）。
5. **監査には担当と期限を付ける。** 赤を見つけたら、直す担当と期限を付けるか、直さない理由を書いて「受け入れ済み」に降ろす。朝の報告は、新しい赤・慢性の赤・受け入れ済みを分ける（K-0083）。
6. **並行のセッションがあるなら**、共有の文書への同時の追記をやめ、セッションごとの追記だけのログと、返事の無い依頼の検出・期限での取り下げを作る（K-0084）。
7. フック・設定・CLAUDE.md を変えるのは、案を見せて利用者が承認してから（どの会話にも効くため）。

## 限界

- 根拠の多くは1つのプロジェクトの観察。
- この種は試作。使ったら、効いたかを、利用者の承認を取ってマスターの記録（マスター（Claude_knowhow）の results/USAGE_LOG.md。マスターの場所は SEED.json の master）に1行書くよう提案する。
