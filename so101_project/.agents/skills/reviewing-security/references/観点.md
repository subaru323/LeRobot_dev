# 見る観点

コードが触るものの行を全部見る。どれも「入力の出どころ → 危ない使い所」の流れで見る。分類は OWASP Top 10 と CWE Top 25 を参考にした（https://top10.owasp.org/ 、https://cwe.mitre.org/top25/ ）。

| 触るもの | 観点（CWE） | 見る所 | 安全な形 |
|---|---|---|---|
| データベース | SQL インジェクション（CWE-89）、NoSQL の注入（CWE-943） | 文字列の連結・f 文字列・テンプレートでクエリを作っていないか | パラメータ化したクエリ、ORM の束縛。並べ替えの列名などは許す値の一覧で |
| HTML・画面 | XSS（CWE-79） | 利用者の値を innerHTML・dangerouslySetInnerHTML・v-html・テンプレートの無エスケープで出していないか | フレームワークの自動エスケープ、textContent。HTML を許すなら消毒のライブラリ |
| シェル・外部コマンド | OS コマンドの注入（CWE-78） | shell=True、文字列で組んだコマンド、exec・system | 引数を配列で渡す。値は許す値の一覧で |
| ファイル | パスの横断（CWE-22）、危ないアップロード（CWE-434） | 利用者の値でパスを作っていないか、`..` や絶対パスを通さないか | 決まったフォルダの下に正規化して収まるか確かめる。ファイル名は作り直す |
| 認証・認可 | 認証の欠落（CWE-306）、認可の抜け（CWE-862、CWE-863）、IDOR（CWE-639） | 他人の id を渡したら他人のデータが見える・変えられないか。管理の操作に権限の確認があるか | 毎回サーバ側で持ち主・権限を確かめる |
| 秘密情報 | 直書き（CWE-798）、ログやエラーへの漏れ（CWE-532、CWE-209） | API キー・パスワード・トークンがコードやログやエラー文に出ていないか | 環境変数・秘密の置き場。エラーは利用者に詳細を見せない |
| 外部への通信 | SSRF（CWE-918） | 利用者の URL をサーバが取りに行っていないか | 行き先の許す一覧、内部のアドレスを弾く |
| コードの実行 | コードの注入（CWE-94） | eval・exec・Function()・テンプレートの式に外からの値を入れていないか | 値として扱う。テンプレートは利用者に書かせない |
| 読み込み | 安全でないデシリアライズ（CWE-502） | pickle・yaml.load・Java の直列化に外からの値を入れていないか | JSON、yaml.safe_load |
| フォーム・状態の変更 | CSRF（CWE-352） | 状態を変える要求にトークンや SameSite があるか | フレームワークの CSRF 対策 |
| 依存 | 古い・脆弱な部品 | 足したライブラリの版 | `npm audit`・`pip-audit` など |

この表に無い言語・場面（C のメモリ、暗号、正規表現の計算量など）は、そのコードに当てはまる観点を自分で足す。
