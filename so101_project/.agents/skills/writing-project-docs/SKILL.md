# AI が読むプロジェクトの文書を書く（種のパッケージ 2026-11-17.1234）

> この種は試作（実務でまだ確かめていない）。

このパッケージのほかの種: `ai-knowhow`（Codex と Codex の使い方全般（モデル・effort・機能・指示の書き方）と、既存のプロジェクトの昔の定石の見直し）、`enforcing-project-rules`（プロジェクトの決まりを、文章でなく仕組み（打つ前のフック・始めの点検・決まりと判定の表・担当つきの監査）で守らせる）、`reviewing-security`（コードの変更を SQL インジェクション・XSS などの観点で見直し、攻撃の筋道つきで指摘して直す）、`running-night-work`（人がいない間（夜など）に AI に作業を進めさせる仕組み（作業の列・予約タスク・朝の報告）を組む）。その場面ならそちらを使う。

## どの文書に何を置くか

| 置きたいもの | 置き場 | 根拠 |
|---|---|---|
| 毎回の会話で要る事実（確かめるコマンド、誤解しやすい所、リポジトリの外の決定） | AGENTS.md | K-0050、K-0023 |
| いまどこまで進んだか、次の一手、決まったこと | STATUS.md など現在地のメモ（CLAUDE.md から入口として指す） | K-0052 |
| たまに要る手順・参照 | スキル（説明文だけが常に読まれる） | K-0023、K-0013 |
| ある作業を任せるときの中身 | 依頼書（依頼の文か、依頼の MD ファイル） | K-0053 |
| コードを読めば分かること（構成、ファイルの一覧） | どこにも書かない | K-0050 |
| 状態（件数・合否・進行・一覧） | 文書に写さず、出すコマンドを書く | K-0081 |
| 事故の経緯、利用者の言葉の引用、取り下げた決まり | 記録のフォルダ（原文のまま移す） | K-0086 |
| 守らせたい決まり | 記憶ではなくプロジェクトの文書。破られるならフックや点検（種 enforcing-project-rules） | K-0085、K-0021 |

## AGENTS.md を書く・直す

1. リポジトリを読み、**読んでも分からないこと**だけを集める。判定は「コードを読めば分かるか」「AI が実際に見に行くか」。両方 Yes なら書かない（K-0050）。
2. 書くコマンドは、実際に動かして通ることを確かめてから書く。
3. [references/雛形.md](references/雛形.md) の AGENTS.md の形で、200 行未満に（K-0050）。強調（IMPORTANT・大文字）は使わず、決まりには理由を1文添える（K-0042、K-0036）。
4. 報告の言語・言葉づかいの決まり（「日本語で、作った用語を使わない」など）は先頭の数行に置く。実際の開発で、902 行の AGENTS.md の 808 行目にあった言葉づかいの決まりは守られず、訂正が続いた（K-0050）。
5. 事故のたびに決まりを足さない。足す前に、フックや点検で止められないかを見る（種 enforcing-project-rules）。決まりを取り下げたら、本文から記録へ移す（K-0086）。
6. 既存のプロジェクトの AGENTS.md を作る・変えるのは、案を見せて利用者が承認してから（どの会話にも効くため）。

## STATUS.md（現在地のメモ）

- 文脈を知らない読み手が、それだけで次の一手に入れるように書く（K-0052）。節は 目的・決まったこと・現在地・次の一手・利用者の判断待ち（Claude_knowhow で使っている並び。公式の決まりではない）。
- 構造のある状態（テストの結果、機能ごとの合否）は JSON に分け、履歴は git に任せる（K-0052）。
- 件数や合否は写さず、出すコマンドを書く。手で写した状態は腐る（K-0081）。
- 古くなった次の一手（止まったセッションの分など）は、期限で記録へ移す。
- 決まったことや次の一手が変わったら、その場で直す。CLAUDE.md の頭に「最初に STATUS.md を読む」と書く。

## 依頼書（サブエージェント・別のセッションに任せる）

- 相手は会話の履歴を見られない。会話で決めたことは書く（K-0053）。
- 最初に、対象のファイル・何が起きているか・「終わった」の決め方。次に、合否の分かる確かめ方。最後に、返してほしい形と証拠（実行したコマンドと出力）（K-0053）。
- 情報は最小で濃く。細かいロジックを書き込みすぎず、共通の認識に頼った曖昧さも避ける（K-0054）。雛形は [references/雛形.md](references/雛形.md)。

## スキル（SKILL.md）

- 説明文は三人称で「何をするか」と「いつ使うか」。主な使い道を先に（K-0051、K-0013）。
- 本文は AI が既に知っていることを書かず、既定のやり方を1つ。500 行以下、参照は1階層（K-0051、K-0013）。
- 同じスキルの中の道具は `${CLAUDE_SKILL_DIR}/scripts/…` で指す（K-0051）。副作用のある手順（リリース・送信など）には `disable-model-invocation: true` を付け、AI が勝手に呼ばないようにする（K-0013）。
- 先に評価のケースを3つ作ってから書く（K-0032）。

この種は試作。使ったら、効いたかを、利用者の承認を取ってマスターの記録（マスター（Claude_knowhow）の results/USAGE_LOG.md。マスターの場所は SEED.json の master）に1行書くよう提案する。
