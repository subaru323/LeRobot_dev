# 物理で流す（MuJoCo）・Isaac Sim へ渡す

`sim/` の画面と検算は運動学だけで動きを組む（ピースは爪に貼り付いて動く）。ここでは同じ関節の列を、物理エンジン MuJoCo の公式の SO-101 の模型（`../models/src/so101_new_calib_camera.xml`）に指令として渡し、ピースを自由に動く剛体にして、本当につかめるか・運べるか・置いた所がずれないかを見る（[計画書_完成形まで](../../docs/plan/計画書_完成形まで.md) の S-15）。

## 入れたもの

- `.venv/`：この作業だけの Python（3.13）と `mujoco` 4.0.1（PyPI から。2026-11-17 に利用者の許しを得て入れた）。LeRobot 本体の `.venv` とは別。消しても `python -m venv .venv` と `pip install mujoco` で作り直せる。
- MuJoCo の模型と `sim/` の関節の角度は同じ（2026-11-17。関節角 3 組で、爪の座標系の位置が 0.002mm 以内。点検役がでたらめな 8 組で 0.004mm 以内・回転 0.001° を確かめた）。

## 流し方（`sim/` で）

```bash
node tools/export-physics.js --set 2
```

```bash
physics/.venv/Scripts/python.exe physics/run_physics.py out/physics/set2_gap15_stand1
```

`--view` で MuJoCo の画面を開き、実時間で見られる（マウスで視点を回せる）。`--snap 3,4.5` でその時刻の絵を PNG に書く。比べる用に `--grip`（爪の力の上限 Nm）・`--solref`・`--friction`・`--squeeze`・`--torsion`・`--noslip 0`・`--hull`（爪を公式の模型の凸包のまま当てる）。既定と違う値で流すと、結果は `result_<条件>.json` に書き、`scene_mjcf.xml` は書き換えない。

```bash
physics/.venv/Scripts/python.exe physics/check_physics.py
```

全部の種を書き出して流し、表にする（1 種 1〜2 分）。最後に負の検算：持っている間も爪を閉じない（`--squeeze -20`）と、全部のピースが NG になるか。摩擦 0.02 では、強く挟むので L・J が運べてしまい、負の検算にならなかった。

## 出るもの（`out/physics/<名前>/`）

| ファイル | 中身 |
|---|---|
| `scene.json` | `export-physics.js` が書く場面と動き |
| `result.json` | ピースごとの置いた所のずれ・向き・傾き・持ち上げた高さ・爪の中で滑った量（握り込みが効いた後から、全部のマスで）・つかむ前に押された量（爪を閉じ始める前まで）、関節と爪の先の追い遅れ（いちばん大きい時刻つき）、爪の細かい形のほかの腕がピースに触れた時刻（触れたら NG）。**置いた所のずれは「物理の結果 − 運動学の sim の最後の置き方」**で、盤の目標との差ではない（sim 自身の差は `check-scene.js` で 0.2mm 未満） |
| `scene_mjcf.xml` と `assets/` | 場面を 1 つの MJCF にしたもの（腕・机・台・ピース・爪の細かい当たりの形）。STL を横に写してあるので、このフォルダだけで開ける |

## Isaac Sim / Isaac Lab で開く

このパソコンには NVIDIA の GPU が無く、Isaac Sim は動かない。だから **Isaac Sim で開けるかは確かめていない**。クラウドの GPU（NVIDIA Brev）で試す段取りは [計画書_IsaacSim_Brev](../../docs/plan/計画書_IsaacSim_Brev.md)。渡せる形は 2 つ：

1. `out/physics/<名前>/scene_mjcf.xml`（2.5MB ほど）：Isaac Sim の MJCF の取り込みか、Isaac Lab の MJCF の変換で、場面ごと USD にする。爪の細かい当たりの形が 1900 個ほど（頂点を XML に直に書いた形）ある。`noslip`・`solref`・`impratio` などの MuJoCo の接触の設定は PhysX に移らないので、開けても同じ動きにはならない。物理の値は Isaac 側で決め直す。
2. 腕だけなら `../models/src/so101_new_calib_camera.urdf`（URDF の取り込み）。関節の列は `node tools/export-motion.js` の CSV（URDF の角度・度）をそのまま関節の目標にできる。

## 【仮】と、ずれうる所

- 摩擦 0.4、ねじりの摩擦 5mm、ピースの密度 1240 kg/m³、すき間をつなぐ棒 6mm 角、爪の力の上限 0.7 Nm、接触の硬さ 0.004 秒、置いた所の合格 3mm・5°。どれも実物で測って入れ替える。
- **挟む力**：爪は位置制御なので、指令をピースの幅より閉じる（8°）と、ずれが 0.19° を超えた所で力の上限に張り付く。挟む力は角度ではなく力の上限で決まる。公式の模型の上限 3.35 Nm（爪の先で 42N ほど）は、LeRobot が実機の爪の力を最大の半分（負荷が続くと 4 分の 1）に絞る（`MAIN_PG/lerobot/src/lerobot/robots/so_follower/so_follower.py`）のより強いので、0.7 Nm【仮】にした（STS3215 の止まったときの力は版によって 1.9〜2.9 Nm ほど。品の資料で確かめていない）。
- MuJoCo は 1 つの STL を凸包で当てる。爪の 2 つ（固定の爪を含む部品と、動く爪）は、三角形を 2mm の辺まで割ってから 4mm の升に振り分け、升ごとに凸包にした（かたまりは 7mm 以下。面に内向きの厚み 1.5mm）。それでも升の中で面が曲がる所・穴の縁では、凸包が面の外へ出る。それ以外の腕は凸包のままで、くぼみが埋まって実物より太る。上のカメラの台は見た目だけ（当たらない）。
- 関節の位置制御の強さ・関節の摩擦と遊びは、公式の模型の値（実機のサーボの設定とは 1 対 1 でない、と模型に書いてある）。
- 接触の硬さ `solref` 0.004 秒【仮】と `noslip` の反復 10 を使う。0.004 秒は種 2 で「ずれが小さくなる値」として選んだもので、PLA の硬さから出した値ではない。爪の力が公式の模型のまま（3.35 Nm）・硬さ 0.02 秒・切った形の厚み 0.6mm だったときは、爪がピースに 1.2〜1.35mm めり込んで、7 種で置いた所が 3〜9mm ずれた（noslip なしでは、O が 1 秒ほどで回って落ちた）。めり込みが厚みの半ばを越えて押し戻しの向きが裏返った恐れもある（点検 C23 の 2）ので、厚みを 1.5mm、力を 0.7 Nm にした。
- 種 2（3×4 L J O）での感度（2026-11-17）：硬さ 0.02 秒・力 0.7 Nm → OK・2.18mm／0.02 秒・3.35 Nm → O が落ちる／0.004 秒・3.35 Nm → 0.23mm／0.004 秒・0.3 Nm → 0.25mm／摩擦 0.3 → 0.26mm／**摩擦 0.2 → O を持ち上げられない**（0.7 Nm。1.5 Nm なら運べる）／爪を凸包のまま → つかむ前にピースを 3.6mm ほど押し、O を持ち上げられない。O は 2 マスを挟み、重心が挟む線から 1 マスの半分ずれるので、いちばん弱い。**結果は接触の硬さ・挟む力・摩擦に強くよる**ので、実物で 1 つ目のつかみを試して決める。
