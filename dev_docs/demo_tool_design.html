LeRobot × SO-ARM101 · Tool design v0

かんたん LeRobot 設計図

ロボットに詳しくない人でも、画面の指示に従うだけで「つなぐ → 教える → 学習させる → 動かす」までを終えられるツールの大まかな設計です。中身は既存の LeRobot コマンドをそのまま使い、ツールは手順の案内と設定の肩代わりに徹します。

利用者から見た 5 ステップ

1. つなぐUSB を挿すとポートとカメラを自動で見つけるA 班
2. 合わせる画面の絵のとおりに腕を動かしてキャリブレーションA 班
3. 教えるリーダーアームで動作を見せて録画するB 班
4. 学習させるボタン 1 つで学習。進み具合を表示C 班
5. 動かす学習したモデルでデモを実行し、成功率を記録D 班

画面の外枠、設定の保存、コマンド実行の共通部品は E 班が担当します。

本体の骨組み

classDiagram

    +task_name

    +steps
    +current
    +next()
    +resume()
  }
  class Step {
    <>
    +status
    +check() bool
    +run()
    +cancel()
  }
  class ConnectStep
  class CalibrateStep
  class RecordStep {
    +episodes_done
  }
  class TrainStep {
    +target
    +progress
  }
  class DemoStep {
    +success_count
  }
  class CommandRunner {
    +run(args) LogStream
    +stop()
  }
  Project "1" *-- "1" HardwareProfile
  Project "1" o-- "1" TaskTemplate
  StepFlow "1" *-- "5" Step
  StepFlow --> Project
  Step <|-- ConnectStep
  Step <|-- CalibrateStep
  Step <|-- RecordStep
  Step <|-- TrainStep
  Step <|-- DemoStep
  Step ..> CommandRunner : uses

各ステップは同じ型（check で前提を確かめ、run で実行）を持ちます。班ごとに 1 つずつ実装すれば、他の班のステップを待たずに並行開発できます。

  S0 --> S1 : ポートとカメラを検出

  S2 --> S3 : 録画開始
  S3 --> S4 : 規定数のお手本がそろう
  S4 --> S3 : 追加で録画
  S4 --> S5 : 学習開始
  S5 --> S6 : 学習完了
  S5 --> S4 : 失敗・中止
  S6 --> S7 : デモ開始
  S7 --> S6 : 終了
  S6 --> S3 : うまく動かない → お手本を追加
  S1 --> S0 : 抜けた

状態は Project に保存し、ツールを閉じても続きから再開できるようにします。前の状態に戻る矢印が、利用者にとっての「やり直し」ボタンになります。

シーケンス図

「学習させる」を押したとき

sequenceDiagram
  actor U as 利用者
  participant W as ウィザード画面
  participant T as TrainStep
  participant R as CommandRunner
  participant L as lerobot-train
  participant G as GPU（HF Jobs）
  participant H as HF Hub
  U->>W: 「学習させる」を押す
  W->>T: check()
  T-->>W: OK（データあり・GPU 設定あり）
  W->>T: run()
  T->>R: run(train の引数一式)
  R->>L: プロセス起動
  L->>G: ジョブ投入
  loop 学習中
    G-->>R: ログ（ステップ・損失）
    R-->>W: 進捗バーを更新
  end
  G->>H: 学習済みモデルを保存
  R-->>T: 終了コード 0
  T-->>W: 状態を「学習済み」に
  W-->>U: 「デモに進めます」

利用者は引数を一切見ません。データセット名、ステップ数、ポリシー種別はタスクの雛形と Project から組み立てます。

まだ決めていないこと

画面をどう作るか

候補は Gradio、Streamlit、FastAPI と自作フロントエンドなど。手軽さと見た目の自由度のどちらを取るかで選びます。

学習をどこで回すか

手元の PC は CPU のみです。HF Jobs（有料）、学校の GPU、Colab など、費用と手間で選びます。

ポリシーを固定するか

初心者向けには ACT 固定が安全です。SmolVLA などを選べるようにするのは後回しでよいと考えます。

Hub のアカウント

利用者ごとにログインさせるか、チーム共有のアカウントにまとめるか。ログイン手順の有無で初心者の負担が大きく変わります。

大まかな叩き台です。図中のクラス名・状態名は仮のものです。
