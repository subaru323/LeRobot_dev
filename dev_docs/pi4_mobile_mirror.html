easy_lerobot · add-pi4-mobile-mirror

ラズパイ4とスマホだけでミラーする

ノートPCを使わずに、ラズパイ4の上で easy_lerobot の画面を動かし、スマホのブラウザから mirrorMODE を操作できるようにする変更です。細かい仕様（Claude 向け）は easy_lerobot/openspec/changes/add-pi4-mobile-mirror/ にあります。

できるようになること

スマホで開く

ラズパイと同じ Wi-Fi のスマホで http://<ラズパイのIP>:8501 を開き、パスワードを入れると、いつものモード選択の画面が出ます。

ミラーとトルク

mirrorMODE で、ミラーの開始・停止と、フォロワーのトルクの入り切りができます。中で動くのは今と同じ dev_scripts/mirror_leader.py です。

準備状況のログ

モード選択の画面に、基板2枚・設定ファイル・カメラがそろったかを2秒ごとに表示し、そろったら「準備完了」を出します。スマホで見られるのは画面のサーバーが起動した後からです。

電源を入れるだけ

systemd で、ラズパイの起動と同時に画面のサーバーが立ち上がります。落ちても自動で戻ります。

配線

USBWi-Fi電源

定点カメラは、アームとつかむ物体の距離を見るためのものです。今回の変更では、カメラはつなぎ方と名前（wrist・front）だけを決め、コードには入れていません。録画をラズパイで動かす段階で使います。

コードで変えたところ

ファイル今までこれから
core/hardware.pyポートが COM19・COM20 に固定ラズパイではリーダーとフォロワーを自動で見分ける（モーターに書かれた原点の値を校正ファイルと照らし合わせる。読むだけで動かさない）。差し込み口はどこでもよい。見分けられないうちはミラーを始められない。Windows は今までどおり
core/procs.pyWindows の仕組み（CTRL_BREAK・taskkill）だけ。Linux では読み込んだ時点で落ちるLinux 用の起動・停止を追加（Ctrl+C と同じ止め方 → 止まらなければ子まで止める）。Windows の処理は変えていない
core/key_input.py・views/record.py画面のないラズパイでは pynput が読み込めず、画面全体が落ちる使うときに読み込む。使えない機械では「この回を終える」「撮り直す」だけを押せなくする
app.py・.streamlit/パソコンの中からしか開けない同じ Wi-Fi から開ける。パスワードを入れるまで先に進めない
deploy/（新規）—systemd の設定と、ラズパイ4での手順書

新しいライブラリは足していません。ラズパイ4には lerobot 本体や torch を入れず、streamlit・pyserial・feetech-servo-sdk だけで動かします。

確かめたこと・まだのこと

確かめた

  • ラズパイ4で画面のサーバーが起動し、同じ Wi-Fi の PC のブラウザから :8501 で開けた（ここではパスワードの画面まで。以下の操作は SSH で中継して確かめた）
  • パスワード：違うと入れない／設定ファイルが無いと案内だけ／ページの URL を直接打っても入口で止まる／正しいと入れる
  • mirrorMODE にラズパイのポート名（/dev/ttyACM0・1）が「未接続」で出る
  • テストモードでミラーの開始・停止：止めると後片付けが走り、取り残し0件
  • 録画画面がラズパイで落ちず、「この回を終える」「撮り直す」だけが押せない
  • プロセス管理の自動テスト10項目：Windows・ラズパイとも全部通過（Windows の動きは変わっていない）

まだ（アームをつないでから）

  • 実物のアームでのミラー・トルク切り替え
  • リーダーとフォロワーの /dev/serial/by-id/ の名前
  • カメラ2台とサーボ基板2枚を同じハブにつないで安定するか
  • systemd の自動起動（sudo が要る）

決めてほしいこと

  1. フォロワーのカメラはどこに付けるか（手首か、グリッパーか）
  2. スマホとラズパイのつなぎ方（いったん保留）。学校の open Wi-Fi は端末同士の通信ができないので使えない。それまでの確認は検証用の Wi-Fi で行う
  3. 録画は後回し。ラズパイは中継役で、将来 GPU のあるパソコンが来たら録画のデータはそこへ送る（ラズパイには貯めない）。送り方はそのときに決める
