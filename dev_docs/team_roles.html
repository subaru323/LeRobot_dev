SO-101 五班体制

5人が常に同時に手を動かせるよう、工程ごとに班を分けます。前の工程の成果物を待たずに済むよう、各班は「代用品」を使って先に進め、本物が届いたら差し替えます。

全体の流れ

A実機を動かす→ robot.id / calibration
Bデータを集める→ HF_USER/<task>
C方策を学習する→ HF_USER/act_<task>
D評価して戻す→ 成功率・失敗パターン

D の結果は B（撮り直し・追加収録）と C（設定変更）に戻り、ループを何周も回します。

E 基盤・統合：上の 4 班すべてを支えます。環境、git 運用、名前の取り決め、進捗の管理を担当します。

各班の担当

A

ハードウェア班

SO-101 のフォロワーとリーダーを組み立て、正しく動く状態に保ちます。

やること

  • 組み立てと配線、電源の確認
  • サーボ ID の設定
  • キャリブレーションと関節可動域の測定
  • カメラの固定位置を決める
  • 故障対応と予備部品の管理

使うもの

  • lerobot-find-port
  • lerobot-setup-motors
  • lerobot-calibrate
  • lerobot-find-joint-limits
  • dev_scripts/random_servo.py

引き渡すもの

  • 固定の robot.id と teleop.id
  • キャリブレーションファイル
  • COM ポート対応表と配線メモ

代用品で進める工夫：組み立て途中でも、サーボ単体の通信試験は random_servo.py でできます。

B

データ収集班

タスクを決め、テレオペで質の良いデモを集めて Hub に上げます。

やること

  • タスク定義（物体、配置、成功条件）
  • カメラ設定と照明の固定
  • テレオペの練習と収録
  • エピソードの品質確認と不良の除外

使うもの

  • lerobot-find-cameras
  • lerobot-teleoperate
  • lerobot-record / lerobot-replay
  • lerobot-dataset-viz
  • lerobot-edit-dataset

引き渡すもの

  • Hub 上のデータセット ${HF_USER}/<task>
  • 収録手順書（誰が撮っても同じ条件になるもの）

代用品で進める工夫：実機ができる前に、Hub の公開 SO-101 データセットで形式と可視化を把握し、タスク定義と収録手順を先に固めます。

C

学習班

方策を選んで学習させ、使えるチェックポイントを出します。

やること

  • まず ACT で基準線を作る
  • ステップ数・バッチサイズの設計
  • GPU の確保（手元 PC は CPU のみ）
  • 余力があれば SmolVLA を試す

使うもの

  • lerobot-train
  • --job.target（HF Jobs）または外部 GPU
  • AGENT_GUIDE.md §6・§7

引き渡すもの

  • Hub 上の方策 ${HF_USER}/act_<task>
  • 学習条件の記録（データ版・ステップ・損失）

代用品で進める工夫：自前データが届くまでは公開データセットや pusht で学習手順と GPU 環境を確立します。pusht での CPU スモーク学習は既に通っています。

D

評価・推論班

学習済み方策を実機とシミュで動かし、何が効いて何が駄目かを数字で返します。

やること

  • 評価手順を決める（試行回数、初期配置、成功判定）
  • 実機で方策を動かして成功率を測る
  • 失敗の動画を分類して B・C に返す
  • 推論の速度と安全停止の確認

使うもの

  • lerobot-eval（シミュ）
  • lerobot-record --policy.path=…（実機）
  • lerobot-rollout / lerobot-policy-server

引き渡すもの

  • 評価記録表（方策・データ版ごとの成功率）
  • 失敗パターンと改善提案

代用品で進める工夫：既存のスモーク用チェックポイント（pusht）で評価の流れと記録表の形式を先に作っておきます。

E

基盤・統合班

全員が同じ環境で動けるようにし、班の間のつなぎ目を管理します。進行管理も兼ねます。

やること

  • 5 台分の環境構築手順を整える
  • git のブランチ運用とレビュー
  • 名前の取り決め（ID・repo_id）を管理する
  • 週 1 回の通し試験（A→D を一周）
  • システムマップ等の資料を更新する

使うもの

  • uv sync --locked
  • lerobot-info
  • .vscode/launch.json
  • dev_docs/

引き渡すもの

  • セットアップ手順書と既知の落とし穴一覧
  • 進捗表と週次の統合結果

既知の落とし穴：FFmpeg は 8.x に固定（9.x で torchcodec が動かない）。開発者モードが無効だと checkpoints/last の作成で WinError 1314。push 時の GitHub アカウントの食い違い。

同時に進めるための決まりごと

名前を先に決める

robot.id、データセット名、方策名を初日に E が決めて共有します。中身が後から入れ替わっても、名前が同じなら他の班は作業を止めずに済みます。

班ごとにブランチと置き場を分ける

ブランチは hw/… data/… train/… eval/… infra/…。各班のスクリプトは dev_scripts/<班>/ に置き、src/ はなるべく触りません。

受け渡しは Hub で行う

データセットと方策は Hugging Face Hub を通じて渡します。USB メモリや個人 PC 上のファイルに依存しません。

実機の時間を割り振る

SO-101 は 1 セットなので、A・B・D の実機使用時間を時間割にします。空いている班はシミュや代用品で進めます。

実機の取り合いを避ける時間割（例）

時期実機を使う班他の班がやること
序盤A（組立・キャリブ）B タスク定義 / C 公開データで学習手順 / D 評価手順 / E 環境統一
中盤B（収録）A 予備部品・保守 / C 収録分から順次学習 / D 前回の方策をシミュ評価 / E 通し試験
終盤D（実機評価）と B（追加収録）を交互にC 再学習 / A 故障対応 / E 資料まとめ
叩き台です。人の割り当て、時期、タスク内容はチームで決めてください。
