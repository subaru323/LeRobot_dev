# Design

## Context

- ラズパイは検証用の Wi-Fi（またはテザリング）の中にいて、インターネット側から見える住所を持たない。外から始まる通信はラズパイに届かないが、ラズパイから外へは出られる。
- ミラーの制御（リーダーの角度を読んでフォロワーに送る、1 秒に 30 回）はラズパイの中で USB だけで完結している。ネットを通るのはボタン・状態・画面の表示だけ。
- 学校の Wi-Fi は外向きの 22 番を通さないことがある（開発用の PC で確認）。

## Decisions

### D1. ラズパイから VPS へ ssh の逆向きトンネルを張る（実装済み）

```
ssh -N -p 443 -R 127.0.0.1:8501:localhost:8501 -R 127.0.0.1:2222:localhost:22 relay@<VPS>
```

- VPS の sshd が `127.0.0.1:8501` と `127.0.0.1:2222` で待ち受け、来た通信をトンネルの中のチャンネルとしてラズパイへ渡す。待ち受けは VPS の内側だけで、外から 8501・2222 は直接開けない。
- 理由: ラズパイ側は外へつなぎに行くだけなので、どの Wi-Fi でもよく、ラズパイの IP アドレスが変わっても来場者の URL は変わらない。今の画面をそのまま使える。
- ラズパイ用の鍵は VPS 側で `restrict,port-forwarding,permitlisten="127.0.0.1:8501",permitlisten="127.0.0.1:2222"` に制限し、ログインできない専用ユーザー（シェルは nologin）に置く。鍵が漏れても VPS の中には入れない。
- 切れたら systemd が 10 秒後に張り直す（`Restart=always`）。生きているかは両側で 15 秒ごとに確かめる（ラズパイ側 `ServerAliveInterval`、VPS 側 `ClientAliveInterval`）。

### D2. VPS の 443 番 1 つで HTTPS と ssh を受ける（実装済み）

- nginx の stream で 443 番を受け、`ssl_preread` で TLS なら HTTPS のサーバー（VPS の内側の 8443 番）へ、それ以外（ssh）なら 22 番へ渡す。
- 理由: 22 番を止める Wi-Fi でもトンネルを張れ、開発用の PC からも入れる。
- HTTPS の証明書は Let's Encrypt（自動更新）。HTTP（80 番）は HTTPS へ転送する。

### D3. 命令の通り道を MQTT にする（提案・未実装）

測定（ラズパイも PC も同じ検証用 Wi-Fi のインターネット回線を使った状態）:

| 経路 | 画面の JS（約 0.4MB） |
|---|---|
| 同じ Wi-Fi でラズパイに直接 | 0.4 秒（約 1.2MB/秒） |
| VPS のトンネル経由 | 60 秒で打ち切り（約 6KB/秒） |

Streamlit は画面を開くたびに数 MB のファイルを送るため、遅い回線から毎回送ることになる。そこで次の形にする。

- VPS に MQTT のブローカー（mosquitto）を置き、nginx の 443 番を通して `wss://<VPS>/mqtt` で受ける。
- 来場者の画面は VPS から配る静的なページにする（ボタンは「ミラー開始」「停止」と状態の表示）。ラズパイの回線を通らない。
- ラズパイには小さな常駐プログラムを置き、`easy-lerobot/cmd` を受けて今の `mirror_leader.py` を起動・停止し、`easy-lerobot/status` に状態（準備完了・ミラー中・停止）を出す。プロセス管理は `core/procs.py` をそのまま使う。
- 権限はユーザーごとに分ける: 来場者のページは cmd への送信と status の購読だけ、ラズパイは cmd の購読と status への送信だけ。
- Streamlit の画面は係の人の保守用として残す（トンネル経由でも同じ Wi-Fi からでも開ける）。
- 代替案: トンネルのまま Streamlit を使う → 上の測定のとおり遅い。

### D4. ラズパイの Wi-Fi は人が切り替える

- 優先順位による自動の切り替えは入れない。使っていて問題を感じたときに、人が選べなくなるため。
- 切り替えで Wi-Fi に入れないとラズパイに届かなくなるので、切り替えの手順には「一定時間 VPS に届かなければ元の Wi-Fi に戻す」安全策を付ける（実装は別途）。

### D5. 手首カメラの映像は HDMI のディスプレイに出す

- 映像はネットで送らない。ラズパイのミニ HDMI にディスプレイをつなぎ、デスクトップなしで全画面表示する（電源ボタンのため文字の画面で起動している設定は変えない）。
- 表示の方法（mpv の DRM 出力など）は実装時に決める。

## add-raspberry-pi-deployment の記述の改め

同提案の design.md「インターネット側への転送（ポート開放やトンネル）は設定しない」は、展示の構成では D1・D2 のとおり VPS へのトンネルを使う。ラズパイ側でポートは開けない（外への接続だけ）。展示を終えたらトンネルのサービスを止め、VPS も止める。

## Risks / Trade-offs

- [URL を知っていれば会場の外からも開ける] → 画面のパスワードは残す。MQTT では来場者用のユーザーの権限を cmd と status に限る。合言葉を会場で変える方法は実装時に決める。
- [トンネルは 1 本の TCP の上に全部が乗る] → 電波が悪いと全員の画面が止まる。MQTT にすればやり取りは数十バイトになり、影響は小さくなる。
- [ラズパイがインターネットに出られないと、来場者は操作できない] → 同じ Wi-Fi から Streamlit の画面を開く今の形は、保守用として残る。
- [VPS のお試し期間は外向きの転送量が 10Mbps に制限される] → ボタンと状態だけなら足りる見込み（未測定）。
